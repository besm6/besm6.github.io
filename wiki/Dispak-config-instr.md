## Аннотация

Данное руководство предназначено для лиц, отвечающих за эксплуатацию
операционной системы Диспак (ОС Диспак). В нем рассматриваются вопросы
генерации системы и ее сопровождения в процессе эксплуатации.

Приведены также функции администратора ОС, даются указания по использованию
обслуживающих программ.

Системному программисту необходимо ознакомиться с документами "Руководство
оператора" (ИЫ.00110-01 34 01) и "Руководство программиста"
(ИЫ.00110-01 33 01).

## 1. Общие сведения об операционной системе Диспак

### 1.1. Назначение и функции ОС

Операционная система (ОС) Диспак предназначена для автоматизирования
процесса прохождения задач пользователя и высокоэффективного использования
вычислительного комплекса.

Основные функции ОС:

1. обеспечение возможно быстрого прохождения задачи через вычислительную
   систему и обработки пакета в целом;
2. обеспечение эффективной эксплуатации центральной части и устройств
   ввода/вывода с учетом конструктивных особенностей;
3. обеспечение оператора ЭВМ достаточным набором средств и возможностей для
   простой и оперативной работы за терминалом;
4. обеспечение высокой надежности работы вычислительной системы в целом и
   отдельных ее компонентов, а также простоту в эксплуатации;
5. обеспечение пользователя средствами отладки программ и управления
   решением задач;
6. обеспечение многопрограммной работы в режиме пакетной обработки, работу
   пользователей с удаленных терминалов в режиме дистанционной пакетной
   обработки и разделения времени, возможности совмещения указанных работ и
   режимов;
7. обеспечение работы в режиме реального времени.

### 1.2. Используемые технические средства

**1.2.1.** Для обеспечения пропуска задач на операционной системе Диспак
необходим следующий минимальный комплект оборудования:

* ЦП Эльбрус 1-КБ;
* секция ОП (объем 64 Мбайт);
* пультовая ЭВМ, снабженная пультовым программным обеспечением (ППО);
* устройство управления накопителями на МЛ ЕС-5525;
* накопитель на магнитной ленте ЕС-5025;
* устройство управления накопителями на сменных магнитных дисках ЕС-5580;
* 2 накопителя на сменных магнитных дисках ЕС-5080;
* АЦПУ ЕС-7040;
* алфавитно-цифровой дисплейный комплекс ЕС-7970 (ЕС-7920);
* 2 алфавитно-цифровых дисплея ТС-7063 (ЕС-7927).

Внешние устройства подключаются к каналам в соответствии с комплектацией ВК
"Эльбрус 1-КБ". Стандартная комплектация ВК "Эльбрус 1-КБ" и распределение
устройств по каналам приведено в документе "СТП. Руководство оператора"
ИЫ.04301-01 34 01.

О работе с пультовой машиной см. в документе "ППО. Руководство оператора"
ИЫ.00112-01 34 01.

## 2. Структура операционной системы Диспак

ОС Диспак представляет из себя совокупность большого числа служебных
программ, связанных между собой в единый комплекс. По функциональным и
организационным принципам в структуре этого комплекса можно выделить четыре
основные части:

* супервизор,
* управляющую программу (УП),
* монитор,
* блок обработки экстракодов.

Каждая из этих частей в свою очередь есть совокупность согласованных между
собой служебных программ. Часть служебных программ размещается постоянно в
оперативной памяти, образуя резидент ОС, остальные хранятся во внешней
памяти (МД) и вызываются в оперативную память по мере надобности.

* Супервизор обслуживает систему аппаратных прерываний и каналы связи с
  устройствами ввода-вывода.
* УП направляет и контролирует работу всех остальных служебных программ ОС.
* Монитор управляет прохождением задач пользователя в ОС.
* Блок обработки экстракодов интерпретирует макрокоманды, встречающиеся при
  выполнении программы.

## 3. Настройка операционной системы

### 3.1. Генерация операционной системы

Генерация операционной системы подразумевает перепись резидентных блоков ОС
с системного диска в оперативную память, настройку ОС на конфигурацию
данной конкретной машины, начальное заполнение системных шкал и таблиц.

Для генерации операционной системы необходим системный диск 2053. На нем
расположены программы ОС, буфер ввода-вывода, каталоги ввода (545-547
зоны), каталог вывода (550 зона), библиотека стандартных программ (630-667
зоны), фамилии и шифры пользователей (540-542 зоны), варианты генерации ОС
(750 зона), стандартные паспорта (543-544 зоны), ключи диалоговых систем
(675 зона), буфер статистики (0-67 зоны). Эта информация переписывается на
диск с транспортной ленты N1 при первоначальной постановке ОС. Без МД 2053
невозможен как вызов ОС, так и ее работа. На этот диск должна быть
разрешена запись.

Для моделирования барабанной памяти и для размещения рабочих сегментов
может быть использован диск-расширитель. Задание этого диска указывается в
параметрах генерации в разделах `НРДИС` и `МДРЗО`. Диск должен быть только
размечен, на него должна быть разрешена запись. В качестве
диска-расширителя можно использовать также часть диска 2053.

Для работы с системами программирования необходим МД 2048. Этот диск должен
быть размечен, на него переписывается информация с транспортной ленты N2,
содержащей коды программ систем программирования.

Генерация ОС Диспак начинается с загрузки в ОП стартового модуля, который
хранится на гибком магнитном диске пультовой ЭВМ.

Стартовый модуль записывается в оперативную память по директиве пультовой
программы, с системного МД 2053 читает программу генерации ОС ("ГЕНС").

Модуль "ГЕНС" обеспечивает размещение резидентных частей ОС в оперативной
памяти.

Вызов ОС завершается сообщением о ресурсах системы на операторский терминал
и переходом на ждущий тест. Полезная работа ОС может начаться только после
выполнения директив `СМЕ`, `ДАТ`, `ВРЕ` (см. "Операционная система Диспак.
Руководство оператора"). По директиве `ВРЕ` аварийно завершаются задачи,
решавшиеся до сброса ОС, начинается выдача на устройства вывода, включаются
в решение задачи, введенные до сброса ОС, разрешаются все остальные
директивы.

### 3.2. Постановка ОСПО на ВК "Эльбрус 1-КБ"

Для постановки ОСПО (ОС и систем программирования) необходимо:

1) включить вычислительный комплекс в соответствии с инструкцией по
эксплуатации ВК Э1-КБ (ПЭ1.700.018 ИЭ);

2) подготовить к работе пультовую машину (ПМ) и вызвать программу имитации
инженерного пульта (см. "ППО. Руководство оператора". ИЫ.00112-01 34 01);

3) разметить полностью два диска с номерами 2053 и 2048 с помощью
автономной программы разметки (см. п. 13.1);

4) переписать готовые программы ОС с транспортной ленты МЛ1 на диск 2053,
воспользовавшись для этого автономной программой переписи. Магнитная лента
должна быть установлена на МГ 32 (на такой номер магнитофона настроена
пультовая программа ПП13).

Для переписи необходимо выполнить следующую последовательность действий в
рамках ППО:

* `У0` — установка нуля;
* `ПП13` — чтение с МЛ в ОП;
* директива `П` — пуск, или нажатие соответствующей клавиши на ПМ;
* убедиться, что РК = 0 3F 07 000 (стоп 0);
* установить параметры чтения с МЛ:
  * слово 5 — N канала (стандартно = 3);
  * слово 6 — N устройства (стандартно = 2);
  * слово 7 — N файла (стандартно = 3);
  * слово 8 — 0 — читаемый код исполняется в режиме совместимости с БЭСМ-6
    (стандартно = 0);
* директива `П` — пуск, или нажатие соответствующей клавиши на ПМ;
* убедиться, что чтение закончено и РК = 0 3F 07 000.

На МЛ 1 находятся 4 файла с номерами 1, 2, 3 и 4. Четные файлы являются
копиями предыдущих нечетных.

* 1, 2 файлы — программа переписи с МЛ в ОП;
* 3, 4 файлы — готовые программы ОС Диспак.

Затем необходимо выполнить последовательность действий для переписи
информации из ОП на МД.

Для ПМ типа "ДВК":

* `У0`
* `ВЫЗОС`

Ответ системы: `ЕСТЬ`

Для ПМ типа ЕС-1840: `ЗАГ SERWIS`

Ответ системы: начальный адрес и длина программы в словах.

Задать параметры переписи:

* ячейка 2 := 1
* ячейка 3 := N пакета в шестнадцатиричном виде
* ячейка B := N устройства МД в шестнадцатиричном виде
* ячейка C := N канала МД в шестнадцатиричном виде
* `У0`
* `АР`
* убедиться, что РК = 0 3F 07 000 (стоп 0)
* директива `П` — пуск, или нажатие соответствующей клавиши на ПМ; после
  окончания переписи программа выходит на "стоп 0" (на РК код 0 3F 07 000).

По умолчанию задан МД 2053 (шестнадцатиричный код 805), канал 0,
устройство 0.

5) занести на "логический" тумблерный регистр необходимую информацию (см.
п. 3.6);

6) вызвать операционную систему. Для этого необходимо выполнить
последовательность действий в рамках ППО.

Для ПМ типа "ДВК":

* `У0`
* `ВЫЗОС Р` — вызов ОС с росписью каталогов.
  Ответ системы: `ЕСТЬ`

Задать параметры программы:

* ячейка 2 := 5
* ячейка 3 := N пакета в шестнадцатиричном виде
* ячейка A := информация для тумблерного регистра
* ячейка B := N устройства МД в шестнадцатиричном виде
* ячейка C := N канала МД в шестнадцатиричном виде
* `У0`
* `АР`
* убедиться, что РК = 0 3F 07 000 (стоп 0)
* директива `П` — пуск, или нажатие соответствующей клавиши на ПМ.

Для ПМ типа ЕС-1840: `ОС Р У<К> М<L> В<N>`, где Р — признак росписи
каталогов, К — номер устройства с МД 2053, L — номер машины, N — номер
варианта.

Ответ системы: начальный адрес и длина программы в словах.

По умолчанию задан МД 2053 (шестнадцатиричный код 805), канал 0,
устройство 0, номер машины = 1, вариант 1.

После нормального завершения вызова ОС на операторский терминал выдаются
сообщения следующего вида:

```
    <ДАТА> <ВРЕМЯ>
 РЕС: <ЗНАЧЕНИЕ ОБОБЩЕННОГО РЕСУРСА СИСТЕМЫ>
```

7) после получения указанных сообщений с терминала оператора необходимо
задать следующие директивы:

| Директива                | Ответ ОС |
|--------------------------|----------|
| `СМЕ <N СМЕНЫ>`          | `ЕСТЬ` |
| `ДАТ <ЧИСЛО> <МЕСЯЦ>`    | `ДАТА: <ЧИСЛО>.<МЕСЯЦ>.<ГОД>` |
| `НЕТ АРХ`                | `ЕСТЬ` |
| `ВРЕ <ВРЕМЯ>`            | `ДАТА: <ЧИСЛО>.<МЕСЯЦ>.<ГОД>  ВРЕМЯ: <ВРЕМЯ>` |

где `<ВРЕМЯ>` = ЧЧММСС; ЧЧ — часы; ММ — минуты; СС — секунды.

После получения последнего сообщения можно начинать работу с ОС.

8) в случае отсутствия любого из указанных ответов системы необходимо
повторить вызов ОС с пункта 5);

9) на работающей операционной системе директивами оператора `ЕСМ МЛ НУ`
(где МЛ = 2, 3 — номера МЛ; НУ — логический номер магнитофона) присвоить
лентам номера;

10) переписать с МЛ 2 (системы программирования режима совместимости)
программой "UNICOP" из файла 1 с 0 зоны в 0 зону МД 2048 2000 зон;

11) переписать с МЛ 3 (система программирования) программой "UNICOP" из
файла 1 с 0 зоны в 2000 зону МД 2048 2000 зон;

12) после окончания переписи на операторском терминале следует набрать
директивы:

| Директива  | Ответ ОС |
|------------|----------|
| `ДАЙ АРХ`  | `ЕСТЬ` |
| `ВРЕ`      | `ДАТА: <ЧИСЛО>.<МЕСЯЦ>.<ГОД>  ВРЕМЯ: <ВРЕМЯ>` |

где `<ВРЕМЯ>` = ЧЧММСС; ЧЧ — часы; ММ — минуты; СС — секунды.

Убедиться в формировании задачи архива: на операторском терминале появится
сообщение `Ф<NСКВ> 41991981062N`, где N — номер ЭВМ.

После формирования задачи архива система работает в стандартном режиме.

### 3.3. Параметры генерации ОС

Для того, чтобы операционная система могла работать на конкретной машине,
необходимо задать системе конфигурацию данной ЭВМ: указать номера системных
дисков, операторские терминалы и т. д. Эти данные представляют собой
параметры генерации и используются программой "ГЕНС" при вызове
операционной системы.

Параметры генерации хранятся в 750-й зоне диска загрузки в виде констант и
в виде текстов, при трансляции которых получаются эти константы.
Переработку текстового описания в константы для "ГЕНС"а осуществляет
программа "ВЫДИНС". Тексты служат входной информацией для программы
"ВЫДИНС"; константы являются выходной информацией программы "ВЫДИНС" и
входной информацией для программы "ГЕНС".

Для работы с программой "ВЫДИНС", задания параметров генерации и записи их
в зону МД загрузки используется директива `ГЕНС` в диалоговой системе
"СЕРП".

Параметры задаются в виде описания необходимых разделов и информации к ним.
Можно создать несколько вариантов параметров для разных ЭВМ комплекса или
описывающих различные конфигурации данной ЭВМ. Каждому текстовому варианту
присваивается имя до 5 символов длиной. По этому имени можно вызвать текст
для просмотра или изменения некоторых разделов, а также для переработки
текста в константы программы "ГЕНС".

Константы получаются в результате трансляции текстового варианта с
возможным внесением исправлений в него. Таким образом, взяв один текст за
базовый, можно получить несколько вариантов констант, внося в текст
различные изменения.

Каждый набор констант для "ГЕНС"а занимает последовательные 40(8) слов и
имеет порядковый номер от 1 до 17(8). Нумерация вариантов раздельная для
разных ЭВМ комплекса. Общее количество вариантов не должно превышать 20(8).

Восьмеричный номер варианта параметров генерации указывается либо в виде
опции директивы вызова ОС, либо указывается в 25-28 разрядах логического
тумблерного регистра.

### 3.4. Задание параметров генерации

Если на данном диске 2053 еще не создавали параметров для генерации, то
первой операцией должна быть подготовка зоны, предназначенной для
параметров. При подготовке зоны на приглашение `ИМЯ-` следует ответить
`НОВ`. По директиве `НОВ` зона обнуляется, в ней проставляется некоторый
признак работы с программой "СЕРП".

После того, как диск был хоть однажды таким образом подготовлен, можно
вызывать директиву `ГЕНС` для задания разделов, описывающих конфигурацию
ЭВМ. Форма описания разделов приведена ниже.

При создании нового варианта удобно пользоваться "подсказками". В этом
случае основные разделы "ВЫДИНС"а будут выдаваться на экран в качестве
приглашения. В ответ следует набирать только информацию к ним.

После работы с "подсказками" можно дополнить перечень разделов для
"ВЫДИНС"а, задавая название недостающего раздела в ответ на приглашение
`РАЗДЕЛ-`.

Следует отличать запись текста варианта от записи констант для "ГЕНС"а:

* запись текста осуществляется по директиве `ЗАП` в ответ на приглашение
  `РАЗДЕЛ-`, при этом константы для "ГЕНС"а записаны не будут;
* запись констант осуществляется после трансляции текста при задании не
  равного нулю номера варианта в ответ на приглашение `НОМЕР-`. Записи

### 3.5. Описание разделов для генерации ОС

Параметры, описывающие конфигурацию ЭВМ, делятся на основные и
неосновные.

К основным относятся те параметры, без которых генерация системы на
серийной машине невозможна. Это — диск загрузки, диск статистики, диск
ввода, диск вывода (как правило информационные поля для загрузки,
статистики, ввода и вывода располагают на одном пакете в целях экономии),
максимальные ресурсы пользователю, номер ЭВМ, год. Отсутствие информации,
задающей основной параметр, считается ошибкой и программа "ВЫДИНС" выдает
соответствующее сообщение.

К неосновным относятся параметры, описывающие устройства и части
программного оборудования, реализация которых может быть отличной от
реализации их на серийной машине, а также те параметры, которые описывают
устройства, отсутствующие на серийной машине.

При работе многомашинного комплекса диски загрузки, статистики,
ввода/вывода, рабочий МД являются общими, поэтому разделы `МЛЗАГ`,
`МЛСТА`, `МЛВВО` и `МЛВЫВ` на всех ЭВМ комплекса должны быть заданы
одинаково. Разделы же `НРДИС` и `МДРЗО` должны указывать на
непересекающиеся поля для разных ЭВМ комплекса.

Текстовая информация состоит из отдельных разделов и информации к ним. В
названии раздела задаются только первые 5 символов. Порядок следования
разделов безразличен. Если номер зоны равен 0, то в разделах, описывающих
системные диски, параметр ZZZZ можно не задавать.

**Основные разделы**

#### 3.5.1. `МЛЗАГ УУУУ-ZZZZ`

где УУУУ — десятичный номер пакета;
ZZZZ — смещение по МД загрузки.

Раздел предназначен для задания информации о диске загрузки, или диске
готовых программ.

Параметр УУУУ принимает значения от 2048 до 4095.

Пример: `МЛЗАГ 2053-560`

#### 3.5.2. `МЛСТА УУУУ-ZZZZ`

где УУУУ — десятичный номер пакета;
ZZZZ — начальная зона статистики.

Раздел предназначен для задания информации о диске статистики. Для всех ЭВМ
комплекса в данном разделе ZZZZ = 0.

Параметр УУУУ принимает значения от 2048 до 4095.

Пример: `МЛСТА 2053`

#### 3.5.3. `ОЗУ ХК`

где Х = 128.

В этом разделе задается информация об оперативной памяти ЭВМ.

Пример: `ОЗУ 128К` — память 128 листа.

#### 3.5.4. `РЕСУР ЛЛ,ТТТ`

где ЛЛ — восьмеричное число листов (1 =< ЛЛ =< 67);
ТТТ — восьмеричное число трактов (ТТТ =< 777).

Раздел служит для задания максимальных ресурсов оперативной и барабанной
памяти, предоставляемых пользователю.

Пример: `РЕСУР 40,740`

#### 3.5.5. `НОММА N`

где N — номер машины, 1 =< N =< 7.

Раздел предназначен для задания номера ЭВМ.

Пример: `НОММА 1`

#### 3.5.6. `ТЕРМ СП,ВУ:1,2,....К-Н`

Раздел служит для описания подключения терминалов к машине.

СП — способ подключения:
СП = АС — подключение через аппаратуру сопряжения.

Если параметр СП отсутствует, то подключение стандартное, то есть напрямую.

ВУ — вид устройства:
VT — АЦД.

К, Н — восьмеричные номера устройств.

Подключенные напрямую АЦД могут иметь номера от 1 до 60(8); при
подключении через аппаратуру сопряжения номера устройств для АЦД могут
изменяться от 1 до 177(8).

Пример: `ТЕРМ VT:1-7;АС,VT 10-20,60-77,115-127`

#### 3.5.7. `ШКОПТ Ф1,Ф2,...,ФК-ФН,....`

где К, Н — восьмеричные номера логических каналов.

В разделе задается информация о наличии операторских терминалов, то есть
перечисляются те физические каналы, которые отводятся для подсоединения
операторских терминалов.

Пример: `ШКОПТ Ф1,Ф20`

#### 3.5.8. `ТКАНА Ф1:0,1,К-Н,Ф2:0,1,К-Н`

где Ф1, Ф2, ... — физические каналы для подсоединения терминалов,
К, Н — восьмеричный номер логического канала (0 =< Н, К =< 7).

В этом разделе указывается, на какие физические каналы будут выдаваться
сообщения операционной системы, распределенные по восьми (0-7) логическим
каналам. После двоеточия перечисляются логические каналы через запятую, а
если они идут подряд, то через минус.

Пример: `ТКАНА Ф1:0-3,Ф2:4-7`

#### 3.5.9. `НРДИС УУУУ,ААА,ЧЧ`

где УУУУ — десятичный номер рабочего диска,
ААА — начальный восьмеричный номер куска (0 =< ААА),
ЧЧ — число кусков в восьмеричном виде (1 =< ЧЧ =< 37).

Рабочий диск — это диск, заменяющий магнитные барабаны. Кусок = 40 зон. Для
дисков емкостью 7,25 Мгб необходимо выполнить условие: N начального куска +
число кусков =< 37; для дисков емкостью 29 Мгб эта сумма не должна
превышать число 174.

Пример: `НРДИС 2052,0,17`

#### 3.5.10. `МДРЗО УУУУ,ААА,ЧЧ`

где УУУУ — десятичный номер рабочего диска,
ААА — начальный восьмеричный номер куска (0 =< ААА),
ЧЧ — число кусков в восьмеричном виде (1 =< ЧЧ =< 37).

Раздел задает поле для моделирования рабочей МЛ. Кусок = 40 зон, заказ поля
в паспорте задачи аналогичен заказу ленты: `ЛЕН 45(1С)` — заказ одного
куска. Правила задания кусков в разделе приведены в разделе `НРДИС`
(п. 3.5.15).

Пример: `МДРЗО 2052,20,17`

#### 3.5.11. `ВЛЭВМ ИМЯ`

В разделе задается имя владельца ЭВМ, которое должно состоять ровно из 11
буквенно-цифровых символов. Если есть пробелы, их необходимо заменить на
ромбики.

Пример: `ВЛЭВМ ИТМ◇И◇ВТ◇АН`

#### 3.5.12. `ГОД ЦЦЦЦ`

где ЦЦЦЦ — десятичные цифры года.

Пример: `ГОД 1989`

**Неосновные разделы**

#### 3.5.13. `ЛИСТА N`

где N — число строк АЦПУ (6 =< N =< 7).

Раздел разрешает пропуск указанного числа строк АЦПУ между страницами
текста. Если раздел не задан, то листование не производится.

#### 3.5.14. `АРХИВ СЛОВО`

где СЛОВО = ДА — работает архивная система "ARFA".

Здесь задается информация о наличии архивной системы. Если раздел не задан,
архивная система не включена в работу.

#### 3.5.15. `БЮДЖЕ СЛОВО`

где СЛОВО = ДА — работает бюджетная система.

В разделе задается информация о наличии бюджетной системы. Если раздел не
задан, бюджетная система не включена в работу.

#### 3.5.16. `ОТАС ХХ-У,ХХ-У,...`

где ХХ — физический номер терминала в АС (1 =< ХХ =< 77),
У — логический номер операторского терминала (1 =< У =< 10).

Раздел задает шкалу операторских терминалов, подключенных через аппаратуру
сопряжения (АС).

#### 3.5.17. `СДАЦ<N> К`

где N — номер АЦПУ, К — число позиций.

Раздел позволяет изменить начало печати первой позиции текста относительно
аппаратного начала на АЦПУ. Раздел применим только для АЦПУ ЕС-7040.
Следует учесть, что для выдачи всех 128-ми позиций значение "К" не должно
превышать четырех.

**Пример задания параметров для генерации ОС на серийной машине**

```
МЛЗАГ 2053-560‾        ТЕРМ VT:1-10‾
МЛСТА 2053‾            ШКОПТ Ф1-Ф11‾
ТКАНА Ф1:0-7‾
НРДИС 2053,26,2‾
```

### 3.6. Логический тумблерный регистр

ВК "Эльбрус 1-КБ" не имеет, как таковых, физических тумблерных регистров.
Моделируется один тумблерный регистр (ТР) в ячейке "1". Во время вызова ОС
информация для тумблерного регистра задается в ячейке "А", после вызова ОС
значение ячейки "А" переносится в ячейку "1", дальнейшие изменения
тумблерного регистра следует производить в ячейке "1".

Разряды тумблерного регистра имеют следующий смысл:

| Разряды     | Значение |
|-------------|----------|
| 64Р = 1     | вызов ОС с росписью каталогов; |
| 63Р = 1     | отмена листования на АЦПУ 0; |
| 62Р = 1     | отмена листования на АЦПУ 1; |
| 41-44РР     | номер варианта параметров генерации; |
| 23Р = 1     | роспись области памяти, моделирующей МБ; |
| 17-19РР     | номер ЭВМ. |

При вызове ОС приказом `ВЫЗОС Р` на ТР устанавливается 64 разряд и система
вызывается с росписью каталогов.

### 3.7. Подсчет контрольных сумм магнитных лент

Контрольные суммы магнитных лент распечатываются на АЦПУ при переписи с МЛ
на МД, а для МЛ1 — при первоначальной постановке ОС. Кроме того,
контрольные суммы магнитных лент подсчитываются по программе "UNICOP",
работа `ЕСКС` (см. [2] раздел 6). В этом случае для МЛ2 и МЛ3 необходимо
задавать номер файла = 1, для МЛ1, содержащей готовые программы ОС, номер
файла = 3. Контрольная сумма выдается на АЦПУ и на терминал.

## 4. Работа с каталогом фамилий и шифров пользователей

Для того, чтобы пользователь мог работать с операционной системой Диспак,

В каталоге фамилии (идентификатору) пользователя ставится в соответствие

4. исключить из каталога шифр отдельного пользователя или целый отдел;

## 5. Работа со стандартными паспортами

### 5.1. Общие сведения о паспорте задачи

Каждая задача, вводимая для решения в ОС Диспак, должна быть снабжена
паспортом. В нем описываются необходимые ресурсы, заказываются магнитные
ленты и диски, а также указывается шифр в смысле ОС Диспак, по которому во
время решения можно отыскать свою задачу.

Раздел паспорта начинается с названия раздела и заканчивается
надчеркиванием (код 115). В названии раздела недопустимы пробелы.

Начальным разделом всегда является `ШИФР`, затем следуют остальные разделы
паспорта в произвольном порядке. Заканчивается паспорт символом "Е".

В паспорте любой задачи должны присутствовать 4 обязательных раздела:
`ШИФР`, `ОЗУ`, `ВРЕМЯ`, `ВХОД`.

Если в паспорте нет хотя бы одного из этих разделов, задача не может быть
обслужена системой.

Кроме обязательных разделов в паспорт могут быть включены другие разделы.
Например, раздел `ЛЕНТ` указывается при работе с магнитными лентами или
дисками.

Все разделы паспорта, кроме раздела `ШИФР`, можно повторять произвольное
число раз. При этом разделы `ЛИСТ` и `ЛЕНТ` дополняют ранее заданный раздел,
либо заменяют пересекающиеся значения параметров. Для всех остальных
разделов последующее задание раздела отменяет предыдущее. При задании
раздела паспорта название раздела можно сокращать до трех символов.

### 5.2. Заведение стандартного паспорта

Для вызова трансляторов и часто используемых программ есть возможность
некоторую постоянную часть паспорта и программу вызова хранить в специально
отведенных зонах МД загрузки. Эта постоянная часть паспорта получила
название "стандартного паспорта". При заведении стандартного паспорта ему
присваивается номер, по которому впоследствии можно будет обратиться к
данному паспорту.

Номер паспорта представляет собой 2 любых символа.
Пример: `98`, `АР`, `С2`.

При обращении к стандартному паспорту в разделе "ШИФР" после цифр шифра
ставится признак "З" и номер паспорта.
При желании пользователь может заменить или дополнить некоторые разделы
стандартного паспорта.

Пример:

```
ШИФР 419925 ЗС2‾ - ОБРАЩЕНИЕ К СТАНДАРТНОМУ
          ПАСПОРТУ "С2"
       ЛЕН 44(200-ЗП)‾ - ЗАКАЗАНА МЛ
       ТРАК 100‾ - ИЗМЕНЕНО ЗАДАНИЕ КОЛИЧЕСТВА ТРАКТОВ
```

Просмотреть, завести или изменить стандартные паспорта можно с помощью
директивы `ПАСП` в системе "СЕРП".

Возможности директивы `ПАСП`:

1. выдача на экран группы паспортов или заданного паспорта с указанием
   длины паспорта (в словах), ключа, количества терминалов и шифра для
   паспортов терминальных задач;
2. заведение нового и редактирование старого паспорта;
3. выброс указанного паспорта;

* `UNICOP` — ключ диалоговой программы UNICOP.

## 8. Архивная система ОС Диспак

### 8.1. Структура архивной системы

#### 8.1.1. Ядро архивной системы

Модули / ГП архивно-файловой системы `ARFA` включены, в состав модулей / ГП
ОС Диспак. К архивно-файловой системе относятся модули / ГП: `ARFA`,
`ОБРАЗ`, `НЕРЕЗА`, `АРХИН`, `КОМАР`, `РА`, `ТРАХ`, `ГИДРА`.

#### 8.1.2. Сервисные программы

Сервисные программы архива занимают на транспортной магнитной ленте 3 ОС
Диспак участок длиной 40 зон. Структура этого участка (по зонам):

```
    1 - УСТСНЯ
    2 - СВОДКА
 3- 6 - БЮСТ
    7 - ARFA (ГП)
10-17 - СТARFA
   20 - ПРОАРХ
21-24 - БИБЛИОТЕКА ARFA
   25 - ТОЛКАЧ
   26 - МДУПЛА
   27 - КОКА
```

После переписи на МД 2048 (см. подраздел 3.2) транспортной МЛ 3 указанный
участок длиной 40 зон будет соответствовать области с именем "СЕРАРХ". По
программе "СВОДКА" необходимо получить расположение областей в зонах МД,
при отсутствии архива или росписи архивных каталогов можно обращаться к
различным программам непосредственно по номеру МД и номеру зоны.

##### 8.1.2.1. Программа `УСТСНЯ`

Программа `УСТСНЯ` предназначена для установки/снятия защиты архивных
томов. Размер программы — 1 зона. Работа с программой описана в разделе
8.6.1.

##### 8.1.2.2. Программа `СВОДКА`

Программа `СВОДКА` (см. 8.6.2) предназначена для выдачи оглавлений
первичных томов. Размер программы — 1 зона.

##### 8.1.2.3. Программа `ARFA` (ГП)

`ARFA` — диалоговая сервисная программа, позволяющая выполнять функции,
связанные с созданием и уничтожением областей, изменением их атрибутов,
управлением бюджетами и т.д. Размер программы — 1 зона. Работа с
программой описана в разделе 8.5.

##### 8.1.2.4. Программа `БЮСТ`

Сервисная программа `БЮСТ` позволяет администратору архива выдать сведения
о распределении архивного пространства. Это служебная задача мониторной
системы; размер — 4 зоны. Подробное описание программы дается в разделе
8.6.3.

##### 8.1.2.5. Программа `СТARFA`

`СТARFA` — это диалоговая система, предназначенная для просмотра
статистики по областям. Она оформлена в виде служебной задачи мониторной
системы и занимает 10 зон. Подробное описание программы дается в разделе
8.6.8.

##### 8.1.2.6. Библиотека `ARFA` (личная библиотека МС Дубна)

Личная библиотека `ARFA` содержит вариант программы `ARFA` для работы в
пакетном режиме. Длина библиотеки — 4 зоны.

##### 8.1.2.7. Программа `ТОЛКАЧ`

`ТОЛКАЧ` — сервисная программа, облегчающая переход на третью версию
архивной системы; размер программы — 1 зона. Работа с программой описана в
разделе 8.6.4.

##### 8.1.2.8. Программа `ПРОАРХ`

Вспомогательная программа `ПРОАРХ` позволяет определить, какие задачи,
находящиеся в решении или на буфере ввода, используют архивную систему.
Размер программы — 1 зона. Работа с программой описана в разделе 8.6.5.

##### 8.1.2.9. Программа `МДУПЛА`

`МДУПЛА` — программа, осуществляющая реорганизацию томов. Работа с
программой описана с разд. 8.6.6; размер программы — 1 зона.

##### 8.1.2.10. Программа `КОКА`

Программа `КОКА` осуществляет контроль целостности информации в каталогах
архива. Программа описана в разделе 8.6.7. Ее размер — 1 зона.

##### 8.1.2.11. Встроенный сервис архива

Встроенный сервис архива в настоящее время обеспечивает единственную
функцию — генерацию архивной системы. Работа с генератором описана в
разделах 8.2.3. и 8.2.3.2.

### 8.2. Постановка архива

#### 8.2.1. Перепись информации с транспортной ленты

В подразделе 8.1.2 было сказано об образовании на МД 2048 области "СЕРАРХ"
с готовыми программами сервиса архивной системы. Точно так же после
переписи транспортной МЛ 3 образуется область "ЗАПАР", которая содержит
архив типа "АРАП", состоящий из оглавления и одного файла "ЗАПАР", который,
в свою очередь, является набором "пускалок" для сервисных программ архивной
системы.

При отсутствии архивной системы к архиву "ЗАПАР", так же, как к программам
из "СЕРАРХ", можно обращаться напрямую по номеру МД и номеру зоны,
учитывая, что сдвиг в программе "РИТМ" задается в кусках.

#### 8.2.2. Запуск новой версии ОС Диспак

Необходимо загрузить версию ОС Диспак, совместно с которой была передана
архивная система. В числе параметров генерации ОС Диспак задать раздел
`АРХИВ ДА`. После вызова новой версии ОС набрать на операторском терминале
директиву `НЕТ АРХ`. Проверить отсутствие архива в решении с помощью
директивы `ВЦП 40`. Если архив находится в решении, то выполнить директиву
`ВКН 40` и дождаться его снятия.

#### 8.2.3. Генерация архивной системы

После вызова новой системы до задания времени средствами ППО необходимо
занести в ячейки 1 и 76003(8) информацию для вызова генератора архива:

```
64-40 РР. = 0;
   39 РР. = 1;
38-23 РР. = 0;
22-17 РР. - ЛОГИЧЕСКИЙ НОМЕР НЕОПЕРАТОРСКОГО ТЕРМИНАЛА,
            С КОТОРОГО БУДЕТ ПРОИЗВОДИТЬСЯ ГЕНЕРАЦИЯ АРХИВА;
16-1 РР.=0.
```

Затем следует набрать директиву `ВРЕМЯ` и убедиться в формировании архива.

После этого на операторский терминал будет выдано сообщение

```
АРХ:ТТ=ЛNТЕРМ,
```

а на указанный терминал будет выдано приглашение `КЛЮЧ`, в ответ на
которое необходимо указать ключ администратора архива. Если архив
генерируется впервые, то запрос ключа не производится.

Затем выдается приглашение `АРХ>`. По директиве `СЕРВИС` произойдет переход
в блок встроенного сервиса архива.

После этого пользователю выдается сообщение о версии программы сервиса
архива и запрашивается имя требуемой программы; в ответ необходимо задать
имя `ГЕН`.

Работа генератора может происходить в двух режимах: в режиме полной
генерации, когда значения всех основных параметров запрашиваются у
пользователя автоматически. И в режиме активности пользователя, когда
пользователь сам указывает имена параметров.

##### 8.2.3.1. Определение параметров архива

##### 8.2.3.1.1. Архивное пространство

Архиву требуются один или два постоянно стоящих диска: на одном из них
располагаются каталоги архива, на другом — их дубли (всякая запись
информации в каталог сопровождается записью и в его копию). В тех случаях,
когда не представляется возможным выделить архиву два постоянно стоящих
диска, возможно расположить и каталоги, и их копии на одном диске. В
начальном состоянии каталоги занимают 10(8) зон на каждом из дисков.

Оба диска должны быть заданы в генерации ОС как общие.

Внимание! Если архиву для каталогов выделяется только один диск, то при
генерации на вопросы `МД АРХ-` и `МД ДУБ-` задается один и тот же номер, а
на вопросы `L АРХ-` и `L ДУБ-` следует указывать полную длину этого диска.

После запроса томов для каталогов возможны вопросы: "ОТСУТСТВУЮТ

Диагностика `НЕТ МЕСТА НА БУФЕРЕ РАБОТ` означает, что перед генерацией
необходимо освободить (на старой версии архива) 30(8) зон на основном
диске архива.

##### 8.2.3.1.2. Общие шифры

В том случае, когда пользователь обращается к области, не указав ее
хозяина (например, поставив в паспорте раздел `ЛЕНТ 30(ДУБНА)‾`), область
с таким именем ищется среди его файлов и, если такого имени там нет,
осуществляется последовательный поиск этой области в "библиотеках" группы,
отдела и в "общей библиотеке". Так, если первые шесть цифр шифра задачи —
"АААААА", то будет выбрана первая существующая из областей "ДУБНА/АААААА",
"ДУБНА/ААААХХ", "ДУБНА/ААУУУУ", "ДУБНА/ZZZZZZ", где "ХХ" — признак группы
(рекомендуемое значение — ".."), "УУУУ" — признак отдела (рекомендуемое
значение — "0099"), "ZZZZZZ" — общий шифр (рекомендуемое значение —
"999999"). Сам шифр 9999 заводить (регистрировать ФИО в ОС) нельзя, хотя
для других значений общего шифра это разрешено.

##### 8.2.3.1.3. Максимальная длина областей

Независимо от размеров свободного архивного пространства и бюджета,
выделенного пользователю, устанавливается предельный размер областей,
которые могут создаваться на данном вычислительном комплексе. Это
ограничение недействительно для администратора архива. Рекомендуется
задавать значение этого параметра возможно меньшим.

##### 8.2.3.1.4. Наличие многомашинного комплекса

В тех случаях, когда архив работает на одной ЭВМ, служебные обмены
буферизуются, что позволяет существенно повысить скорость работы архивной
системы.

При генерации запрашиваются номера ЭВМ, для которых является общим архив.
Затем многократно производится запрос: "ЭВМ С общим указать список номеров
ЭВМ, имеющих общий буфер ввода-вывода (общий диск 2053).

##### 8.2.3.1.5. Наличие бюджетной системы

Возможна работа архива без бюджетной системы; в этом случае все
пользователи пользуются неограниченными правами заведения областей (однако
использование этого режима не рекомендуется).

##### 8.2.3.1.6. Интервал проверки целостности каталогов

В процессе выполнения ряда работ (таких, как создание и уничтожение
областей и т.п.) нарушается целостность каталогов архива. При этом в
специально выделенной зоне каталога сохраняется информация, необходимая
для восстановления непротиворечивости информации в случае сбоя ЭВМ. Однако
проверка этой зоны осуществляется только перед выполнением новой
аналогичной работы, либо по истечении заданного интервала.

Рекомендуемое значение параметра — 1-4 часа.

##### 8.2.3.1.7. Интервал запуска вталкивания/выталкивания

У пользователя запрашивается, будут ли использоваться средства
вталкивания/выталкивания. При отрицательном ответе другие вопросы не
задаются.

Все работы, связанные с вталкиванием/выталкиванием запускаются
автоматически практически во всех необходимых случаях: при установке
вторичного тома, при обращении к вытолкнутой области и т.п. Однако, если
машины, работающие с архивом, имеют раздельные буфера ввода, то архив не
получит события в том случае, когда область, необходимая задаче, введенной
на одной машине, подкачана на другой ЭВМ. В этом случае проверка на
вталкивание осуществляется через заданные интервалы времени.

##### 8.2.3.1.8. Интервал обслуживания вторичного тома

В случае использования вталкивания/выталкивания пользователю

Если к нерезидентной области в течение срока, заданного данным параметром
(в сутках), не было обращений, то область считается пригодной для
выталкивания на вторичный том. Рекомендуемое значение параметра — 5-10
суток.

Данный параметр, так же как и предыдущий, имеет значение в том случае,
когда архив работает на нескольких ЭВМ, имеющих раздельные буфера ввода.
Параметр определяет, с какой частотой будут осуществляться работа по
вталкиванию/выталкиванию со вторичным томом. Рекомендуемое значение — один
час.

##### 8.2.3.1.9. Срок хранения областей на первичном томе

Если к нерезидентной области в течение срока, заданного данным параметром
(в сутках), не было обращений, то область считается пригодной для
выталкивания на вторичный том. Рекомендуемое значение параметра — 5-10
суток.

##### 8.2.3.1.10. Интервал проверки освобождения области от захвата

Если пользователь выдал экстракод безусловного захвата области (`Э50 ’115’`
или его аналог), то архивная система проверяет, не захвачена ли эта
область задачей, работающей на другой ЭВМ. Если в каталогах архива имеется
отметка о захвате области другой машиной, то задача, выдавшая экстракод
безусловного захвата, закрывается до тех пор, пока область не освободится.
Проверка освобождения (повторное чтение каталогов) осуществляется через
задаваемый интервал. Рекомендуемое значение — 5 секунд.

##### 8.2.3.1.11. Выбор тома для создания области

Имеется возможность запретить создание областей на неустановленных томах.
Такой запрет можно установить отдельно для каждого типа томов. У
пользователя запрашивается список групп, для которых допускается создание
только на установленных томах, — отдельно по видам "ДИСК" и "ЛЕНТ".

##### 8.2.3.12. Группа для упрятывания

Для упрятывания задач по директиве оператора `УПР` операционная система
создает области архива. Эти области имеют нулевой вид, а их группа
задается при генерации архива.

##### 8.2.3.13. Шкала групп для `БАЦ`

Параметр задает шкалу групп, использование которых допускается при
создании областей буферизации выходного потока задачи (по разделу паспорта
`БАЦ`).

##### 8.2.3.14. Управляющие директивы

* `ВЫД` — обеспечивает выдачу параметров генерации архива.
* `ПЕЧ` — параллельная печать протокола работы.
* `ЗАП` — запись параметров генерации архива.
* `КНЦ` — окончание работы с генератором.

##### 8.2.3.2. Генерация архива

Генерация архива начинается после выполнения действий, предписанных пунктом
8.2.3.

Параметры генерации архива хранятся в зоне 751 системного диска; после
генерации необходимо обеспечить дублирование этой зоны на дубли системных
пакетов. Если ЭВМ многомашинного комплекса работают с разными системными
пакетами, то генерацию следует проводить на каждой из ЭВМ комплекса.

Для того, чтобы осуществить роспись каталогов архива, необходимо на 1-м
тумблерном регистре задать в 16-1 разрядах двоично-десятичный номер МД
архива (в противном случае программа завершится с диагностикой `НЕТ КЛЮЧА
РОСПИСИ КАТАЛОГОВ!`). Номера разрядов приведены в представлении БЭСМ-6.

При росписи каталогов архива тома МДАРХ и МДДУБ заносятся в состав архива
как тома 0-й группы вида "Д".

### 8.3. Сообщения архивной системы

При работе архивно-файловой системы на операторский терминал могут
выдаваться описываемые ниже сообщения (в скобках указывается номер
маршрута, по которому данное сообщение выдается).

#### 8.3.1. Сообщение об отсутствии параметров архивной системы на системном диске (2053)

```
(2) ПРОВЕРЬ ПАРАМЕТРЫ АРХ.
```

В 751-й зоне системного диска отсутствуют параметры архива, либо заданное
в них размещение дублей каталогов не соответствует хранимому на МД архива.

#### 8.3.2. Сообщение об отсутствии архивного тома

```
(1) УСТАНОВИ МД АРХ.
(5) УСТ.СРЧ.К20Б<НОМЕР ТОМА>
```

Необходимо установить указанный в сообщении том на накопитель.

#### 8.3.3. Сообщение о порче каталогов архива

```
(2) НЕТ КЛЮЧА ЗОНЫ
```

При запуске архива в начальной зоне каталога (на основном или
дубль-диске) испорчен ключ каталога.

#### 8.3.4. Сообщение о несоответствии версии каталогов и версии программ архивной системы

```
(2) СМЕНИ ВЕРСИЮ АРХ
```

При запуске архива обнаружено несоответствие версий. Необходимо
откорректировать каталоги с помощью генератора архива.

#### 8.3.5. Сообщение о сбое архивной системы

```
(2) ВНИМАНИЕ - СБОЙ АРХИВА
```

Ситуация возникает вследствие ошибки аппаратуры или программного
обеспечения. Одновременно с выдачей этого сообщения на АЦПУ
распечатывается информация о состоянии архива в момент сбоя (промежуточная
выдача под шифром `41991981062<N ЭВМ>`), которую следует передать
разработчикам архивной системы.

#### 8.3.6. Сообщения об ошибках ввода

```
(2) НЕТ ОБЛАСТИ <ИМЯ ОБЛАСТИ>
    <ШИФР> ВЫБР
```

В паспорте задачи с шифром `<ШИФР>` заказана несуществующая область с
именем `<ИМЯ ОБЛАСТИ>`.

```
(2) НЕСАНКЦИОН.ДОСТУП <ИМЯ ОБЛАСТИ>
   <ШИФР> ВЫБР
```

У задачи с шифром `<ШИФР>` заказана в паспорте область, к которой данный
пользователь не имеет права обращаться; либо заказана на запись область, к
которой пользователь имеет права обращаться только для чтения.

#### 8.3.7. Сообщение о блокировке работы архива

```
(2) АРХИВ ЖДЕТ
```

Работа с архивом заблокирована директивой `НЕТ АРХ` (см. 4).

#### 8.3.8. Сообщение о порче вторичного тома

```
(2) ТОМ <НОМЕР ТОМА>: ОШ.В КЛЮЧЕ
    ИЛИ
(2) ТОМ <НОМЕР ТОМА>: ЧУЖОЙ
```

В каталоге вторичного тома отсутствует ключ либо, при наличии ключа, —
неверно задан владелец ЭВМ.

#### 8.3.9. Сообщение об ошибке МД

```
(2) АРХ:Т.<НОМЕР ТОМА>-<НОМЕР ЗОНЫ> ОШЧТ
 (2) АРХ:Т.<НОМЕР ТОМА>-<НОМЕР ЗОНЫ> ОШЗП
```

Не проходит обмен с указанной зоной указанного тома.

#### 8.3.10. Сообщение о вызове генератора архива

```
(2) АРХ: ТТ=Л<ЛОГИЧЕСКИЙ НОМЕР ТЕРМИНАЛА>
```

Сообщение свидетельствует о вызове встроенного сервиса архива с терминала,
имеющего указанный логический номер.

#### 8.3.11. Сообщение о некорректном вызове генератора

```
(2) АРХ: ТТ=Л<ЛОГИЧЕСКИЙ НОМЕР ТЕРМИНАЛА>
 (2) ВНИМАНИЕ: ПОПЫТКА ВХОДА
```

Сообщение свидетельствует о попытке вызова встроенного сервиса архива с
терминала, имеющего указанный логический номер, если был указан неверный
ключ администратора архива.

### 8.4. Управление работой архивной системы

#### 8.4.1. Директивы `ДАЙ АРХ` и `НЕТ АРХ`

В том случае, когда была выполнена директива `НЕТ АРХ`, работа архивной
системы блокируется. На операторский терминал выдается ответ `ЕСТЬ`. По
второму маршруту (логическому каналу) периодически выдается `АРХИВ ЖДЕТ`.
В этом режиме на директиву `РЕЖ` сообщается `АРХИВ ОТКЛ.`. Отмена режима
выполняется директивой `ДАЙ АРХ`.

#### 8.4.2. Вызов генератора

Для вызова генератора надо после вызова ОС до задания времени занести в
слова 1 и 76003(8) "приказ":

```
64-40 РР. = 0;
   39 РР. = 1;
38-23 РР. = 0;
22-17 РР. - ЛОГИЧЕСКИЙ НОМЕР ПОЛЬЗОВАТЕЛЬСКОГО ТЕРМИНАЛА,
            С  КОТОРОГО   БУДЕТ   ПРОИЗВОДИТЬСЯ   ГЕНЕРАЦИЯ
АРХИВА;
16-1 РР.=0.
```

"Приказ" может быть выполнен: при включении архива в решение; при
блокировке архива директивой `НЕТ АРХ`; при снятии архива по ошибке.

После этого на указанный терминал будет выдано приглашение `КЛЮЧ:`, в ответ
на которое необходимо указать ключ администратора архива. Если архив
генерируется впервые, то запрос ключа не производится.

Затем производится запрос `ТОМ:`; пользователь должен указать номер тома, на
котором располагается встроенный сервис архива, необходимо указать ровно 4
цифры.

На запрос `ЗОНА:` необходимо указать начальную зону встроенного сервиса
(т.е. "1030"), здесь также должно задаваться ровно 4 цифры.

#### 8.4.3. Директива `ВКН 40`

Если на 1-м тумблерном регистре зажат только 23-й разряд, то при снятии
архива по директиве `ВКН 40` на АЦПУ будет выдана информация о состоянии
архива.

### 8.5. Директивы администратора архивной системы

В данном разделе описываются те директивы программы `ARFA`, которые
доступны только администратору архива (т.е. администратору бюджета
"......" .

#### 8.5.1. Внесение тома в каталоги архивной системы

##### 8.5.1.1. Описание директивы

```
ВНБОБ Б=<НОМЕР ТОМА>,L=<ЧИСЛО ЗОН>,Г=<ГРУППА>,
В=<ВИД ТОМА>
```

* `<НОМЕР ТОМА>` — десятичное целое число, определяющее номер передаваемого
  в архив тома;
* `<ЧИСЛО ЗОН>` — восьмеричное число — размер тома (0 < L < 65436),
  стандартные значения для МД 200 Мгб — 45424 зоны;
* `<ГРУППА>` — может принимать значения от 0 до 3;
* `<ВИД ТОМА>` — возможные значения — "Д", "Н", "Л";
* в результате исполнения данной директивы указанный том включается в
  архивное пространство и становится недоступным для непосредственного
  обращения;
* при включении в состав архива вторичного тома следует установить том на
  накопитель, так как вторичный том располагает собственным оглавлением,
  которое формируется на нем в момент исполнения директивы. В связи с тем,
  что в это оглавление записывается, в частности, владелец ЭВМ,
  необходимо, чтобы на всех ЭВМ комплекса значение параметра генерации ОС
  `ВЛЭВМ` было одинаковым на всех ЭВМ комплекса.

##### 8.5.1.2. Диагностические сообщения

* `ОШ.В НОМЕРЕ ТОМА` — допущена ошибка при задании номера тома;
* `ТОМ УЖЕ В АРХИВЕ` — при попытке повторного включения тома в архив
* `ОШИБКА ВИДА` — неверно задан вид тома;
* `НЕТ МЕСТА В КАТ.` — нет места для размещения информации о томе;
* `НЕ УСТАНОВЛЕН ТОМ` — при внесении в состав архива вторичного тома этот
  том не установлен.

##### 8.5.1.3. Авостные ситуации

* `ЗАПРЕЩ.ЭКСТРАКОД` — директива выдана не администратором архива
  (фатальный авост);
* `ОШ.В ИНФ.СЛ.ЭКСТ` — задан нулевой номер тома или нулевая длина тома.

#### 8.5.2. Дублирование тома

##### 8.5.2.1. Описание директивы

```
ФОТО Ч=<АДРЕС ЧТЕНИЯ>,З=<АДРЕС ЗАПИСИ>,
L=<ЧИСЛО КОПИРУЕМЫХ ЗОН>
```

`<АДРЕС ЧТЕНИЯ>` и `<АДРЕС ЗАПИСИ>` задаются в виде "<номер тома>" или
"(<номер тома>,<нач.зона>). В первом случае считается, что начальная зона
равна нулю.

При исполнении данной директивы все другие работы архивной системы на
данной ЭВМ блокируются, и осуществляется перепись заданной части архивного
тома на том, выделенный для копирования. При этом том, на который
осуществляется копирование, также становится недоступным для
непосредственного обращения. При исполнении данной директивы необходимо
заблокировать работу архивной системы на других ЭВМ комплекса с помощью
директивы `НЕТ АРХ` (см. 8.4.1).

#### 8.5.3. Исключение тома из архива

##### 8.5.3.1. Описание директивы

```
УНТ Б=<НОМЕР ТОМА>
```

Директива позволяет исключить том из состава архивного пространства.
Исключение возможно только в тех случаях, когда на томе не располагаются
каталоги (то есть том не является ни томом каталогов, ни томом копий) и не
имеется ни одной области.

Директива доступна только администратору архива.

##### 8.5.3.2. Диагностические сообщения

* `ОШ.В НОМЕРЕ ТОМА` — неверно задан номер тома
* `ТОМ УЖЕ В АРХИВЕ` — попытка исключения тома с каталогами или тома, на
  котором имеются области
* `НЕ УСТАНОВЛЕН ТОМ` — исключаемый том не включен в архив

##### 8.5.3.3. Авостные ситуации

* `ЗАПРЕЩ.ЭКСТРАКОД` — директива выдана не администратором архива

#### 8.5.4. Резервирование места для размещения каталогов

##### 8.5.4.1. Описание директивы

```
РЕЗЕРВ Б=<НОМЕР ТОМА>,L=<ЧИСЛО ЗОН>
```

* Директива позволяет зарезервировать на основном томе или томе с дублями
  каталогов "неприкосновенный запас" зон для размещения каталогов. По
  данной директиве из общего об’ема свободного пространства изымается
  заданное число зон (меньше 2000(8)). Если на диске свободно меньше места,
  чем резервируется, то резервируется (становится недоступным для создания
  областей) все свободное пространство.
* Директива доступна только администратору архива.

##### 8.5.4.2. Авостные ситуации

* `ЗАПРЕЩ.ЭКСТРАКОД` — директива выдана не администратором архива
* `ОШ.В ИНФ.СЛ.ЭКСТ` — номер тома не совпадает с номером основного диска и
  диска дублей

### 8.6. Работа с сервисными программами

#### 8.6.1. Программа `УСТСНЯ`

В ряде случаев для осуществления системных работ требуется снятие признака
архивного диска, защищающего том от прямого обращения экстракодом обмена.
Для этой цели следует использовать сервисную программу, включенную в состав
генератора архива.

##### 8.6.1.1. Запуск программы

Запуск программы осуществляется с помощью системы `СЕРП`. Предварительно
следует выполнить директиву `НЕТ АРХ` и выбросить из решения архив с помощью
директивы `ВКН 40`.

```
СП 4419988
 ИТМ И ВТ. С Е Р П: <ВЕРСИЯ>
 ЧТО-      ШИФР 41991981062<N ЭВМ>
   ШИФР 41991981062<N ЭВМ>
 ЧТО-      РИТМ
 ** РИТМ: <ВЕРСИЯ> **
 ТОМ-      ЗАПАР
 РАБОТА-   РААП
 ИМЯ-      ЗАПАР
 -         Ф УСТСНЯ
 + ИЛИ -   <"-" ДЛЯ СНЯТИЯ ПРИЗНАКА АРХИВНОГО
            ТОМА; "+" - ДЛЯ УСТАНОВКИ>
 N ТОМА-   <НОМЕР ТОМА (4 ЦИФРЫ)>
   NNN: ПРОГР УСТСНЯ
 -         КНЦ
 ЧТО-      КНЦ
   КОНЕЦ СЕАНСА
```

После окончания данной программы на АЦПУ выдается распечатка, где
указывается выполненная операция (`УСТАНОВЛЕНА/СНЯТА ЗАЩИТА ТОМА NNNN`) и
приводится список защищенных признаком архивности томов.

**Внимание!** Реально признак архивного тома снимется (установится) только
после переопознания тома.

##### 8.6.1.2. Дополнительные возможности

Возможен запуск программы из пакета; при этом появляется возможность
задавать информацию об установке/снятии признаков защиты для нескольких
томов:

```
ШИФР 41991981962N
ЛЕН 42(<МД ТЕКСТОВ>)
ОЗУ 3
ВХО 1
ВРЕ 100
Е
В 1 К 00 070 0002 С00 10 0000 0042 1001
В 70010
БХ*ТТТТ
БХ*ТТТТ
.......
Б000000
ЕКОНЕЦ
```

Здесь "Х" — произвольный символ; "\*" — символ "+" или "-"; "ТТТТ" — номер
тома.

#### 8.6.2. Программа `СВОДКА`

##### 8.6.2.1. Вызов программы

Программа `СВОДКА` вызывается с терминала по ключу:

```
СВОДКА  <ШИФР>
```

Шифр может содержать шесть или двенадцать цифр. При этом первые (и,
возможно, единственные) шесть цифр должны соответствовать шифру
администратора архива. Если следующие шесть цифр не заданы (или равны
нулю), то выдается оглавление основного архивного диска. В противном случае
последние шесть цифр должны иметь вид "00NNNN", где NNNN — номер тома, по
которому требуется сводка.

При входе программы в решение на терминал выдается запрос `КЛ.АДМ.:` и
открывается прием в секретном режиме для ввода ключа администратора архива.
После набора ключа на терминал выдается:

```
СВОДКА ПО ТОМУ NNNN. ТЕРМИНАЛ СВОБОДЕН.
```

и терминал освобождается.

##### 8.6.2.2. Выдаваемая информация

При нормальном завершении на АЦПУ выдается следующая информация: заголовок
(номер тома, вид и группа тома, общее количество свободных зон, номер МД
каталогов и МД дублей каталогов); оглавление тома; сообщения об ошибках в
оглавлении тома.

Оглавление тома выдается в виде таблицы, содержащей четыре графы: размер
участка, начальная и конечная зона участка, порядковый номер участка в
области, имя области. Если на томе располагаются каталоги, то вместо имени
области выдается название соответствующего каталога, а вместо номера
участка — порядковый номер зоны каталога данного вида. Пометка "(2)" при
названии каталога означает, что эта зона предназначена для размещения
дубля каталога (соответствующую основную зону можно определить по номеру
участка).

Если фрагментация тома приближается к критической (то есть существуют
области, занимающие число участков, близкое к предельно допустимому), то
программа выдает сообщение: `ТРЕБУЕТСЯ РЕОРГАНИЗАЦИЯ ТОМА`. В этом случае
необходимо воспользоваться программой "МДУПЛА" (см. 8.6.6).

В случае нарушения целостности каталогов могут выдаваться сообщения:
`ПОТЕРЯНЫ ЗОНЫ: <НОМЕРА ЗОН>`, `ДВАЖДЫ ЗАНЯТЫ: <НОМЕРА ЗОН>`. В этом случае
рекомендуется обратиться к разработчикам.

При неправильном задании входной информации или при порче каталогов могут
выдаваться сообщения:

```
-НЕТ ПРИПИСКИ В ЗОНЕ
-ПРИПИСКА НЕ ОКОНЧЕНА
-НЕТ ТОМА В КАТАЛОГЕ БОБИН
-НЕТ ИНФОРМАЦИИ О ТОМЕ
-НЕ ИМЕЕТЕ ПРАВА
-ОШИБКА ВО ВХОДНОЙ ИНФОРМАЦИИ
```

При этом оглавление тома не выдается.

##### 8.6.2.3. Дополнительные возможности

Возможны следующие расширения стандартного паспорта программы `СВОДКА`.
Вместо номера МД каталогов в слове по адресу 2000 может быть задан любой
другой архивный диск. В этом случае при отсутствии номера тома в шифре
задачи сводка будет выдаваться по этому тому. По адресу 2001 возможно
задать ключ администратора архива. В этом случае запрос ключа
администратора с терминала не производится. Кроме того, при этом возможен и
запуск программы в пакетном режиме (с тем же паспортом).

#### 8.6.3. Программа `БЮСТ`

##### 8.6.3.1. Вызов программы

Вызов программы осуществляется с терминала по ключу:

```
БЮСТ <ШИФР>
```

причем первые шесть цифр шифра должны соответствовать шифру администратора
архива. При входе программы в решение на терминал выдается запрос
`КЛЮЧ АДМ.:`, на который пользователь должен задать в режиме секретного
приема ключ администратора архива. После этого на терминал выдается запрос
`ВИД -`. В ответ необходимо указать вид ресурсов, по которому необходимо
получить сведения: `ДИСК`, `НЕРЕЗ`, `ЛЕНТА`. Затем вновь задается вопрос
`ВИД-`. В ответ можно указать другой вид. Вопрос повторяется до тех пор,
пока пользователь не ответит на него пустой посылкой. Сведения выдаются по
всем указанным видам ресурсов.

Затем программа выдает запрос `ПАР-`. Подобно предыдущему, этот вопрос
повторяется до тех пор, пока в ответ на него не будет получена пустая
посылка. На каждый запрос пользователь должен задавать один из описанных
ниже параметров. Значения параметров будут выдаваться для каждого
имеющегося в архиве бюджета отдельно для каждого из заданных видов.
Возможно задание следующих параметров:

* `ВЫД` — об'ем пространства, выделенного данному бюджету;
* `ИСП` — суммарная длина всех областей, созданных из данного бюджета и его
  подчиненных;
* `ОСТ` — число зон, не использованных данным бюджетом и его подчиненными
  бюджетами (ВЫД = ИСП + ОСТ);
* `РАСПР` — об'ем пространства, распределенного данным бюджетом
  нижестоящим бюджетам;
* `РЕЗ` — об'ем пространства, не занятого областями и не отданного
  нижестоящим бюджетам (то есть остаток с точки зрения архивной системы).

Соответствующие графы таблицы имеют заголовки "ВЫДЕЛЕНО", "ОБЛАСТИ",
"НЕ ИСПОЛЬЗОВАНО", "РАСПРЕДЕЛЕНО", "РЕЗЕРВ".

После ввода параметров выдается сообщение:

```
РАБОТАЕТ ПРОГРАММА ’БЮСТ’.  ТЕРМИНАЛ СВОБОДЕН
```

и терминал освобождается.

##### 8.6.3.2. Выдаваемая информация

В результате работы программы на АЦПУ выдается распечатка, содержащая
следующие графы:

* шифр бюджета;
* шифр администратора бюджета;
* группы, работа с которыми разрешена данному бюджету;
* сведения о ресурсах, имеющихся у каждого бюджета, по тем видам и
  параметрам, которые были заданы при запуске.

Для бюджета "......" об'ем выделенного пространства считается равным
об'ему пространства, выделенного всем подчиненным бюджетам.

##### 8.6.3.3. Дополнительные возможности

Стандартный паспорт программы может быть дополнен конструкцией:

```
В 20000
Б<КЛЮЧ АДМИНИСТРАТОРА АРХИВА>
С<ШКАЛА ВЫДАВАЕМЫХ ВИДОВ>
С<ШКАЛА ВЫДАВАЕМЫХ ПАРАМЕТРОВ>
```

Здесь шкалы начинаются с 48-го разряда и соответствуют перечислению видов
(параметров) в 8.6.3.2. Например 47-й разряд соответствует в первой шкале —
виду `НЕРЕЗ`, а во второй — параметру `ИСП`.

При наличии такой конструкции в паспорте диалог с терминалом не
производится (выдается лишь сообщение `ТЕРМИНАЛ СВОБОДЕН`). Кроме того, при
этом возможен и запуск программы в пакетном режиме.

#### 8.6.4. Программа `ТОЛКАЧ`

Программа "ТОЛКАЧ" — это программа одноразового использования,
предназначенная для облегчения перехода на третью версию архивной системы
(версия ОС Диспак 104 от 05.06.84 и более поздние). Программа позволяет
осуществить "массовое" изменение вида областей с резидентного на
нерезидентный.

Запуск программы осуществляется с помощью системы `СЕРП`. При этом
требуется отсутствие архива в решении, так как эта программа работает на
специальном программном канале.

```
                          СП 419988
СЕРП: <ВЕРСИЯ>
ЧТО-                       ШИФР 41991981062<N ЭВМ>
ШИФР 41991981062<N ЭВМ>
ЧТО-                      РИТМ
 ’РИТМ’ <ВЕРСИЯ>
 ТОМ-                        ЗАПАР
РАБОТА-                     РААП
ИМЯ-                        ЗАПАР
-                          Ф ТОЛКАЧ
ШИФР-                      <ШИФР - 6 ЦИФР ИЛИ ТОЧЕК>
ШИФР-                      . . . . . .
. . . . . . . . . . . . . . . . . . . .
ШИФР-                      <ПУСТАЯ ПОСЫЛКА>
NNN: ПРОГР ТОЛКАЧ
-                           КНЦ
ЧТО-                        КНЦ
 КОНЕЦ СЕАНСА
```

На запрос `ШИФР-` задаются те пользователи (или группы пользователей, если
используются шифры с точками), области и бюджеты которых остаются в
неприкосновенности. Все области, хозяева которых не включены в список,
получают в результате работы программы второй тип. Все бюджеты, шифры
которых не включены в список, вместо ресурсов вида "Д" (первичный) получают
равное количество зон вида "Н" (вторичный). Возможно задание в списке до
восьми шифров.

После окончания работы программы на АЦПУ выдается следующая информация:
шифры, заданные в качестве входной информации к программе, и сообщение,
характеризующее причину завершения работы:

| Сообщение      | Значение |
|----------------|----------|
| `ВЫПОЛНЕНО`    | Нормальное завершение программы; |
| `НЕТ МД АРХ.`, `НЕТ МД ДУБ.`, `НЕТ СИСТ.МД` | Отсутствие соответствующего диска на устройствах данной ЭВМ; |
| `НЕВЕРН.ШИФР`  | В списке имеется неправильно заданный шифр. |

**Внимание!** Повторный запуск лишь увеличивает число областей
нерезидентного вида; поэтому в тех случаях, когда число шифров, которые вы
хотите задать, превышает 8, вам необходимо "укрупнить" шифры (то есть
добавить в них "точек") с тем, чтобы свести количество привилегированных
групп к восьми.

#### 8.6.5. Программа `ПРОАРХ`

Программа "ПРОАРХ" — вспомогательная программа, позволяющая определить,
имеются ли на буфере ввода и в решении задачи, использующие архив. Запуск
программы осуществляется с помощью системы "СЕРП":

```
                         СП <ШИФР>
СЕРП: <ВЕРСИЯ>
ЧТО-                       РИТМ
 ’РИТМ’ <ВЕРСИЯ>
 ТОМ-                       ЗАПАР
РАБОТА-                    РААП
ИМЯ-                       ЗАПАР
-                          Ф ПРОАРХ
 NNN: ПРОГР ПРОАРХ
-                          КНЦ
ЧТО-                       КНЦ
 КОНЕЦ СЕАНСА
```

В результате работы программы на печать выдаются следующие сообщения:

| Сообщение            | Значение |
|----------------------|----------|
| `КАНАЛЫ С ОБЛАСТЯМИ` | Номера программных каналов, по которым решаются задачи, работающие с областями |
| `КАНАЛЫ, ИСП.АРХИВ`  | Номера программных каналов, которые в данный момент не имеют заказанных областей, но ранее обращались к архиву |
| `ЖДУТ ПРОСМОТРА`     | Номера задач на буфере ввода, которые ждут просмотра архивной системой (в том числе и задачи с разделом "ЖДЕМ" и "ТЕЛЕ" в паспорте); |
| `ЗАПРЕЩЕНЫ АРХИВОМ`  | Номера задач на буфере ввода, которые просмотрены архивной системой, но по какой либо причине (вытолкнуты области, заняты индивидуальные области) не получили от нее разрешения на включение; |
| `ЖДУТ ВКЛЮЧЕНИЯ`     | Задачи на буфере ввода, заказавшие области в паспорте, и которые с точки зрения архивной системы полностью пригодны для включения в решение. |

Если задачи, использующие области, отсутствуют, то выдается сообщение
`АРХИВ НЕ ИСПОЛЬЗУЕТСЯ ЗАДАЧАМИ!`.

#### 8.6.6. Программа `МДУПЛА`

Программа "МДУПЛА" осуществляет реорганизацию архивных томов. Необходимость
в запуске программы возникает, если фрагментация тома становится близкой к
критической, то есть на томе появляются области, которые занимают
предельно допустимое число участков. О необходимости запуска программы
реорганизации выдает предупредительное сообщение "СВОДКА".

##### 8.6.6.1. Запуск программы

Перед запуском программы необходимо выбросить из решения архив и запретить
его повторное формирование на всех ЭВМ комплекса (то есть выполнить
директивы `НЕТ АРХ` и `ВКН 40` на каждой машине). Для работы программы
необходим вспомогательный диск, по размеру не меньший, чем уплотняемый.
Запуск программы осуществляется с помощью системы "СЕРП":

```
                             СП 419988
СЕРП: <ВЕРСИЯ>
ЧТО-                         ШИФР  41991981062<N  ЭВМ>  ШИФР
41991981062<N ЭВМ>
ЧТО-                         РИТМ
 ’РИТМ’
 ТОМ-                         ЗАПАР
РАБОТА-                      РААП
ИМЯ-                         ЗАПАР
-                            МДУПЛА
МД УПЛ-                      <НОМЕР РЕОРГАНИЗУЕМОГО ДИСКА>
МД БУФ-                      <НОМЕР  ВСПОМОГАТЕЛЬНОГО ДИСКА>
 NNN: ПРОГР МДУПЛА
-                            КНЦ
ЧТО-                         КНЦ
 КОНЕЦ СЕАНСА
```

При работе программа "МДУПЛА" использует четыре диска: основной диск
архива, диск с копиями каталогов, уплотняемый диск и буферный диск.

##### 8.6.6.2. Сообщения программы

* Сообщения об отсутствии необходимых МД:

  ```
  УСТАНОВИ АРХИВНЫЙ ДИСК
  УСТАНОВИ ДИСК ДЛЯ ДУБЛЕЙ КАТАЛОГОВ
  УСТАНОВИ УПЛОТНЯЕМЫЙ ДИСК
  УСТАНОВИ БУФЕРНЫЙ ДИСК
  ```

* Сообщения об ошибках во входной информации:

  ```
  НЕВЕРНЫЙ НОМЕР ТОМА
  БУФЕРНЫЙ ДИСК ПРИНАДЛЕЖИТ АРХИВУ
  МДУПЛ НЕТ В АРХИВЕ
  ```

* Сообщения об ошибках в каталогах архива:

  ```
  ОШИБКА В КАТАЛОГЕ ДУБЛЬ-ЗОН
  ОШИБКА В ЗОНЕ ПРИПИСКИ
  ОШИБКА В КАТАЛОГЕ БОБИН
  ```

* Сообщение о нормальном завершении:

  ```
  УПЛОТНЕНИЕ АРХИВНОГО ДИСКА ЗАКОНЧИЛОСЬ
  ```

При завершении программы с причиной из группы (С) или аварийном завершении
(в том числе в результате сбоя ЭВМ или накопителя) перед запуском архивной
системы или повторным запуском программы "МДУПЛА" необходимо восстановить
уплотняемый диск, диски с каталогами и их копиями к состоянию,
предшествовавшему запуску программы. В связи с этим перед запуском
программы всегда необходимо осуществлять копирование этих трех дисков.

#### 8.6.7. Программа `КОКА`

Программа "КОКА" осуществляет контроль каталогов архива. Она позволяет
обнаружить практически все несоответствия в каталогах архива. Рекомендуется
запускать эту программу периодически и в случае появления сообщений об
ошибках немедленно обращаться к разработчикам.

Замечание. Поставляемая в настоящее время версия программы "КОКА"
осуществляет лишь контроль ссылок в каталоге областей.

##### 8.6.7.1. Запуск программы

Запуск программы осуществляется с помощью системы `СЕРП`. Предварительно
следует выполнить директиву `НЕТ АРХ` и выбросить из решения архив с помощью
директивы `ВКН 40`.

```
                               СП 419988
ИТМ И ВТ. С Е Р П: <ВЕРСИЯ>
ЧТО-                           ШИФР 41991981062<N ЭВМ>
```

##### 8.6.7.2. Сообщения программы

При отсутствии ошибок в каталогах архива на печать выдается сообщение
`ОШИБКИ В КАТАЛОГАХ НЕ ОБНАРУЖЕНЫ`. В противном случае на листинг выдаются:

* сообщения об ошибках: `НЕВЕРНЫЙ КЛЮЧ`, `ССЫЛКА ВВЕРХ`, `ДВАЖДЫ ЗАНЯТ`,
  `НЕСУЩЕСТВУЮЩАЯ ЗОНА`.
* схема всего каталога областей с указанием потерянных квантов каталога.

#### 8.6.8. Система статистики `СТARFA`

##### 8.6.8.1. Общее описание

Описываемая система предназначена для получения в диалоговом режиме
справочных сведений о файлах — областях архивно-файловой системы "ARFA" ОС
Диспак. Требуемые пользователем сведения берутся из записей каталога
системы "ARFA". Возможен выбор файлов по конкретным значениям некоторых
параметров или по принадлежности их некоторому диапазону.

Возможно также упорядочить получаемый список по одному из параметров по
невозрастанию (или по алфавиту, когда этот параметр — имя области).

Параметры, с которыми может работать система, перечислены ниже. Необходимо
отметить, что доступ к значениям некоторых из них может иметь только
администратор архивной системы, а к другой группе — только хозяин области.

При входе в систему пользователю задается вопрос `ШИФР-`, в ответ на
который пользователь должен задать шифр бюджета, администратором которого
он является. Затем пользователю задается вопрос `ПАРОЛЬ-`, в ответ на
который пользователь в секретном режиме должен задать ключ администратора.
Если пользователь не является администратором бюджета, то на запрос
`ШИФР-` надо ответить пустой посылкой.

Список параметров:

| Параметр | Значение |
|----------|----------|
| `ИМЯ` | Имя области, простое или составное; |
| `ХОЗ` | Шифр хозяина области, а именно первые шесть цифр шифра; |
| `ТИП` | Тип области в смысле архивной системы, т. е. две цифры, первая — группа от 0 до 3, вторая — вид области от 0 до 4; |
| `ДЛИ` | Длина области в зонах, восьмеричная, не более 7777. |
| `ЗОН` | Начальная зона области, восьмеричная, не более 7777. Параметр доступен только администратору архива. |
| `ШФБ` | Шифр бюджета, из которого область была создана; |
| `ДСО` | Дата создания области; |
| `ДЗП` | Дата последней записи в область; |
| `ДЧТ` | Дата последнего чтения из области; |
| `КОЛ` | Количество обращений, т. е. количество выданных экстракодов обмена к данной области; |
| `БОБ` | Номер бобины, на которой область расположена. Доступен только администратору архива. |
| `БВТ` | Номер вторичного тома, на котором расположена область. Параметр доступен только администратору архива. |
| `ДРУ` | У каждой области может быть до 6 шифров-"друзей", под которыми, кроме хозяина, возможен к ней доступ. У каждого "друга" имеются отдельные права на доступ. Они могут быть: `ЧТ` — только чтение, `Ч/З` — чтение и запись, `ЗАХ` — захват области в монопольное использование; |
| `ПРО` | Права (см. выше) пользователей, не включенных в список "друзей" (прочих); |
| `ЧАС` | Частота обращений к одной зоне области. Производная величина, равна количеству обращений, деленному на длину области; |
| `ТДЛ` | Текущая длина, т. е. номер последней занятой зоны. Всегда меньше длины `ДЛИ`; |
| `ШЗП` | Шифр, под которым была произведена последняя запись в файл. Хранится и выдается только первые шесть цифр шифра; |
| `ВЗП` | Время суток последней записи в область. Хранится с точностью до нескольких минут; |
| `ПЧТ`, `ПЗП` | Наличие паролей на чтение и на запись соответственно. Выдается, есть пароль или его нет. |
| `ЗКТ` | Номер зоны каталога на основном МД архива, в которой хранится запись о данной области. Восьмеричный, от 0 до максимального номера зоны на диске. Этот параметр доступен только администратору архива. |
| `ГДЕ` | Адрес, с которого в зоне каталога (см. `ЗКТ`) начинается запись о данной области. Восьмеричный, от 30 до 1761. Параметр доступен только администратору архива. |

На каждый из описанных выше параметров возможна установка. Устанавливать
можно конкретное значение или некоторое множество допустимых значений. В
соответствии с установками и будут отбираться области, о которых будет
выдаваться информация.

Выдача информации производится в виде таблицы на экран терминала и/или на
АЦПУ. В строке этой таблицы — информация об одной области, в столбце — по
одному конкретному параметру.

##### 8.6.8.2. Описание приказов

Все имена приказов, установок и параметров различаются по первым трем
символам. Исключение составляют параметры приказов `ПЕЧ`, `ЭКР`, `ИНК`,
`СТР`, `БЛД`. Они различаются по одному первому символу.

##### 8.6.8.2.1. Приказ `УСТАНОВИ`

Приказ служит для задания требуемых установок на области и некоторых
параметров системы. Форма обращения:

```
УСТ <УСТАНОВКА>,...
```

где

```
<УСТАНОВКА>::= <ИМЯПАР>=                          (1),
               <ИМЯПАР><ЗНАК><ЗНАЧЕНИЕ>           (2),
               <ИМЯПАР><ЗНАК><НАЧЗНАЧ>-<КОНЗНАЧ>  (3),
```

а `<ЗНАК>` — это "=" или "<>", т. е. всегда возможна установка не только на
равенство, но и на неравенство определенному значению (2) или на
принадлежность или непринадлежность некоторому диапазону (3). Форма (1)
служит для сброса, т. е. отмены установки на данный параметр.

Если задано несколько установок, то подходящей считается область,
удовлетворяющая всем установкам одновременно.

Имена установок, отмеченные звездочкой, доступны только администратору.
Если установки на эти параметры будет задавать обычный пользователь, то он
получит диагностику `НЕ ИМЕЕТЕ ПРАВА`.

Именем установки может быть:

`ИМЯ` — установка на имя области. Возможно задание трех форм установки,
отличающихся способом сравнения с именем области архива:

```
ИМЯ<ЗНАК><ОДНОИМЯ> (1),
ИМЯ<ЗНАК><ОДНОИМЯ1><ТОЧКА><ОДНОИМЯ2>..<ТОЧКА><ОДНОИМЯN>(2),
ИМЯ<ЗНАК><ОДНОИМЯ1><ТОЧКА>..<ТОЧКА><ОДНОИМЯN><ТОЧКА> (3)
ГДЕ <ТОЧКА>::= .       ;
```

Число N простых имен в установке не больше 7.

В случае (1) `<ОДНОИМЯ>` из установки сравнивается со всеми простыми
именами областей на всех уровнях. Область считается подходящей, если
последнее (или единственное) ее простое имя "совпадает" (см. ниже) с
`<ОДНОИМЯ>`.

В случае (2) область подходит, если число простых имен в ее составном имени
точно равно N и каждое из них "совпадает" с соответствующим именем
`<ОДНОИМЯК>` из установки.

В случае (3) область подходит, если первые N ее простых имен "совпадают" с
именами `<ОДНОИМЯ1>` — `<ОДНОИМЯN>` из установки.

Опишем синтаксис `<ОДНОИМЯ>` и понятие "совпадать".

```
<ОДНОИМЯ> ::= *                                  (1),
              <СИМВОЛ ИЛИ СКИП>... ДО 9 СИМВОЛОВ (2) .
```

В случае (2) для "совпадения" `<ОДНОИМЕНИ>` и простого имени из составного
имени области каждый символ `<ОДНОИМЕНИ>` должен либо совпасть с
соответствующим ему по номеру символом простого имени, либо оказаться
скипом. Таким образом, скип — литера, совпадающая с любой в сопоставляемом
имени. Первоначальное значение скипа — точка, но оно может (и должно, т. к.
точка — разделитель простых имен в составном) быть заменено на другое
соответствующей установкой приказа `УСТ`.

Случай (2) эквивалентен `<ОДНОИМЕНИ>` из 9 скипов.

Примечание: для того, чтобы работал просмотр составных имен, нужно включить
его приказом `СТР ДА` (см. ниже).

`ХОЗ` — установка на шифр хозяина области. Возможно задание до 6 цифр шифра
или скипов. Если число цифр меньше шести, то шифр дополняется скипами
справа.

`ТИП` — установка на тип области, т. е. на группу и вид. Если выборка по
группе или по виду не нужна, то на соответствующее место нужно поставить
скип. Например: `УСТ ТИП=0.` (только на нулевую группу).

`ДЛИ` — установка на длину области в зонах. Установка задается в
восьмеричном виде. Можно задать конкретное значение или диапазон длин.

`ЗОН` (\*) — установка на начальную зону области. Можно задать одно значение
или интервал. Если область имеет приписку, то она считается неподходящей
при любой заданной установке на зону.

`ШФБ` — установка на шифр бюджета, из которого была создана область.
Задается аналогично `ХОЗ`.

`ДСО`, `ДЗП`, `ДЧТ` — установки на даты создания, последней записи и
последнего чтения из области соответственно. Задаются (и выводятся) в виде:
`ДД.ММ.8Г`, т. е. год всегда должен быть 80-м. Возможны установки на
конкретную дату или на интервал дат.

Если в данную область ни разу не записывали с момента ее создания, то она
считается неподходящей при любой заданной установке на дату записи, включая
случай, когда установка задана на неравенство. Аналогично если задана
установка на дату чтения, то неподходящей считается любая область, из
которой ни разу не читали.

`КОЛ` — установка на число выданных экстракодов обмена к данной области.
Задается целым десятичным числом или интервалом.

`БОБ` (\*) — установка на номер бобины МЛ или МД, на котором находится
область. Можно задать одну бобину или интервал номеров бобин.

`ДРУ` — установка на шифр одного из друзей. Считается, что область
подходит, если шифр хотя бы одного из друзей "сравнивается" с шифром,
заданным в установке. Способ сравнения здесь несколько отличается от того,
которым сравниваются установки `ХОЗ` и `ШФБ`. Там скип в шифре установки
заменял любую цифру в соответствующем параметре области, но не наоборот. В
установке `ДРУ` установленный шифр и действительный шифр в этом смысле
полностью равноправны, скип в установке заменяет скип в шифре "друга", и
скип в шифре "друга" заменяет скип в установке.

`ЧАС` — установка на частоту обращений к одной зоне области. Задается целым
десятичным числом или их интервалом.

`ТДЛ` — установка на текущую длину области. В восьмеричном виде можно
задать конкретное значение или диапазон значений.

`ШЗП` — установка на шифр, под которым была произведена последняя запись в
область. Аналогично `ХОЗ` и `ШФБ`.

`ВЗП` — установка на время суток, в которое была последняя запись в данную
область. Ее значение имеет вид: `ЧЧ[<РАЗД>ММ][-ЧЧ[<РАЗД>ММ]]`, т. е. можно
задать конкретное время или интервал, и при задании времени минуты можно
опускать, в этом случае значение минут полагается равным нулю. Упомянутый
`<РАЗД>` — разделитель, он может быть двоеточием или точкой. Если задана
установка на время записи, а в данную область с момента ее создания ни
одной записи не было, то область всегда считается неподходящей. При задании
установки следует помнить, что время записи хранится с точностью до
нескольких минут.

`ПЧТ`, `ПЗП` — установки на наличие или отсутствие паролей на чтение или на
запись соответственно. Значением этих установок могут быть только `ЕСТЬ`
или `НЕТ`.

`ЗКТ` (\*) — установка на зону каталога. В восьмеричном виде, не более
7777. Может быть числом или интервалом.

`ГДЕ` (\*) — установка на расположение записи. Можно задать восьмеричное
число (имеет смысл только до 1777) или диапазон.

`СТР` — установка на наличие структурированности, т. е. на наличие
подобластей у данной области-каталога. Значение этой установки — как в
установках `ПЧТ` и `ПЗП`.

`СБР` — предписывает сбросить все имеющиеся установки кроме тех, что стоят
в приказе `УСТ` справа от данной установки.

`ПОК` — предписывает показать все установки, имеющиеся к данному моменту.

`СКИ` — изменяет значение скипа. Форма обращения к этой установке:

```
УСТ ...,СКИ=<НОВЫЙ СКИП>,...
```

`<НОВЫЙ СКИП>` не должен быть пробелом, запятой, слэшем.

При ошибке в одной из установок приказа `УСТ` или при задании
несуществующей установки выдается соответствующая диагностика, приказ не
выполняется, и ни одна из заданных ранее установок не изменяется.

##### 8.6.8.2.2. Приказ `СБРОС`

Приказ служит для сброса всех текущих установок и не имеет параметров.
Форма обращения:

```
СБР
```

##### 8.6.8.2.3. Приказ `ПОКАЖИ`

Этот приказ предназначен для показа значений установок, заданных к текущему
моменту. Форма обращения:

```
ПОК
```

##### 8.6.8.2.4.1. Приказ `СТАТИСТИКА`

Этот приказ — основной в системе. По нему и производится выдача на экран
терминала и/или на печать интересующей информации. Данные об областях
выводятся в виде таблицы, по строкам которой расположены области, а по
столбцам — затребованные в приказе параметры, по которым выдается
информация.

Форма обращения:

```
СТА [<ПАРАМЕТР>,...][/<ВРЕМЕННАЯ УСТАНОВКА>,...]
```

где `<ПАРАМЕТРЫ>` будут описаны ниже, а `<ВРЕМЕННЫЕ УСТАНОВКИ>` — те же,
что и в приказе `УСТ`, только они устанавливаются лишь на время выполнения
данного приказа, а после окончания — сбрасываются.

`<ПАРАМЕТРЫ>` задают, какие именно данные об областях нужно получить. В
выводимой таблице столбцы располагаются в том же порядке, что и параметры в
приказе. Перед таблицей выводится заголовок.

Параметры, отмеченные звездочкой, доступны только администратору. Если эти
параметры будет задавать обычный пользователь, то он получит диагностику
`НЕ ИМЕЕТЕ ПРАВА`.

`<ПАРАМЕТРЫ>` могут быть:

| Параметр | Значение |
|----------|----------|
| `ИМЯ` | Имя области, простое или составное; если имя составное, то оно выводится в несколько строчек. Кроме того, принят принцип максимальной экономии бумаги, если подряд выводятся сведения о нескольких областях с одинаковыми первыми простыми именами, то такие имена "факторизуются". |
| `ХОЗ` | Шифр хозяина области, а именно первые шесть цифр шифра; |
| `ТИП` | Тип области в смысле архивной системы, т. е. две цифры, первая — группа от 0 до 3, вторая — вид области от 0 до 4; |
| `ДЛИ` | Длина области в зонах, восьмеричная, не более 777. Если область имеет тип каталога, то в этой графе ставится "КАТ". |
| (\*) `ЗОН` | Начальная зона области, восьмеричная, не более 7777. Если область имеет тип каталога, то в этой графе ставится "КАТ". Если область имеет приписку, то справа от номера зоны приписки ставится буква "П". |
| `ШФБ` | Шифр бюджета, из которого область была создана; |
| `ДСО` | Дата создания области; |
| `ДЗП` | Дата последней записи в область; если ни одной записи в данную область с момента ее создания не было, то в этой графе ставится "НЕТ". |
| `ДЧТ` | Дата последнего чтения из области; если ни одного чтения в область с момента ее создания не было, то в этой графе ставится "НЕТ". |
| `КОЛ` | Количество обращений, т. е. количество выданных экстракодов обмена к данной области; выводится в виде десятичного целого числа. |
| (\*) `БОБ` | Номер бобины, на которой область расположена; |
| `ДРУ` | "Друзья" области. У каждого "друга" имеются отдельные права на доступ. Они могут быть: `ЧТ` — только чтение, `Ч/З` — чтение и запись, `ЗАХ` — захват области в монопольное использование; |
| `ПРО` | Права (см. выше) пользователей, не включенных в список "друзей" (прочих); |
| `ЧАС` | Частота обращений к одной зоне области. |
| `ТДЛ` | Текущая длина, или номер последней занятой зоны. Выдается в восьмеричном виде. Если область — каталог, то эта графа оставляется пустой. |
| `ШЗП` | Шифр, под которым была произведена последняя запись в файл. Хранится и выдается только первые шесть цифр шифра; если область — каталог или если записей в область не было с момента ее создания, то эта графа оставляется пустой. |
| `ВЗП` | Время суток последней записи в область. Выдается в виде ЧЧ:ММ с точностью до минут. Если область — каталог или если записей в область не было с момента ее создания, то эта графа оставляется пустой. |
| `ПЧТ`, `ПЗП` | Наличие паролей на чтение и на запись соответственно. Выдается, есть пароль или его нет. |
| (\*) `ЗКТ` | Зона каталога. |
| (\*) `ГДЕ` | Адрес записи об области в зоне. |

Для упрощения работы с системой введены три фиктивных параметра:

| Параметр | Значение |
|----------|----------|
| `ОДИ` | Первый стандартный набор параметров, включает ИМЯ, ХОЗ, ТИП, ДЛИ, ЗОН, ШФБ, ДСО, БОБ. Этот набор параметров устанавливается также когда все параметры опущены. |
| `ВСЕ` | Еще один стандартный набор. Несмотря на его звание, он включает лишь ИМЯ, ХОЗ, ТИП, ДЛИ, ЗОН, ШФБ, ДСО, ДЗП, ДЧТ, КОЛ, БОБ, ДРУ, ЧАС для администратора и ИМЯ, ХОЗ, ТИП, ДЛИ, ТДЛ, ШФБ, ДСО, ДЗП, ДЧТ, КОЛ, ШЗП, ДРУ, ЧАС для обычного пользователя. Он предназначен для печати на АЦПУ-128 и вывод его на терминал при включенной проверке строки на длину (см. приказ `БЛДЛИН`) невозможен. Если включен просмотр и вывод составных имен (`СТР ДА`), то последний параметр — `ЧАС` опускается. |
| (\*) `СИС` | Стандартный набор для администратора. Включает ИМЯ, ХОЗ, ТИП, БОБ, ЗОН, ДЛИ, ЗКТ, ГДЕ. Естественно, доступен лишь администратору. |

При задании параметров к этим стандартным наборам можно добавлять другие
параметры. При этом параметры приказа будут располагаться в выводной строке
именно в том порядке, в каком они были в строке приказа. Например:

`СТА ОДИ,ПЧТ,ПЗП` — к набору `ОДИ` будут добавлены параметры `ПЧТ` и `ПЗП`.

Кроме этого, существуют еще два полезных "параметра". Это `ЗАП` и `СБР`.
Употребление `ЗАП` среди параметров приказа предписывает запомнить
параметры, и следующий приказ `СТА` (или `СТП`, см. ниже), если у него все
параметры будут опущены, будет выполнен с данными запомненными. Если же у
другого приказа будут параметры, то они добавятся к запомненному списку.
`СБР` отменяет режим запоминания параметров и опустошает запомненный
список.

В этом приказе вывод информации на терминал производится порциями, вначале
по 14 строк, затем это значение шага может быть изменено приказом `ШАГ`
(см. ниже). После вывода очередной порции производится выход на прием с
терминала с приглашением `ИДТИ-`. Если на это приглашение ответить `Н`, то
просмотр каталога областей будет прекращен, любой другой ответ вызовет
продолжение исполнения приказа.

Выдача на АЦПУ приглашением `ИДТИ-` не прерывается.

##### 8.6.8.2.4.2. Приказ `СТП`

Этот приказ аналогичен приказу `СТА`, но выводит таблицу областей,
упорядоченную по первому параметру приказа. Если этот параметр и
единственный, то добавляются параметры из набора `ОДИ` (см. выше), причем
если набор включает первый параметр, то лишнее вхождение удаляется. Также,
если параметры заданы явно, то первый параметр вычеркивается из списка
остальных.

Упорядочивать можно по всем параметрам, кроме `ПЧТ`, `ПЗП`, `ДРУ`
(бессмысленно), `ЗКТ`, `ГДЕ`. Кроме остальных параметров, есть еще `СВО` —
упорядочивание по бобине и по зоне вместе. `СВО` доступно лишь
администратору архива.

##### 8.6.8.2.5. Приказ `ПЕЧАТЬ`

Этот приказ включает и выключает печать на АЦПУ. После его исполнения на
АЦПУ печатается вводимая пользователем строка и ответы системы на нее, т. е.
точная копия диалога на экране. Кроме того, при включении печати
производится отказ от режима ’инкогнито’, если он был.

Форма обращения:

```
ПЕЧ [<ПАРАМЕТР>]
```

`<ПАРАМЕТР>` приказа может быть `ДА` либо `НЕТ`, что соответственно
означает включение или выключение печати. Если `<ПАРАМЕТР>` опущен, то
печать включается, если она была выключена, и выключается, если была
включена.

##### 8.6.8.2.6. Приказ `ЭКРАН`

Этот приказ включает и выключает вывод таблицы, получаемой по приказу
`СТА`, на экран терминала. На все остальные ответы системы приказ `ЭКР` не
влияет.

Форма обращения:

```
ЭКР [<ПАРАМЕТР>]
```

Смысл `<ПАРАМЕТРА>` тот же, что и в приказе `ПЕЧ`.

##### 8.6.8.2.7. Приказ `ИНКОГНИТО`

Этот приказ предназначен для управления режимом ’инкогнито’, с которым
решается задача.

Форма обращения:

```
ИНК [<ПАРАМЕТР>]
```

Если `<ПАРАМЕТР>` — `НЕТ`, то производится отказ от инкогнито, любое другое
значение параметра, включая и его отсутствие, означает захват инкогнито.

##### 8.6.8.2.8. Приказ `ПРОПУСТИТЬ`

По этому приказу уничтожается текущее содержимое буфера вывода задачи.
Форма обращения:

```
ПРО
```

##### 8.6.8.2.9. Приказ `АЦПУ`

Этот приказ предназначен для немедленной разгрузки буфера вывода задачи,
т. е. действительной печати накопленной выдачи. Если задача решается в
режиме инкогнито, то этот приказ эквивалентен приказу `ПРО`.

Форма обращения:

```
АЦП
```

##### 8.6.8.2.10. Приказ `СТРУКТУРА`

Этот приказ разрешает и запрещает просмотр подфайлов в структурированных
областях, имеющих составное имя. Форма обращения:

```
СТР [<ПАРАМЕТР>]
```

Смысл `<ПАРАМЕТРА>` тот же, что в приказах `ПЕЧ` и `ЭКР`.

##### 8.6.8.2.11. Приказ `БЛДЛИН`

При выводе строки таблицы в приказе `СТА` она обычно проверяется на длину.
Когда включен вывод на терминал, то длина выводимой строки должна быть не
более 79 символов, при выводе только на АЦПУ — не более 127 символов.
Данный приказ позволяет выключить эту проверку. Форма обращения:

```
БЛД [<ПАРАМЕТР>]
```

`<ПАРАМЕТР>` то же, что в приказах `ПЕЧ`, `ЭКР` и `СТР`.

##### 8.6.8.2.12. Приказ `ШАГ`

Этот приказ изменяет шаг выдачи строк на терминал (см. описание приказа
`СТА`). Форма обращения:

```
ШАГ [<НОВШАГ>]
```

Если `<НОВШАГ>` отсутствует, то выдается текущее значение шага.
Первоначальное значение шага — 14. Если установить шаг, равный нулю, то
выдача приглашением `ИДТИ-` прерываться не будет.

##### 8.6.8.2.13. Приказ `АДМ`

Этот приказ служит для перехода в режим администратора. Форма обращения:

```
АДМ
```

Производится в секретном режиме прием пароля администратора в смысле
системы "ARFA".

##### 8.6.8.2.14. Приказ `КОНЕЦ`

Этот приказ оканчивает работу с системой. Кроме того, захватывается режим
инкогнито, если печать на АЦПУ не включалась ни разу. Форма обращения:

```
КОН
```

### 8.7. Экстракоды обращения к архивной системе

#### 8.7.1. Общее описание

##### 8.7.1.1. Структура информационных слов

Все экстракоды обращения к архивной системе имеют следующий вид:

```
Э63 АИСП
```

где АИСП — адрес нулевого информационного слова. Перед исполнением
экстракода на сумматоре должна находиться константа `’КЛЮЧАР’` в коде УПП.
В ряде случаев информация к экстракоду задается также и на регистре младших
разрядов.

Стандартная структура информационных слов.

Слово по исполнительному адресу (ИС):

```
48-43Р - ТИП РАБОТЫ
42-37Р - ВИРТУАЛЬНЫЙ НОМЕР
36-25Р - ПАРОЛЬ
   12Р - ПРИЗНАК ЧТЕНИЯ
 4- 1Р - ХАРАКТЕРИСТИКА ИМЕНИ
```

Существуют следующие четыре способа задания имени.

**1 способ:**

```
  4 Р - " 0 "
3-1 Р - ЧИСЛО УРОВНЕЙ В ИМЕНИ
```

Тогда:

```
СЛОВО  ИС+1  - ПЕРВЫЕ ШЕСТЬ СИМВОЛОВ ПЕРВОГО ПРОСТОГО
               ИМЕНИ.
СЛОВО  ИС+2 :
      48-25Р - СЕДЬМОЙ-ДЕВЯТЫЙ СИМВОЛЫ ПЕРВОГО ПРОСТОГО
               ИМЕНИ
      24- 1Р - ШИФР ХОЗЯИНА ОБЛАСТИ ИЛИ 0.
```

Слова ИС+3 и т. д. — последующие простые имена, записываемые по тем же
правилам, что и первое (за исключением разрядов для шифра хозяина области,
где должны стоять нули).

**2 способ:**

```
  4 Р - " 1 "
3-1 Р - " 0 "
```

Тогда слова ИС, ИС+1, ИС+2 ... и т. д. имеют следующий вид:
`ИМЯ1.ИМЯ2.ИМЯ3..../<ШИФР ХОЗЯИНА>`, т. е. имя располагается
последовательно в ячейках ИС, ИС+1 и т. д. в коде УПП. При этом символ с
кодом `’143’` считается пустым символом.

**3 способ:**

```
4-1 Р - ВСЕ " 1 "
```

Тогда имя задается в коде ISO. Простые имена дополняются до девяти символов
пробелами справа.

**4 способ:**

Вместо имени в ИС+1 может быть задан идентификатор области (в этом случае
4-1Р ИС должны быть равны нулю).

Структура идентификатора области:

```
   34Р = 1
33-18Р - ВНУТРЕННЕЕ ИМЯ ОБЛАСТИ
   17Р = 0
16-10Р - ПРОДОЛЖЕНИЕ ВНУТРЕННЕГО ИМЕНИ ОБЛАСТИ
 9- 1Р = ’356’(8).
```

При этом слово ИС+2 должно принадлежать памяти задачи. Если 34-й разряд
равен нулю, или 17-й разряд равен единице, или отсутствует ключ в 9-1-м
разрядах, то выдается диагностика `НЕВЕРНОЕ ИМЯ ОБЛ.`; та же диагностика
выдается при задании неверного внутреннего имени. Внутреннее имя может быть
получено с помощью экстракода `Э50 ’105’` или экстракода запроса имени
области.

Экстракоды, работающие с областью как по имени, так и по виртуальному
номеру, должны содержать ноль либо в 42-37-м, либо в 4-1-м разрядах (если
и виртуальный номер, и характеристика имени равны нулю, то это трактуется
как задание имени четвертым способом).

В ряде экстракодов информация выдается также на сумматор и в память задачи.

За исключением специально оговоренных случаев содержимое сумматора,
регистра младших разрядов и установленная группа операций после выполнения
экстракодов обращения к архиву не определены.

##### 8.7.1.2. Авостные ситуации

1. `ИНФ.СЛ.В ЧУЖ.ЛИС` — слово по исполнительному адресу экстракода (или одно

   информационных слов отличны от нуля.

#### 8.7.3. Экстракоды, работающие с номерами томов

Ряд экстракодов в качестве информации для работы используют шифр тома в
двоично-десятичном виде. Это экстракоды типа:

* `Э50 ’131’` — дозаказ тома;
* `Э50 ’115’` — захват тома;
* и др.

Этими экстракодами можно воспользоваться и для работы с областями, но номер
тома в двоично-десятичном виде заменяется на идентификатор области,
называемый ссылкой на область и описанный в 8.7.1.1.

Эту ссылку на область можно получить с помощью двух экстракодов.

1) С помощью экстракода `Э50 ’105’`, если на в.н. уже заказана область.

   Пример: в паспорте задачи мы вставили следующий раздел
   `ЛЕН 43(ВАСЯ.МАЛЬЧИК/4199..)‾`, тогда после выполнения экстракода
   `Э50 ’105’` с сумматором, равным `’430000’`, мы получим ссылку на область
   `ВАСЯ.МАЛЬЧИК` с хозяином `4199..`.

2) Способ: с помощью экстракода запроса ссылки по имени, если область не
   заказана в задаче. Этот экстракод описан в 8.7.2.11.

#### 8.7.4. Экстракоды, работающие с виртуальными номерами

Основная группа экстракодов по виртуальным номерам работает точно так же,
как в случае, если на виртуальный номер заказан диск.

## 9. Служебные экстракоды

### 9.1. Выдача сообщения об установке тома МЛ(МД)

`ИР 050 А`, где АИСП = 1206(8).

Экстракод предназначен для выдачи на операторский терминал сообщения:

```

```

где ХХХХ — номер тома МЛ(МД), который необходимо установить; N — номер

Перед выполнением экстракода на СМ в 1-16 Р заносится номер тома в
двоично-десятичном виде, на индекс-регистр 3 код 71717.

номер в восьмеричном виде и выдачи на терминал не последует. Если же том не
установлен, то СМ=0 и на операторский терминал производится выдача запроса
об установке тома.

## 10. Бюджетная система ОС Диспак

### 10.1. Общие сведения

Бюджетная система является одним из средств управления прохождением задач
в ОС. Она дает возможность:

* автоматизировать процесс учета и контроля использования ресурсов времени
  и бумаги;
* воздействовать на порядок включения задач в решение;

Рассмотрим кратко две вышеуказанные функции бюджетной системы.

#### 10.1.1. Бюджетирование ресурсов бумаги и времени

Все пользователи вычислительной системы подразделяются бюджетной системой
на отделы. Принадлежность к отделу определяется по любым двум подряд идущим
цифрам шифра (чаще всего две первые цифры). Какие именно две цифры,
устанавливает организация — владелец ЭВМ, внося через сервис БС маску,
которая накладывается на шифр на этапе ввода задач в ЭВМ. Отделу с помощью
сервиса БС выделяется бюджет времени и бумаги. Ресурсы времени
подразделяются на три категории:

* экспрессное;
* лимитное;
* дежурное.

#### 10.1.2. Включение задач в решение

Экспрессное время выделяется задачам, шифры которых находятся в специальном
каталоге БС. Категория времени определяет срочность решения задач. Задачи с
экспрессным временем являются наиболее приоритетными при включении их в
решение. Экспрессные и дежурные задачи определяются по маске и признакам, с
помощью которых выделяются определенные цифры шифра. Пример маски:
`ХХ0000ХХ`. Это означает, что признак экспрессности/дежурности размещается в
7-8 позициях. Пример признака: `45`. Это означает, что задача, шифр которой
имеет "45" в позициях, определенных маской, будет отнесена к категории
экспрессных/дежурных. Каждый отдел может иметь несколько экспрессных
признаков, а дежурный признак устанавливается единым для всех шифров.
Дежурные задачи являются наименее приоритетными. При прохождении задачи
время ее решения вычитается из ресурса экспрессного, лимитного или
дежурного времени в зависимости от принадлежности задачи к одной из трех
категорий. В рамках БС могут существовать так называемые "замороженные"
задачи. Если шифр задачи принадлежит каталогу "замороженных" шифров, то
задача не будет выбираться в решение, пока ее не "разморозят" с помощью
сервиса БС. Для лимитных и дежурных задач устанавливается время, после
которого они могут выбираться в решение.

### 10.2. Сервис бюджетной системы

Сервис бюджета представляет собой диалоговую программу, вызываемую по
ключу. Программа имеет два входа — диспетчерский и системный. Под
диспетчерским входом работает диспетчер. Он по мере надобности
просматривает картину расходования ресурсов отделов, корректирует эти
ресурсы, устанавливает время ввода задач различных категорий, отключает
некоторые отделы от бюджетной системы или снова их включает и т. д. Все
возможности можно посмотреть в инструкции диспетчеру (п. 10.2.4).

Под системным входом работает системный программист, который ведет
подготовку для работы с бюджетной системой, в последующем меняет пароли и
местоположение каталогов, выполняет ряд дополнительных действий
(п. 10.2.3).

#### 10.2.1. Общие правила при работе с программой

После вызова программы на вопрос `КТО` нужно ответить либо `СИС` (режим
системного программиста), либо `ДИС` (режим диспетчера). После этого
необходимо подтвердить соответствующие пароли, выйти на вопрос `ЧТО` и
начинать работу. `А.` на любое приглашение — включение/выключение
параллельной печати протокола, `V.` — отмена/установка выдачи на терминал,
`КНЦ` в ответ на любое приглашение — окончание работы. Директивы `НОВ`,
`ИСХ` и `ТЕК` в ответ на `ЧТО` означают настройку на нужный каталог
(п. 10.2.2). Для работы программы необходимо завести следующий стандартный
паспорт:

```
ОЗУ 27‾
ВХО 6000‾
ВРЕ 100‾
РОС 0‾
ТЕЛ‾
ИНК‾
ЛЕН 43(NNNN -ЗП)‾
БЛО‾
Е
В 6000
К 00 070 6003
К 00 010 6003
К 00 30 00001
С 0010 0000 0043 ZZZZ
ЕКОНЕЦ
```

где `ZZZZ` — номер зоны, а `NNNN` — МД или область, на котором находится
готовая программа, занимающая 3 зоны.

Нужно также завести ключ, по которому программа будет вызываться.

#### 10.2.2. Подготовка и настройка зон каталогов

Сервис бюджетной системы работает с "текущим", "новым" и "исходным"
каталогами, а также с дублем "исходного" каталога. С "текущим" каталогом
(710 зона системного МД) работает ОС. Остальные каталоги располагаются в
произвольном месте.

Если бюджетная система включается в ОС впервые, то необходимо переписать
зону текущего каталога, которая поставляется вместе с готовой программой
сервиса бюджета. Далее надо обнулить зоны для "исходного", "нового"
каталогов, дубля "исходного" каталога. Затем, вызвав программу по ключу,
надо войти в системный вход и настроить зоны каталогов. В случае ошибки
нужно выполнить директиву `НАЧ`. Диалог имеет следующий вид:

```
КТО         СИС
ПРОТОКОЛ    ДА
            ПУСТАЯ ПОСЫЛКА
            НЕТ
```

При одном из первых двух ответов идет выдача на АЦПУ.

```
ПАР1        ПАРОЛЬ,КОТОРЫЙ БУДЕТ ПОДТВЕРЖДАТЬСЯ
            ПРИ СИСТЕМНОМ ВХОДЕ
ПАР1        ПАРОЛЬ,КОТОРЫЙ БУДЕТ ПОДТВЕРЖДАТЬСЯ
            ПРИ ДИСПЕТЧЕРСКОМ ВХОДЕ
```

```
ЗОНА        НОМЕР ЗОНЫ ИСХОДНОГО КАТАЛОГА
ПАРЗП       ПАРОЛЬ НА ЗАПИСЬ
ПАРЧТ       ПАРОЛЬ НА ЧТЕНИЕ
МDНОВ       НОМЕР МД С НОВЫМ КАТАЛОГОМ

ПАРЧТ       ПАРОЛЬ НА ЧТЕНИЕ
МDДУБ       НОМЕР МД С ДУБЛЕМ ИСХОДНОГО КАТАЛОГА
ЗОНА        НОМЕР ЗОНЫ ДУБЛЯ ИСХОДНОГО КАТАЛОГА
```

При отсутствии паролей ответом служит пустая посылка. В случае размещения

```
МDИСХ       ИМЯ ОБЛАСТИ ИСХОДНОГО КАТАЛОГА
ХОЗЯИН      ХОЗЯИН ОБЛАСТИ ИСХОДНОГО КАТАЛОГА
```


На терминал выдаются внесенные параметры.

```

            ПУСТАЯ ПОСЫЛКА
            НЕТ (Н)
```

программиста (`ПАР1`) и нужно начинать работу по вводу в каталоги ресурсов
(п. 10.2.4.7 и п. 10.2.4.8).

Для системного входа необходимо на `КТО` ответить `СИС` и подтвердить
пароль системного программиста. Под системным входом можно проводить
следующую работу:

1\) Смена паролей или номера зон каталогов, безбюджетного шифра:

```
ЧТО       ГЕН
ПАР1      НОВЫЙ ПАРОЛЬ ДЛЯ СИСТЕМНОГО ВХОДА
ПАР2      НОВЫЙ ПАРОЛЬ ДЛЯ ДИСПЕТЧЕРСКОГО ВХОДА
ОСТАЛЬНОЕ ДА (Д)
МЕНЯЕМ    ПУСТАЯ ПОСЫЛКА
          НЕТ (Н)
```

При ответе "нет" следует вопрос `ЗАПИСАТЬ ->`. При ответе "да" следует
запрос о новом местоположении каталогов, в обоих случаях дальнейшая работа
идет как при настройке зон каталогов (п. 10.2.2).

2\) Установка некоторых режимов работы.

Каждый режим маркируется наличием/отсутствием определенного разряда в
некоторой ячейке, поэтому режимы устанавливаются следующим образом:

```
ЧТО    РЕЖ
 -     ЕХХ=1
 -     ЕХХ=0
```

Здесь `ХХ` — вид режима и, соответственно, номер разряда в указанной
ячейке. Имеются следующие режимы:

| Режим      | Значение |
|------------|----------|
| `Е 47 = 1` | Запрещен перевод из лимитных в дежурные. |
| `Е 46 = 1` | Запрещен перевод из экспрессных в лимитные. |
| `Е 43 = 1` | Проверять допустимость интервала ввода. |
| `Е 28 = 1` | Выдавать ошибку ввода для задач, вводимых вне |
| `Е 27 = 1` | Выброс задач в случае `НБЮД`. |

3\) Исправление каталогов.

Под системным входом директива `КОР` правит только каталог лимитов — `ТЕК`
или `ИСХ`. Это нужно, например, при ошибке МД в зоне исходного каталога
или, если переход на новый бюджет осуществлялся при наличии нескольких
задач в решении.

В случае ОШМД может получиться такая ситуация, что откорректированные
ресурсы запишутся в текущий каталог, а в исходный не успеют записаться.
Возникает необходимость подправить только исходный каталог.

В случае перехода на новый бюджет при наличии нескольких задач в решении
тоже возникает несоответствие ресурсов исходного и текущего каталогов, так
как после окончания счета этих задач будут возвращены неизрасходованные
ресурсы. В таком случае нужно править текущий каталог — изъять эти ресурсы.

```
ЧТО         КОР
ОТДЕЛ       NN
            NN1 -NN2
            ПУСТАЯ ПОСЫЛКА
```

Программа запрашивает, какой каталог править — `ТЕК` или `ИСХ`. Запись в
указанный каталог производится без вопроса `ЗАПИСАТЬ`.

```
ТЕКУЩИЙ ИЛИ    ТЕК            ЗАПИСЬ В ТЕКУЩИЙ КАТАЛОГ
ИСХОДНЫЙ       ИСХ            АНАЛОГИЧНО
               ПУСТАЯ ПОСЫЛКА НЕ ЗАПИСЫВАТЬ
```

При работе с каждой директивой на терминал выдается номер зоны и номер МД,
с которыми эта директива работает, т. е. сообщается местоположение
каталогов.

4\) Восстановление каталогов.

Текущий каталог ресурсов восстанавливается из области статистики с зоны
1433, в который он дублируется в процессе работы программы СБОР-80.

Исходный каталог имеет дубль, зона и номер МД которого задаются при
генерации. Дублирование происходит каждый раз при корректировке лимитов.

#### 10.2.4. Инструкция диспетчеру

В начале работы на вопрос `КТО` надо ответить `ДИС` и сообщить пароль
диспетчера.

##### 10.2.4.1. Показ и установка признаков экспрессных и дежурных задач

Диалог имеет следующий вид:

```
ЧТО   МАС
 -    СЧИ
 -    МЭ=            ВЫДАТЬ МАСКУ ЭКСПРЕССНОГО
                     ВРЕМЕНИ
 -    МД=            ТО ЖЕ ДЛЯ ДЕЖУРНОГО
 -    ПЭ=<NN><Э>.    ВЫДАТЬ ПРИЗНАКИ
                     ЭКСПРЕССНОСТИ У ОТДЕЛА
                     <NN>, НАЧИНАЮЩИЕСЯ С
                     С ЦИФРЫ <Э>
 -    ПЭ=<NN>..      ВЫДАТЬ ПРИЗНАКИ
                     ЭКСПРЕССНОСТИ ОТДЕЛА <NN>
 -    ПЭ=<NN><ЭЭ>    ВЫДАТЬ ПРИЗНАК ЭКСПРЕССНОСТИ
                     <ЭЭ> ОТДЕЛА <NN>
 -    ПД=            ВЫДАТЬ ПРИЗНАК ДЕЖУРНОСТИ
 -    МЭ=ХХ00..0ХХ   УСТАНОВИТЬ ЭКСПРЕССНУЮ
                     МАСКУ
 -    МД=00..0ХХ     ТО ЖЕ ДЛЯ ДЕЖУРНОЙ
 -    ИЭ=<NN><ЭЭ>    ИЗМЕНИТЬ ПРИЗНАК
 -                   ЭКСПРЕССНОСТИ (ПЭ) У
                     ОТДЕЛА <NN> НА <ЭЭ>
 -    УЭ=<NN><ЭЭ>    УСТАНОВИТЬ ПЭ У
                     ОТДЕЛА <NN>
 -    УД=<ДД>        УСТАНОВИТЬ ПРИЗНАК
                     ДЕЖУРНОСТИ (ПД)
 -    ЗАП            ЗАПИСЬ ПОЛЯ МАСОК
 -    ВЫХ            ВЫХОД ИЗ "МАС"
```

##### 10.2.4.2. Управление временем ввода задач

Управление временами имеет следующий вид:

```
ЧТО       РЕЖ
 -        ВД=<ЧЧ>.<ММ>-<ЧЧ>.<ММ>
 -        ВЛ=<ЧЧ>.<ММ>-<ЧЧ>.<ММ>
 -        ВЭ=<ЧЧ>.<ММ>-<ЧЧ>.<ММ>
```

Директивами `ВД`, `ВЛ`, `ВЭ` можно изменить интервал ввода в решение
соответственно дежурных, лимитных и экспрессных задач. Здесь
`<ЧЧ>.<ММ>-<ЧЧ>.<ММ>` — интервал времени ввода в решение.

##### 10.2.4.3. Открытие и закрытие лимитного и дежурного времени

Можно создать особые условия некоторым отделам, а именно: предоставить им
право ввода задач (открыть время) с лимитным или дежурным временем в то
время, когда для всех других отделов оно остается закрытым. Задачи
пользователей таких отделов будут вводиться, получат приоритет — правда,
более низкий, чем у экспрессных задач, — а потом будут решаться. Структура
диалога:

```
  ЧТО         ОТК
ОТКРЫТЬ       ОТК/ЗАК
  ИЛИ         ПУСТАЯ ПОСЫЛКА      ВЫХОД ИЗ РАЗДЕЛА
ЗАКРЫТЬ
 РЕЖИМ        ДЕЖ/ЛИМ
  ДЕЖ         ПУСТАЯ ПОСЫЛКА      РАБОТА ПО ДАННОЙ
  ИЛИ                             КАТЕГОРИИ ВРЕМЕНИ
  ЛИМ                             ОКОНЧЕНА
 ОТДЕЛ        NN                  НОМЕР ОТДЕЛА
              N1-N2               ДИАПАЗОН НОМЕРОВ
```

У соответствующих разделов указанные категории времени закрываются.

##### 10.2.4.4. Отключение отделов от бюджетной системы и включение их в бюджетную систему

Для включения/выключения отделов необходимо на `ЧТО` ответить `ВКО`, на
вопрос `ВКЛЮЧИТЬ ИЛИ ИСКЛЮЧИТЬ` ответить `В` (включение) или `О` (пустая
посылка — выход из блока) и на вопрос `ОТДЕЛ` ответить номером отдела или
диапазоном номеров (пустая посылка — переход на вопрос о
включении/выключении).

Просмотр всех видов каталогов осуществляется директивой `КТЛ`
(`ЧТО     КТЛ`), а просмотр какого-либо одного каталога (в зависимости от
набранной ранее директивы параметром указанных директив может быть либо
список просматриваемых отделов (через запятую), возможно состоящий из
одного отдела, либо диапазон отделов через тире.

##### 10.2.4.6. Корректировка ресурсов

Корректировка производится следующим образом:

```
   ЧТО        КОР
  ОТДЕЛ       NN
              N1-N2
              ПУСТАЯ ПОСЫЛКА      РАБОТА ПО ДАННОМУ
                                  РАЗДЕЛУ ОКОНЧЕНА
    -         <ИМЯ РЕСУРСА><ЗНАК><КОЛИЧЕСТВО>
 ЗАПИСАТЬ     ДА ИЛИ НЕТ
```

Здесь `<ИМЯ РЕСУРСА>` = `Б` (бумага), `Л` (лимитное время), `Д` (дежурное
время), `Э` (экспрессное время).

`<ЗНАК>` = `’+’` (добавить) или `’-’` (отнять).

`<КОЛИЧЕСТВО>` = количество метров АЦПУ (от 1 до 5 цифр) или время в
форматах `<ЧЧ>.` или `<ЧЧ>.<ММ>`. Например:

```
Э +3 Д+12.20 Б-20    ДОБАВИТЬ 3 ЧАСА ЭКСПРЕССНОГО
                     ВРЕМЕНИ И 12ЧАС. 20МИН.
                     ЛИМИТНОГО, А ТАЖЕ ОТНЯТЬ
                     20М БУМАГИ.
```

##### 10.2.4.7. Создание нового каталога

Для занесения ресурсов в новый каталог диспетчер выполняет следующие
действия:

```
ЧТО      НОВ
ЧТО      ВВД
ОТДЕЛ    NN  ИЛИ  N1-N2
```

Далее работа диспетчера идет по аналогии с директивой `КОР`. Чтобы лимиты
отдела были нулевые, достаточно внести только один любой параметр времени,
равный нулю.

##### 10.2.4.8. Переход на новый бюджет

Переход на новый бюджет расходов ресурсов времени и бумаги осуществляется в
начале периода. Текущий и исходный каталоги получают значения нового.

Переход осуществляется посредством последовательного набора в ответ на
`ЧТО` директивами `НОВ` и `НБЮ`. После перехода на новый бюджет
автоматически устанавливается дата и время включения лимитов.

Когда планируемые на следующий период ресурсы бывают близки значениям
ресурсов исходного каталога на текущий момент, есть смысл не употреблять
`ВВД`, а воспользоваться следующими директивами:

```
ЧТО      ИСХ
ЧТО      ПРК
```

Таким образом новый каталог примет значение исходного каталога.

## 11. Сбор и обработка статистики в ОС Диспак

**11.1.** В ОС Диспак выбран способ регистрации и накопления фиксированной информации
внутри системы в процессе работы вычислительной системы и последующей
автономной обработки этой информации. Накапливается статистическая
информация о задачах пользователей и о работе всех внешних устройств
комплекса. Собираемые данные характеризуют весь процесс прохождения задачи
пользователя в ЭВМ, отражают загрузку внешних запоминающих устройств, а
также фиксируют аварийные ситуации, возникающие в процессе работы.

В ОС имеется ряд блоков сбора статистической информации. Эти блоки
вызываются в работу по мере необходимости. Процесс регистрации и сбора
статистической информации распадается на несколько этапов. Первый и второй
этапы осуществляются системными блоками автоматически. По окончании каждой
задачи все данные о ней собираются и компонуются на буфере ОЗУ, а затем
переносятся на буфер системного МД.

Второй этап в организации хранения статистической информации — перенос ее
с системного МД в область накопления — осуществляется вспомогательной
программой.

Для обработки полученных статистических данных необходимо создать область
`СТАТ/4155..` длиной 1744 зоны (аналог МД 2091). Специальный набор программ
статистики должен быть переписан в область накопления статистики (`СТАТ`) в
1150–1172 зоны из 0-й зоны области `ГПСТАТ/4155..`. Кроме того, для первого
запуска программы "СБОР" необходимо расписать 20-ю зону области
`СТАТ/4155..` разметочным кодом (по директиве `РОСП` программы "СЕРП", на
приглашение `КОД-` следует ответить пустой посылкой).

**Структура диалога**

Все остальные программы статистики работают с информацией на диске
накопления, то есть могут быть введены в решение только после программы

### 11.2. Программа "ИТОГ"

Программа "ИТОГ" — сервисная программа обработки и выдачи статистики по
задачам, предоставляющая пользователю:

* возможность получения полной информации о задачах, накапливаемой ОС;
* развитый аппарат критериев выбора задач;
* возможность запуска в диалоговом и пакетном режимах;
* возможность получения различных вариантов таблиц выдаваемых параметров в
  одном запуске программы;
* возможность подсчета числа задач, удовлетворяющих заданным критериям
  выбора.

Пользователь может работать в двух различных по функциям блоках: "КЛАСС" и
"РАБ".

#### 11.2.1. Описание блока "КЛАСС"

Задав разбиение на "классы" по значению какого-либо параметра,
пользователь может подсчитать количество задач, удовлетворяющих каждому из
заданных классов разбиения. В одном запуске можно задать до 5 вариантов
различных разбиений на классы. Причем в каждом варианте разбиение идет по
одному из заданных параметров, значения (диапазон значений) которого заданы
через разделитель `,`. Если такого параметра в варианте нет, то разбиение
идет по первому заданному в варианте параметру.

#### 11.2.2. Описание блока "РАБОТА"

Программа настраивается на получение статистики по задачам (в том числе и
суммарной) в зависимости от заданного типа статистики и параметров выбора.

#### 11.2.3. Структура построения задания на работу программы

Разобьем условно параметры выбора задач на основные и дополнительные.

Основными назовем параметры, значения которых являются общими критериями
выбора задач для всех вариантов задания дополнительных параметров.

Дополнительными мы будем называть параметры, значения которых являются
критериями выбора задач только для данного варианта задания параметров
выбора.

Есть следующие ограничения на задание дополнительных параметров:

* параметры, заданные в основных, не могут быть заданы в дополнительных;
* если параметры `ШИФ` или `ОТД` не были заданы в основных параметрах, то
  их необходимо задать в каждом варианте выбора;
* в блоке "КЛАСС" в дополнительных параметрах можно задать разбиение на 8
  классов по значению первого параметра. Класс может быть задан либо одним
  значением, либо одним диапазоном значений;
* в блоке "РАБОТА" разбиение на классы интерпретируется как несколько
  возможных значений параметра выбора. В случае отсутствия дополнительных
  параметров считается, что основные параметры являются первым вариантом
  выбора задач. Задание основных и дополнительных параметров должно
  соответствовать указанному типу статистики;

Пользуясь принятой терминологией, приведем общую структуру построения
задания:

* основные параметры;
* дополнительные параметры (до 5-ти вариантов);
* параметры печати (до 5-ти вариантов) (только для блока "РАБОТА");

#### 11.2.4. Описание и способы задания параметров

##### 11.2.4.1. Управляющие параметры режима работы программы

* `ЗАМ` — режим замены шифров сбойных задач, параметр может быть задан
  только в основных;
* `УБР` — режим выдачи итоговой строки таблиц без ее внутреннего
  содержания (задается только в параметрах печати);
* `ВАР` — параметр, определяющий номера вариантов выбора, для которых
  выдавать данный вариант печати.

##### 11.2.4.3. Правила и способы задания значений параметров

Основные параметры могут быть заданы либо одним значением, либо одним
диапазоном значений. Исключение составляют параметры `ОТД`, `ШИФ`, которые
могут быть заданы несколькими значениями <ОТД,ШИФ> или несколькими
диапазонами значений `ОТД`.

В режиме выдачи не итоговой статистики по каждому из заданных шифров —
(ШИФР), параметр `ШИФ` всегда должен быть задан в основных параметрах. Для
остальных типов статистики (ШИТ, ОИТ, ОТД, ХРО) задание основных параметров
не является обязательным условием.

В блоке "КЛАСС" параметры `ОТД` и `ШИФ` всегда задаются в основных
параметрах.

Параметры `ОТД`, `ШИФ` должны задаваться первыми, как в случае задания их в
основных параметрах, так и в дополнительных:

```
ОТД=41,12-10       ЦЕЛЫЕ ЧИСЛА  0 < NОТД < 100
ШИФ=4100..,420031,45..00000000
```

Шифр — произвольный набор цифр и точек. Точка означает произвольную цифру в
шифре. Неуказанные позиции шифра дополняются точками справа до 12.

Рассмотрим задание других параметров:

```
ДАТ=01.05.85-06.05.85
ДАТ=01.05.85
ДАТ=01.06.85/02.06.85
```

Разделитель `/` задает режим "сутки". Первая дата — дата начала отсчета
суток, вторая — дата конца отсчета суток. Границы суток задаются системным
программистом (смотри инструкцию администратору). Задача удовлетворяет
заданному диапазону дат в режиме "сутки", если она закончила свое решение
после начальной границы первых суток и до конечной границы суток во второй
дате.

Параметры `ЗВР`, `ИВР`, `ЗЭВ`, `ЗДВ`, `ЗЛВ`, `ИЭВ`, `ИДВ`, `ИЛВ`, `РЕШ`,
`ПРО`, `ТРВ`, `КМВ`, `МПВ`, `НСЧ`, `КСЧ`, `НВВ` задаются в виде: ЧЧ.ММ.СС
или ЧЧ.ММ, где ЧЧ — часы, ММ — минуты, СС — секунды. Данные параметры могут
задаваться диапазонами, либо одним значением:

```
ЗВР=03.00-04.05.00   ;   ИВР=05.00
```

Параметры `ЗАЦ`, `ИАЦ`, `ПЛВ`, `ЗОП`, `ЗТР`, `ИТР`, `СТП`, `ЗБО`, `ЗКУ`,
`ЧМБ`, `ЧМЛ`, `ЧМБ`, `УВВ`, `ПКВ`, `ПРМ`, `СНЯ`, `МАШ`, `СМЕ` задаются в
10-ном виде и могут быть заданы одним значением, либо диапазоном значений:

```
ЗТР=0-12    ;   ИТР=10
```

Параметры `НОМ`, `КАН`, `ТЕР`, `ТАС`, `СТП` задаются в 8-ном виде одним
значением, либо диапазоном значений:

```
КАН=40-41      ;    НОМ=30
```

Параметры `БЗП`, `БЧТ` задаются одним значением, либо диапазоном значений:

```
БЗП=20-30   ;  БЧТ=2060,4080-4085
```

Присутствие хотя бы одного из параметров `БЗП` и `БЧТ` в выдаваемых
параметрах приводит к выдаче на печать всех бобин задачи, заказанных по
чтению и по записи. При этом бобины, заказанные по записи, помечаются
звездой. В параметрах печати может быть задан только один из параметров
`БЧТ`, `БЗП`.

Параметры `ЗАМ`, `УБР` определяют режимы работы программы и тип выдаваемых
таблиц. Указанные параметры значений не имеют.

Параметр `ВАР=12345` означает, что данный вариант таблицы печати выдавать
для 1, 2, 3, 4, 5 вариантов выбора. По умолчанию печатается таблица каждого
варианта выбора.

Рассмотрим применяющиеся символы-разделители:

* `;` — разделитель параметров (может быть заменен пробелом);
* `,` — разделитель классов в варианте или разделитель шифров и номеров
  отделов;
* `-` — разделитель значений параметра в диапазоне задания;
* `/` — разделитель значений в параметре "ДАТА" при работе в режиме
  "сутки";

#### 11.2.5. Диалоговый режим работы программы

Для диалоговой работы нужно либо сформировать описанный ниже пакет, либо
завести соответствующие стандартный паспорт и ключ:

```
ШИФР ХХХХХХХХХХХХ
ОЗУ 32
ВРЕ ХХХ
ТРА УУ          ПО МЕРЕ НЕОБХОДИМОСТИ
ТЕЛ
АЦП 64
РОС 0
ЛЕН 42(СТАТ-ЗП)41(СТАТ-ЗП)
ВХО 76000
ЕВ76000
К 00 110 6005 00 050 0105
К 15 24 4ПРЧТ 00 050 0121
К 15 24 0ПРЗП 00 050 0121
К 00 170 6005
К 00 30 00001
С 0010 0000 0042 1160      НАЧ.ЗОНА ГП
ЕКОНЕЦ
```

После выхода задачи в решение на терминал выдается приглашение:

```
ЧТО-
```

В ответ следует набрать директиву, выбирающую блок, в котором в дальнейшем
пойдет работа программы:

```
КЛА (ЕТХ)   БЛОК <КЛАСС>
РАБ (ЕТХ)   БЛОК <РАБОТА>
```

Программа настраивается на работу с областью `СТАТ`. Ответ `КНЦ` влечет за
собой завершение работы. Следующий запрос:

```
ТИП СТАТИСТИКИ-
```

Следует задать один из типов:

* `ШИТ` — итог по каждому из заданных шифров;
* `ШИФ` — статистика по всем задачам пользователя для каждого из заданных
  шифров;
* `ШХР` — статистика по всем задачам пользователя для заданных шифров в
  порядке поступления на диск;
* `ОИТ` — итог по заданным отделам;
* `ОТД` — итог по каждому шифру из заданных отделов;
* `ОХР` — статистика по всем задачам пользователя для каждого из заданных
  отделов.

Далее программа запрашивает основные параметры. Варианты ответов на
приглашение. Имеются следующие параметры:

* `<ТЕКСТ>` — прием набранного текста и очередной запрос основных
  параметров;
* `ВЫД` — просмотр на экране заданных основных параметров. Далее
  повторяется запрос основных параметров;
* `(ЕТХ)` — в случае, если основные параметры заданы, производится
  семантический и синтаксический контроль задания. Если ошибок не найдено,
  то переходим к запросу дополнительных параметров. В случае, если основные
  параметры были заданы неверно, выдается сообщение о допущенной ошибке и
  производится запрос основных параметров заново;
* `НАЧ` — производится запрос основных параметров заново.

После задания основных параметров выбора задач запрашиваются варианты
задания дополнительных параметров. На запрос очередного варианта:

```
ВАРИАНТ N1:
```

возможны следующие ответы:

* `<ТЕКСТ>` — прием набранного текста и очередной запрос дополнительных
  параметров для текущего варианта;
* `ВЫД` — выдача на экран всех, заданных до текущего момента, параметров
  (основных и дополнительных);
* `(ЕТХ)` — в случае, если были заданы параметры в варианте, производится
  семантический и синтаксический контроль. Если ошибок нет, переходим к
  следующему варианту. В противном случае, выдается сообщение об ошибке и
  идем на запрос этого варианта. В случае, если вариант не был задан или
  обработали 5 вариантов выбора, то переход либо на запрос вариантов печати
  (РАБОТА), либо на обработку статистики (КЛАСС);
* `НАЧ` — переход на начало блока (на запрос основных параметров).

Запрос вариантов печати:

```
ПЕЧАТЬ  N1 :
```

Ответы на запросы:

* `<ТЕКСТ>` — прием набранного текста и очередной запрос дополнительных
  параметров для текущего варианта;
* `ВЫД` — выдача на экран всех заданных до этого параметров (основных,
  дополнительных, печати)
* `(ЕТХ)` — если первый вариант, и не было задано до этого параметров, то
  снова запрос. Если не первый вариант и не было задано параметров, то —
  обработка статистики. Если вариант был задан, то осуществляется контроль
  заданного варианта. В случае ошибки, запрашиваем этот вариант снова. В
  противном случае идем на запрос следующего варианта;
* `НАЧ` — на начало работы блока (на запрос основных параметров).

#### 11.2.6. Типы выдаваемой статистики в блоке "РАБОТА"

##### 11.2.6.1. Итог по каждому из заданных шифров

Обозначение данного типа статистики — `ШИТО`. Пусть заданы следующие
параметры:

```
ТИП СТ-КИ:ШИТО
ПАРАМЕТРЫ:"ЕТХ"
ВАРИАНТ N1:ШИФ=4       ШИФРЫ В ВАРИАНТАХ
ВАРИАНТ N2:ШИФ=2
ВАРИАНТ N3:ШИФ=5
ПЕЧАТЬ  N1:ЧЗД;ЧМД;ЧМБ
```

Тогда выходной документ представляет собой три таблицы, каждая из которых
содержит суммарные значения параметров `ЧЗД`, `ЧМД` и `ЧМБ` для всех задач,
шифры которых начинаются соответственно с цифр 4, 2 и 5.

##### 11.2.6.2. Статистика по указанным шифрам

Данный тип статистики имеет тип `ШИФР`. Здесь, маневрируя заданием шифров,
можно получить статистику по отделу (`ШИФ=41....`), группе отделов
(`ШИФ=4.....`), статистику по любым классам задач пользователя
(`ШИФ=4108..22`), статистику по всем задачам (`ШИФ=......`) в порядке
поступления на диск статистики.

Для данного типа статистики параметр `ШИФ` может быть задан только в
основных.

Пусть заданы следующие параметры:

```
ТИП СТАТИСТИКИ - ШИФ
ПАРАМЕТРЫ:ШИФ=4.....,5..  ШИФР ТОЛЬКО ОСНОВНОЙ
ВАРИАНТ N1:
ПЕЧАТЬ  N1:ЧЗД;ЧМД;ЧМБ
```

Выходная таблица отличается от таблиц предыдущего примера тем, что
печатаются не суммарные параметры, а индивидуальные для каждой задачи, шифр
которой удовлетворяет шифрам, заданным в параметрах.

Статистика типа `ШХР` отличается от статистики `ШИФ` тем, что информация о
разных задачах выдается в порядке поступления ее в область статистики.

##### 11.2.6.3. Итог по заданным отделам

Данный тип статистики имеет имя `ОИТ`. Приведем пример:

```
ТИП СТАТИСТИКИ - ОИТ
ПАРАМЕТРЫ: "ЕТХ"
ВАРИАНТ1 : ОТД=01-02,05
ВАРИАНТ2 : ОТД 34
ВАРИАНТД=01-02,04-05
ПЕЧАТЬ : ЧЗД; ЧМД; ЧМБ
```

Выходная информация — это две таблицы с суммарными значениями параметров
печати для каждого отдела.

Статистика типа `ОТД` представляет собой печать той же информации, но для
каждой задачи с шифром из указанных отделов.

Если задан тип статистики `ОХР`, то выдается индивидуальная информация по
каждой задаче, имеющей шифр из данного отдела. Заметим, что в предыдущем
случае суммируется информация по конкретному пользователю, т. е.
учитываются только первые четыре цифры шифра.

#### 11.2.7. Работа в блоке "КЛАСС"

В блоке "КЛАСС" можно задать с помощью неосновных параметров разбиение
задач, по которым выдается статистика. Например, требуется подсчитать число
задач данного отдела, решавшихся 21.03.85 и работавших с терминалами 55 и
34. Пример диалога:

```
ЧТО-        КЛА
ТИП СТАТИСТИКИ : ОИТ
ПАРАМЕТРЫ:       ОТД 45, ДАТ 21.03.85
ВАРИАНТ1 :       ТЕР 55,34
ВАРИАНТ2 :       "ЕТХ"
```

Итоговая таблица представляет собой одну строку и две колонки по номерам
терминалов.

#### 11.2.9. Административная подсистема

Готовая программа занимает 6 зон, одна зона также отводится под
дополнительную информацию. Первый запуск программы необходимо произвести с
терминала от лица администратора. Администратору предоставляются следующие
возможности:

* работать в блоке администратора;
* работать с любыми носителями статистической информации (пользователь
  может работать только с областью `СТАТ`).

Рассмотрим диалог в блоке администратора:

```
 ЧТО- АДМ           ПРИЗНАК РАБОТЫ АДМ-РА.
КЛЮЧ- ХХХХХХ        ШЕСТИЗНАЧНОЕ ЧИСЛО,
                    ЗАДАВАЕМОЕ ПО ДИРЕКТИВЕ
                    "КЛЮ"
ТИП СТ-КИ- ШИФ
ЧТО- КАТ            ВХОД В БЛОК АДМИНИСТРАТОРА
```

Блок администратора позволяет:

* задавать, изменять названия отделов;
* задавать номера причин снятий и соответствующие им шифры замен;
* задавать границы машинных суток, установленных на данном предприятии.

В блоке доступны директивы:

* `НОТ` — директива заведения, изменения названий отделов. По этой
  директиве запрашивается номер отдела (от 01 до 99) и его название (не
  более 48 символов). Пустая посылка на запрос номера отдела означает
  переход к следующей директиве.
* `ОТД=ХХ-УУ,ZZ` — директива выдачи на терминал названий отделов по
  заданным номерам.
* `ЗАМ` — директива входа в блок запроса причин снятия задач и
  соответствующих им шифров замен. Данная директива имеет смысл на
  предприятиях, обслуживающих сторонние организации.

  Шифры задач, у которых причина снятия совпадает с заданными, заменяются
  на соответствующие шифры замен, тем самым реализуется возможность
  списания с пользователя использованных ресурсов задач, окончившихся
  сбоями по вине аппаратуры или другим, не зависящим от него причинам.

  В ответ на директиву `ЗАМ` производится запрос:

  ```

                      СНЯТИЯ ( ОТ 0 ДО
                      127 ). ДАЛЕЕ ИДЕТ ЗАПРОС
                      ШИФРА ЗАМЕНЫ.
                :НОВ  ЗАВЕДЕНИЕ НОВОГО
                      СПИСКА ПРИЧИН И
                      ШИФРОВ ЗАМЕН.
                :НАЧ  ВЫХОД ИЗ БЛОКА
                      ЗАДАНИЯ ПРИЧИН.
     ШИФР ЗАМЕНЫ:ХХХХХХХХХХХХ
                :НАЧ  ВЫХОД ИЗ БЛОКА
                      ЗАДАНИЯ ПРИЧИН.
  ```

  Возможно задать до 15 причин снятий и шифров замен. При заполнении поля
  выдается сообщение: `< ЗАДАНО 15 ШИФРОВ ЗАМЕН >`.
* `ПЕЧ` — печать названий отделов (печать остальных параметров не
  реализована).
* `ЗАП` — запись зоны с дополнительной информацией.
* `КЛЮ` — директива задания и изменения ключа администратора (6 символов).
* `СУТ` — директива перехода на запрос границ машинных суток (интервал
  времени).
* `ВЫХ` — выход из блока.
* `КНЦ` — конец работы программы.

## 12. Управление прохождением задач в ОС

Для изменения режима прохождения задач в ОС служат директивы `ПЛАН` и
`ПРИО` диалоговой системы "СЕРП".

Директива `ПЛАН` служит для перераспределения каналов между классами
решаемых задач, а директива `ПРИО` — для работы с каталогом приоритетных
шифров (КПШ). Задачи, шифр которых принадлежит КПШ, являются для ОС в
некотором смысле более приоритетными, чем прочие задачи. ОС имеет так
называемый архив режимов ОС (АРО). Элементами АРО являются поименованные
варианты распределения каналов между классами и поименованные варианты КПШ.
Кроме архивных имен имеются служебные имена:

* `РАБ` — рабочий вариант КПШ;
* `ГОТ` — специальный вариант КПШ, который при перевызове ОС получает имя
  `РАБ`.
* `РАБ` — рабочий вариант распределения каналов между классами;
* `ГОТ` — вариант распределения, который после перевызова ОС займет место
  варианта с именем `РАБ`.

Варианты распределения каналов между классами (в том числе и с именем
`ГОТ`) имеют подварианты для каждой из 7 ЭВМ.

означает работу с вариантом для ЭВМ, на которой вызвана программа "СЕРП".

## 13. Работа с магнитными носителями в ОС Диспак

### 13.1. Разметка магнитных дисков

#### 13.1.1. Для подготовки к работе магнитных дисков необходимо произвести их разметку

Разметка включает в себя проверку качества носителя, разделение носителя
на зоны длиной 1024 слова, присвоение номера каждой зоне, а также
присвоение номера всему носителю. Эта информация помещается в специальные
служебные слова, которые при разметке также записываются на магнитный
носитель. Магнитные ленты используются только в режиме ЕС и не
размечаются.

#### 13.1.2. Разметка магнитных дисков

Разметка магнитных дисков может осуществляться как с помощью автономной
программы разметки (без ОС), так и в операционной системе.

##### 13.1.2.1. Автономная программа разметки

(См. "Пультовое программное обеспечение. Руководство оператора"
ИЫ.00112-01 34 01.)

Для ее вызова необходимо поставить на накопитель гибких магнитных дисков
(НГМД) пультовой машины гибкий магнитный диск (ГМД) с программами разметки
МД и вызова ОС. С помощью средств пультовой программы (см. [4]) набрать на
клавиатуре пультовой машины следующую информацию (номера ячеек и содержимое
регистров приведены в шестнадцатиричном виде):

Для ПМ типа "ДВК":

* `У0`
* `ВЫЗОС`

Ответ системы: `ЕСТЬ`

Для ПМ типа ЕС-1840: `ЗАГ SERWIS`

Ответ системы: начальный адрес и длина программы в словах.

Задать параметры разметки:

* ячейка 2 := 0
* ячейка 3 := N пакета в шестнадцатиричном виде
* ячейка B := N устройства в шестнадцатиричном виде
* ячейка C := N канала в шестнадцатиричном виде
* `У0`
* `АР`
* убедиться, что РК = 0 3F 07 000 (стоп 0)
* директива `П` — пуск, или нажатие соответствующей клавиши на ПМ.

В процессе разметки номер размечаемых цилиндра и головки заносятся в ячейку
13. После окончания разметки программа выходит на "стоп 0" (на РК код
0 3F 07 000).

##### 13.1.2.2. Разметка дисков в операционной системе

Программа разметки магнитных дисков емкостью 100 и 200 Мгб вызывается с
терминала по ключу `РЗ` с фиксированным шифром разметки `419922`:
`РЗ 419922`. Предлагается несколько видов работ:

* `РЗД` — разметка всего диска полностью,
* `ТДД` — составление и выдача таблицы дефектных дорожек,
* `РОД` — разметка отдельных дорожек, номера дорожек задаются в
  шестнадцатиричном виде,
* `РЗЗ` — разметка диска с заданной зоны до конца,
* `РИП` — разметка инженерного пакета тяжелым кодом,
* `ГЕН` — задание конфигурации ВУ.

Размечаемый пакет должен быть установлен на накопитель и включен.
Физический номер накопителя указывается в ответ на запрос `ВУ(ХХХ)=` в виде
трех шестнадцатиричных цифр (например, `03А`). Номер пакета в десятичном
виде задается в ответ на запрос `ПАКЕТ=` (например, `2048`). На все время
разметки терминал остается занятым.

Для начальной разметки всего диска следует воспользоваться работой `РЗД`.
Работы `ТДД`, `РЗЗ` и `РОД` возможны только с пакетами, которые ранее были
размечены в операционной системе.

Внимание! В работах, связанных с заданием номеров зон (`РЗЗ`) или номеров
дорожек (`РОД`), в общем случае затрагиваются зоны предыдущая и последующая
по отношению к заданным (например, при разметке по работе `РЗЗ` начиная со
2-й зоны будет размечена и часть 1-й зоны; при разметке дорожки 00002
будут размечены зоны 2-я и 3-я).

В работе `РИП` пакет расписывается тяжелым кодом без служебных слов и без
дефектации, только с выдачей информации о плохих дорожках.

При обнаружении дефектной дорожки на терминал и АЦПУ выдается номер
дефектной дорожки (цилиндр и головка в шестнадцатиричном виде), номер зоны
(в восьмеричном виде), содержимое нулевого, четвертого и шестого слов
местной памяти канала, 24 байта уточненного состояния и 3 слова
статистики. Если размечаемый пакет не имеет дефектов, выдач на терминал не
будет до окончания разметки. Если разметку не удается начать, на терминал
и АЦПУ будет выдано соответствующее сообщение.

По умолчанию выдается информация только о дефектуемых дорожках, дорожки с
корректируемой ошибкой данных не считаются дефектными. Изменить эти режимы
можно директивами:

* `У.` — усиленный режим разметки, при котором дорожки с корректируемой
  ошибкой данных также отбраковываются;
* `П.` — выдача информации о каждом сбое, даже если дорожка не
  отбракована.

Директивы изменения режимов можно задать в ответ на любое приглашение.

Не могут быть размечены системные диски и диски, занятые в данный момент
задачей.

### 13.2. Копирование информации

Копирование информации на магнитных носителях осуществляется с помощью
диалоговых программ "СЕРП" и "UNICOP", а также с помощью программы "КОПЕС"
(см. [2], раздел 6). "СЕРП" (в части копирования) применяется для работы с
размеченными носителями, а "UNICOP" и "КОПЕС" — для работы с МЛ в режиме
ЕС.

Для копирования системных магнитных дисков на магнитные ленты пользуются
программой "UNICOP", работа `Б6ЕС`.

При копировании готовых программ ОС необходимо формировать ленту по типу
МЛ1: первые два файла занимает программа "МЛОПОС", записанная программой
"UNICOP" работой `Б6ЭЛЬБ`, третий и четвертый файлы — ГП ОС, записанные
работой `Б6ЕС3`.

#### 13.2.1. Директивы переписи системы "СЕРП"

Используются следующие директивы программы "СЕРП":

* `ПЕРЕ` — для переписи зон с пользовательского тома (МД, области архива)
  на пользовательский том;
* `ПЕРТ` — для переписи без формирования задачи;
* `ПЕРП` — для переписи с обходом "плохих" зон.

Для переписи системных пакетов необходимо к его номеру приписать (без
пробела) букву `Д`. При этом указанный диск не попадет в паспорт
формируемой задачи переписи, а будет ею дозаказан.

Структура диалога приведена в табл. 7.

**Таблица 7**

| Приглашение системы | Ответ польз-ля | Комментарии |
|---------------------|----------------|-------------|
|                  | `СП <ШИФР>`    | Вызов программы "СЕРП" |
| `ЧТО-`           | `ПЕРЕ`         | Директива переписи |
| `СЧИТ:ТОМ-`      | `2113`         | Номер тома чтения |
| `ЗАП:ТОМ-`       | `ОБЛ/419955`   | Том записи |
| `СЧИТ:ЗОНА(8)-`  | `700`          | Начальная зона чтения |
| `ЗАП:ЗОНА(8)-`   | `0`            | Начальная зона записи |
| `КОЛ-ВО ЗОН-`    | `20`           | Число зон переписи |
| `СЧИТ:ЗОНА-`     | пуст. посылка  | Конец задания для переписи |
| `ХХ:ПРОГР ПЕРЕ`  |                | Формирование задачи переписи |
|                  | `КНЦ`          | Конец работы с прогр. "СЕРП" |

#### 13.2.2. Программа "UNICOP"

Программа "UNICOP" (см. [2], раздел 6) используется при копировании, когда
на одном из двух носителей информация записана в режиме ЕС, а на другом —
в режиме, совместимом с БЭСМ-6. При этом предварительно нужно выполнить на
операторском терминале директиву `ЕСМ <НБОБ> <НУ>`, где `<НБОБ>` — это
произвольный номер, присваиваемый МЛ, а `<НУ>` — номер устройства, на
котором установлена лента.

Работы `ЕСБ6` и `Б6ЕС` предназначены для переписи информации, состоящей из
48-разрядных слов, в соответствующем направлении;

работа `Б6ЭЛЬБ` предназначена для копирования на МЛ программы начальной
переписи ГП ОС ("МЛОПОС"), копируется 2 зоны из области МЛОПОС в 1-й и 2-й
файлы МЛ, на вопрос "физический адрес загрузки" в данной работе следует
отвечать `71717`, виртуальный адрес — 2000, номер регистра приписки — 48;

работа `Б6ЕС3` используется при копировании ГП ОС на МЛ, копируется 500 зон
из 300-й зоны диска 2053 в 3-й и 4-й файлы МЛ, на которую предварительно
записана программа "МЛОПОС" (2 файла). В аннотации следует указать
начальный адрес загрузки `НАЗ 10600000`;

работа `ЕСКС` предназначена для подсчета контрольной суммы одного файла МЛ.

Пример диалога:

```
 РАБОТА(ЕСБ6,Б6ЕС,ЕСКС,Б6ЕС3,Б6ЭЛЬБ,ПЛОТ):ЕСБ6
 ПЛОТ 32
 ТОМ ЕС:222
 ТОМ Б6:ОБЛ/4199..
 НОМЕР ФАЙЛА(0-С МЕСТА):1
 НОМЕР ЗОНЫ Б6:0
 НОМЕР ЗОНЫ ЕС:0
 ПЕРЕМОТКА ПО ОКОНЧАНИИ(ДА,НЕТ):ДА
 ЧИСЛО ФАЙЛОВ ЕС:2
 ЧИСЛО ЗОН:1000
 ПЕРЕПИСЬ ЕС-> Б6.
 АННОТАЦИЯ К ПЕРЕПИСЫВАЕМОЙ ИНФОРМАЦИИ: ТЕКСТ
 КОЛИЧЕСТВО ЗОН - 1000
КНЦ
```

По окончании переписи на терминал и на АЦПУ выдается информация о
переписанных зонах и контрольная сумма переписанных зон (одной копии).
Отказаться от выдачи на АЦПУ можно директивой `А.`.

#### 13.2.3. Программа "КОПЕС"

Программа "КОПЕС" осуществляет копирование информации с магнитной ленты в
режиме ЕС на другую магнитную ленту в режиме ЕС. Магнитным лентам
предварительно следует присвоить номера директивой `ЕСМ <НБОБ><НУ>`, где
`<НБОБ>` — номер МЛ, `<НУ>` — номер магнитофона, на котором установлена МЛ.
Причем:

* МЛ чтения всегда имеет номер 1,
* МЛ записи всегда имеет номер 2.

Информация копируется идентично до признака "конца ленты" (два ТМ подряд).
После копирования на АЦПУ выдается контрольная сумма всей МЛ (общая сумма
всех файлов). Эту программу удобно использовать для копирования МЛ1 (лента
с ГП ОС).

Вызов программы копирования:

```
ДИМИП ХХХХХХ
КТ ДОКЭБ 0 ДОКЭБ
РЕД КОПЕС
Ф
ВЫЙ
```

## 15. Дополнительные возможности

### 15.1. Обеспечение работы с системным журналом

Системный журнал — это область на резидентном МД, в которой собираются
сообщения, выдаваемые на операторский терминал. Просмотр журнала
осуществляется с помощью директивы `ОПТ` системы "СЕРП". Структура
диалога:

```
ЧТО-  ОПТ
 =    ДАТ 12.03         ВЫДАВАТЬ СООБЩЕНИЯ ПО
                        УКАЗАННОЙ ДАТЕ
 =    ВРЕ 14.20-15.00   ВЫДАВАТЬ СООБЩЕНИЯ,
                        ВЫДАННЫЕ ЗА ДАННЫЙ
                        ИНТЕРВАЛ ВРЕМЕНИ
 =    ВЫД               ВЫДАЧА ВСЕХ СООБЩЕНИЙ
 =    НАЙ КЗ            ВЫДАЧА СООБЩЕНИЙ,
                        СОДЕРЖАЩИХ КОНТЕКСТ "КЗ"
 =    КНЦ
```

### 15.2. Работа с нестандартным оборудованием

Операционная система допускает работу с нестандартным оборудованием в
первом режиме по байтовым каналам. Программа пользователя, использующая
нестандартное оборудование, должна применять экстракоды работы с
терминалами — ЭК 071 (см. [2]).
