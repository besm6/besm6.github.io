директив и сообщений.

Описание рассчитано на операторов, инженеров и системных программистов.

## 1. Назначение программы

Операционная система (ОС) Диспак предназначена для управления ресурсами ВК
"Эльбрус 1-КБ", для облегчения создания программ на них и для управления
процессом их обработки.

ОС Диспак полностью совместима с программным обеспечением, накопленным на
ЭВМ БЭСМ-6. Операционная система обеспечивает:

* мультипрограммный режим пропуска задач;
* режимы пакетной обработки и терминального доступа;
* динамическое распределение памяти для решаемых задач;
* управление вычислительным процессом посредством директив оператора;
* автоматическое распределение внешних устройств между задачами
  пользователя;
* перезапуск системы и задач пользователей при отказах и сбоях
  оборудования;
* функционирование систем программирования, входящих в состав мониторной
  системы "Дубна" (например, Фортран-ГДР, Forex, Алгол-ГДР, Madlen, Рефал,
  Симула и др.), а также систем программирования Бемш, Автокод ИТМ,
  БЭСМ-Алгол и др.

## 2. Условия выполнения программы

Для обеспечения пропуска задач на операционной системе Диспак необходим
следующий минимальный комплект оборудования:

* ЦП Эльбрус 1-КБ;
* секция ОП (объем 64 Мбайт);
* пультовая ЭВМ, снабженная пультовым программным обеспечением (ППО);
* устройство управления накопителями на МЛ ЕС-5525;
* накопитель на магнитной ленте ЕС-5025;
* устройство управления накопителями на сменных магнитных дисках ЕС-5580;
* 2 накопителя на сменных магнитных дисках ЕС-5080;
* АЦПУ ЕС-7040;
* алфавитно-цифровой дисплейный комплекс ЕС-7980;
* 2 алфавитно-цифровых дисплея ЕС-7927.

Внешние устройства подключаются к каналам в соответствии с комплектацией ВК
"Эльбрус 1-КБ". Стандартная комплектация ВК "Эльбрус 1-КБ" и распределение
устройств по каналам приведено в документе "СТП. Руководство оператора"
ИЫ.04301-01 34 01.

Работа с пультовой машиной описана в документе "ППО. Руководство оператора"
ИЫ.00112-01 34 01.

## 3. Выполнение программы

Для вызова ОС необходимо установить ГМД с программой вызова ОС на НГМД N1 и
выполнить приведенные ниже директивы пультовой машины (см. "ППО. Руководство
оператора" ИЫ.00112-01 34 01):

**3.1.** Для ПМ типа ДВК:

* `У0`
* `ВЫЗОС Р` — вызов ОС с росписью каталогов.
  Ответ системы: `ЕСТЬ`
* ячейка 2 := 5
* ячейка 3 := N пакета в шестнадцатиричном виде
* ячейка A := информация для тумблерного регистра
* ячейка B := N устройства в шестнадцатиричном виде
* ячейка C := N канала в шестнадцатиричном виде
* `У0`
* `АР`
* убедиться, что РК = 0 3F 07 000 (стоп 0)
* директива `П` — пуск, или нажатие соответствующей клавиши на ПМ.

Для ПМ типа ЕС-1840: `ОС Р У<N НСМД> М<N МАШ> В<N ВАР>` (см. [4]).

Ответ системы: начальный адрес и длина программы.

По умолчанию задан МД 2053 (шестнадцатиричный код 805), канал 0,
устройство 0, N машины = 1, N варианта = 1.

После сообщения на операторский терминал N1 о ресурсах ОС с операторского
терминала выполняются директивы начала работы системы: `СМЕ N`, `ДАТ XXZZ`,
`ВРЕ ЧЧММ`.

**3.2.** После нормального завершения вызова ОС на операторский терминал
выдаются сообщения следующего вида:

```
НМД<НОМЕР МД>
ЗАТЕР КАТ<N КАТАЛОГА>
<ДАТА> <ВРЕМЯ>
ОС ДИСПАК ВК Э1-КБ
 РЕС: <ЗНАЧЕНИЕ ОБОБЩЕННОГО РЕСУРСА СИСТЕМЫ>
```

**3.3.** После получения указанных сообщений с терминала оператора
необходимо задать следующие директивы:

| Директива                | Ответ ОС |
|--------------------------|----------|
| `СМЕ <N СМЕНЫ>`          | `ЕСТЬ` |
| `ДАТ <ЧИСЛО> <МЕСЯЦ>`    | `ДАТА: <ЧИСЛО>.<МЕСЯЦ>.<ГОД>` |
| `ВРЕ <ВРЕМЯ>`            | `ДАТА: <ЧИСЛО>.<МЕСЯЦ>.<ГОД>  ВРЕМЯ: <ВРЕМЯ>` |

где `<ВРЕМЯ>` = ЧЧММСС; ЧЧ — часы; ММ — минуты; СС — секунды.

После получения последнего сообщения можно начинать работу с ОС.

**3.4.** В случае отсутствия любого из указанных ответов системы необходимо
повторить вызов ОС с пункта 3.1.

## 4. Директивы оператора

### Общие сведения о директивах

Директивы операционной системы Диспак подразделяются на два множества:
множество директив оператора и множество директив пользователя. Первое
множество включает в себя второе множество и таким образом является полным,
т. е. содержит в себе все директивы ОС. Любая директива оператора (и
соответственно любая директива пользователя) может быть исполнена с
терминала оператора. С терминала пользователя разрешается задавать лишь
некоторые директивы оператора. Эти директивы представляют собой множество
директив пользователя. Директивы ОС Диспак разделены на следующие группы:

1. Директивы подготовки операционной системы к работе.
2. Директивы установки режимов на ЭВМ.
3. Информационные директивы.
4. Директивы управления прохождением задач.
5. Директивы управления внешними устройствами.
6. Сервисные директивы.

Директивы оператора можно задавать с терминала ЕС-7927. Для этого достаточно
набрать нужную директиву и нажать клавишу "ВВ". После выполнения директивы
на терминал выдается соответствующее сообщение.

### Условные обозначения

| Обозначение | Значение |
|-------------|----------|
| /О/  | Директива оператора. Директива оператора может быть исполнена только с терминала оператора. |
| /ОП/ | Директива пользователя. Данная директива может быть исполнена как с терминала оператора, так и с терминала пользователя. |

### 4.1. Директивы подготовки операционной системы к работе

#### 4.1.1. Директива `СМЕ[НА] <N СМЕНЫ>`

/О/. Директива предназначена для указания системе номера смены операторов,
обслуживающей ЭВМ.

| Параметр     | Значение |
|--------------|----------|
| `<N СМЕНЫ>`  | Номер смены операторов (от 1 до 7), обслуживающей ЭВМ. |

После перевызова системы или при заступлении новой смены первой директивой,
которая должна быть исполнена, является данная директива.

Номер смены указывается для повышения ответственности операторского состава
за выполняемую работу.

Сообщение системы на директиву:

* `ЕСТЬ` — подтверждение выполнения директивы.

Примечание: проверка заданного номера смены осуществляется по директиве
`СМЕ` без параметров.

Пример:

```
СМЕ 4
   ЕСТЬ
```

С помощью директивы операционной системе указано, что в данный момент ЭВМ
обслуживает смена операторов номер четыре.

Латинский вариант: `CRP <N СМЕНЫ>`.

#### 4.1.2. Директива `ДАТ[А] <ЧИСЛО> <МЕСЯЦ>`

/О/. Директива предназначена для указания ОС текущей даты.

| Параметр   | Значение |
|------------|----------|
| `<ЧИСЛО>`  | Текущее число месяца (от 1 до 31). |
| `<МЕСЯЦ>`  | Текущий месяц (от 1 до 12). |

Каждый из вышеуказанных параметров следует набирать двузначным числом через
пробел или без пробела, например: `ДАТ 03 04` или `ДАТ0304`.

Дата необходима для нормального функционирования системы.

Сообщения системы на директиву:

* `<ДАТА> ВРЕМЯ:<ВРЕМЯ>` — сообщение позволяет проконтролировать
  правильность задания даты;
* `ДАЙ СМЕ` — сообщение указывает на необходимость исполнения директивы
  `СМЕ <N СМЕНЫ>`.

Директива задается только после исполнения директивы `СМЕ <N СМЕНЫ>`.

Примечание: в директиве год не указывается, поскольку представляет собой
параметр генерации системы. Задание данного параметра производится в блоке
"ГЕНС" диалоговой программы "СЕРП".

Латинский вариант: `DAT <ЧИСЛО> <МЕСЯЦ>`.

#### 4.1.3. Директива `ВРЕ[МЯ] <ВРЕМЯ>`

/О/. Директива предназначена для занесения в систему астрономического
времени и его коррекции.

| Параметр   | Значение |
|------------|----------|
| `<ВРЕМЯ>`  | Астрономическое время (ч, мин) на момент исполнения данной директивы (задается в виде "ЧЧММ"). |

По директиве после перевызова ОС производится установка системных часов в
начальное состояние с последующей выдачей признака для программы-планировщика,
разрешающего выбор задач в решение.

Подсчет времени внутри системы выполняется программным способом.

Сообщения системы на директиву:

* `ДАТА:<ДАТА> ВРЕМЯ:<ВРЕМЯ>` — сообщение позволяет проконтролировать
  правильность задания параметров даты и времени;
* `ДАЙ [СМЕ] И/ИЛИ [ДАТ]` — сообщение указывает на необходимость исполнения
  директивы `СМЕ <N СМЕНЫ>` и/или `ДАТ <ЧИСЛО> <МЕСЯЦ>`;
* `ОШВР` — параметры заданного времени превышают допустимые границы (для
  часов больше 24, для минут больше 60).

В сообщении на директиву следует обратить внимание на дату. Если дата не
соответствует действительной, то следующей должна быть исполнена директива
`ДАТ` (см. 4.1.2).

Примечание 1: до директивы `ВРЕ <ВРЕМЯ>` разрешается задавать директивы
`СМЕ`, `ДАТ`, `ДАЙ (НЕТ) СТОП`, `ДАЙ (НЕТ) СПЕЦ`, `ДАЙ (НЕТ) СТК`,
`ДАЙ (НЕТ) АРХ`.

Пример:

```
ВРЕ 1109
 ДАТА:13.06.82 ВРЕМЯ: 11.09.00
```

В первой строке задана директива, во второй строке сообщение на данную
директиву — в сообщении указана текущая дата (11.06.82) и время, занесенное
в систему после исполнения директивы `ВРЕ <ВРЕМЯ>`.

Латинский вариант: `TIM <ВРЕМЯ>`.

### 4.2. Директивы установки режимов на ЭВМ

#### 4.2.1. Директива `КВА[НТ]`

/О/. Директива предназначена для отмены режима МИН и установки режима
квантования процессорного времени по всем программным каналам.

В режиме квантования время ЦП распределяется между задачами, находящимися в
решении. Каждой задаче выделяется определенный квант времени, отсчитываемый
в относительных единицах и варьируемый от 0 до 177 (1 единица = 200 мсек).
Отработав свой квант времени, задачи становятся в конец очереди задач,
ожидающих момента, когда им будет выделен новый квант времени. Таким
образом, операционная система постоянно уделяет время каждому пользователю.
Это время может быть небольшим (меньше секунды), но этого времени, как
правило, достаточно, чтобы у абонента за терминалом сложилось впечатление
монопольного использования ЭВМ.

Сообщение системы на директиву:

* `ЕСТЬ` — подтверждение выполнения директивы.

Отмена режима квантования и установка режима "МИН" в соответствующих классах
задач выполняется с помощью директивы `МИН [<N КЛАССОВ>]`.

Латинский вариант: `QUA`.

#### 4.2.2. Директива `МИН [<N КЛАССОВ>]`

/О/. Директива предназначена для отмены режима квантования и установки
режима "МИН" в указанных классах задач.

| Параметр       | Значение |
|----------------|----------|
| `<N КЛАССОВ>`  | Номера классов, для которых устанавливается режим "МИН" (классы указываются через пробел, от 0 до 7). |

В классах, для которых установлен режим "МИН", в первую очередь выполняются
задачи с минимальным временем, оставшимся до конца решения.

Сообщение системы на директиву:

* `ЕСТЬ` — подтверждение выполнения директивы.

Если режим МИН необходимо задать для 0–3 класса (стандартное задание МИН),
достаточно исполнить данную директиву без параметров.

После вызова системы автоматически устанавливается стандартный режим МИН.

Пример:

```
МИН 1 3 5 6
 ЕСТЬ
```

Для задач 1, 3, 5 и 6 класса установлен режим МИН.

Примечание: классы, для которых установлен режим МИН, указываются в
сообщении на директиву `РЕЖ`.

Латинский вариант: `MIN [<N КЛАССОВ>]`.

#### 4.2.3. Директивы `ДАЙ СТК`; `НЕТ СТК`

/О/. Директивы предназначены для установки и отмены на ЭВМ режима "СТК".

Установка режима "СТК" вызывает останов ЭВМ в момент возникновения
прерывания по контролю команды или по контролю числа с сохранением
содержимого всей памяти. В дальнейшем инженеры могут проанализировать
сбойную ситуацию и определить возможную неисправность.

Сообщение системы на директиву:

* `ЕСТЬ` — подтверждение выполнения директивы.

Примечание: наличие режима "СТК" определяется по директиве `РЕЖ`.

Латинский вариант: `ONL СТК`; `OFF СТК`.

#### 4.2.4. Директивы `ДАЙ СТО[П]`; `НЕТ СТО[П]`

/О/. Директива предназначена для установки или отмены на ЭВМ режима "СТОП".

В режиме "СТОП" программе-планировщику устанавливается признак запрета
выбора задач в решение с буфера ввода.

Обычно данный режим задается перед обнулением машины или когда надо
обеспечить монопольную обработку задачи, находящейся в решении.

Сообщения системы на директиву:

* `ЕСТЬ` — установлен режим "СТОП";
* `ЕСТЬ` — отменен режим "СТОП".

Пример:

```
ДАЙ СТОП
ЕСТЬ
```

На ЭВМ установлен режим "СТОП".

Примечание: наличие режима "СТОП" определяется по директиве `РЕЖ`.

Латинский вариант: `ONL СТО`; `OFF СТО`.

#### 4.2.5. Директивы `ДАЙ СПЕ[Ц]`; `НЕТ СПЕ[Ц]`

/О/. Директива предназначена для установки или отмены на ЭВМ режима
"СТОП СПЕЦ".

В данном режиме с буфера ввода в решение выбираются те задачи, для которых
исполнена директива `СПЕ <N ЗАДАЧИ НА БУФЕРЕ ВВОДА>`.

Существуют следующие отличия режима "СТОП" от режима "СТОП-СПЕЦ":

* в режиме "СТОП" запрещается выбор задач в решение; в режиме "СТОП-СПЕЦ"
  разрешается выбор в решение только тех задач, для которых исполнена
  директива `СПЕ <N ЗАДАЧИ НА БУФЕРЕ ВВОДА>`;
* в режиме "СТОП" запрещается формирование диалоговых задач на буфере ввода
  после их вызова с терминала; в режиме "СТОП-СПЕЦ" — разрешается.

Сообщения на директиву:

* `ЕСТЬ` — установлен режим "СТОП СПЕЦ";
* `ЕСТЬ` — отменен режим "СТОП СПЕЦ".

Если после выполнения директивы вызова диалоговой задачи на экран терминала
выдалось сообщение `СТОП:<N ЗАДАЧИ НА БУФЕРЕ ВВОДА>`, то это означает:
1) заданная диалоговая задача сформировалась на буфере ввода; 2) на ЭВМ
установлен режим "СТОП-СПЕЦ".

Если директиву задать в режиме "СТОП", то на ЭВМ будет установлен режим
"СТОП-СПЕЦ".

Примечание 1: наличие режима "СТОП-СПЕЦ" определяется по директиве `РЕЖ`.

#### 4.2.6. Директивы `ДАЙ ДИА`; `НЕТ ДИА`

/О/. Директивы служат для установки или отмены диалогового режима на ЭВМ.

Сообщения системы на директивы:

* `ЕСТЬ` — на ЭВМ установлен диалоговый режим;
* `ЕСТЬ` — на ЭВМ отменен диалоговый режим.

При установке запрета диалогового режима на все терминалы, занятые задачей,
выдается сообщение `ЗАКАНЧИВАЙТЕ РАБОТУ`; при попытке вызова диалоговой
задачи на терминал выдается сообщение `ДИАЛГ ЗАКР`.

#### 4.2.7. Директивы `ДАЙ ОТЛ`; `НЕТ ОТЛ`

/О/. Директивы предназначены для установки и отмены на ЭВМ отладочного
режима.

В отладочном режиме программе-планировщику разрешается выбрать в решение
только одну фоновую задачу (заказанное время больше 10 минут), а по
остальным программным каналам в решение выбираются отладочные задачи.

Сообщение системы на директивы:

* `ЕСТЬ` — подтверждение выполнения директивы.

Латинский вариант: `ONL ОТЛ`; `OFF ОТЛ`.

### 4.3. Информационные директивы

#### 4.3.1. Директива `ВЦП [<ПАРАМЕТР>]`

/ОП/. Директива предназначена для получения оперативных сведений о ходе
решения задач.

`<ПАРАМЕТР>` = `П` / `Р` / `Т` / `<N ПР.КАНАЛА>`

| Параметр          | Значение |
|-------------------|----------|
| `П`               | Выдать информацию о всех задачах, находящихся в решении. |
| `Т`               | Выдать информацию о всех решаемых задачах с разделом "ТЕЛЕ" (о всех диалоговых задачах). |
| `Р`               | Выдать информацию о заказанных и использованных (в данный момент времени) ресурсах каждой решаемой задачи. |
| `<N ПР.КАНАЛА>`   | Выдать информацию о ходе решения задачи по указанному программному каналу (номер программного канала от 1 до 57). |

Примечание: присутствие в директиве знака "+" после параметров указывает на
3-ий режим.

Сообщение на директиву `ВЦП П` представлено в виде последовательности строк
(количество строк зависит от числа задач, находящихся в решении); в каждой
строке содержится следующая информация:

* физический номер терминала (отсутствие номера указывает на выполнение
  задачи без участия средств телеобработки);
* шифр задачи;
* номер программного канала (номер решаемой задачи внутри операционной
  системы);
* номер программного канала, по которому выполняется главная задача.
  Выдается только для подчиненных задач;
* время, затраченное ЦП на решение задачи пользователя к моменту выполнения
  директивы;
* время, оставшееся до завершения задачи на момент выполнения директивы;
* номер класса (от 0 до 8), к которому относится задача. Выдается только на
  терминал оператора;
* квант времени центрального процессора, выделяемый задаче. Выдается только
  на терминал оператора;
* идентификатор магнитного накопителя (МГ — накопитель на магнитной ленте;
  МД — накопитель на магнитных дисках), номер накопителя и номер бобины,
  участвующие в данный момент в обмене с задачей (если задача не участвует
  в обмене с внешней памятью, то данная часть сообщения отсутствует; если у
  накопителя выключено питание, то вместо номера бобины печатается "ВЫКЛ").
  Выдается только на терминал оператора.

Пример:

```
    404040000000 01 00.02.45  00.07.14  2 020
    430002000000 02 00.00.56  00.05.04  2 020
    521000000000 10 00.01.00  00.01.00  4 100
07  146800000000 13 00.03.57  00.11.02  5 120 МГ 42-0063
33  419999135790 16 00.00.04  00.19.55  6 120
```

В данный момент в решении находятся 4 задачи: по 1, 2, 10 и 13 программному
каналу.

По 1-ому каналу в течение 2 мин. 45 сек. решается задача с шифром
404040000000. До завершения задачи осталось 7 мин. 14 сек. Квант времени =
020, номер класса 2.

Аналогично интерпретируется текст выдачи для 2, 10 и 13 программного канала
с той лишь разницей, что для задачи по 13 программному каналу указан номер
терминала и устройство (МГ 42 с бобиной 0063), участвующие в операции
обмена.

Пример:

```
   577980000000 01    00.23.07 00.36.52  0 040 МГ43 ВЫКЛ
07 521000000000 15 17 00.00.20 00.00.20  5 060
   419999135790 17    00.00.10 00.19.49  6 120
```

В данном примере приведена диагностика при отключении питания магнитного
накопителя (магнитофон 43), закрепленного за задачей с шифром 577980000000,
и общее изменение формата сообщения на директиву в случае выполнения
подчиненной задачи. Шифр подчиненной задачи 521000000000. Ее главная задача
имеет шифр 419999135790 и находится в решении по 17 программному каналу.

По директиве `ВЦПТ` выдается информация только о терминальных задачах. Если
задача многотерминальная, то над ее строкой в сообщении "ВЦПП" указываются
физические номера терминалов, подключенных к данной задаче.

Пример:

```
11  234500000000 15 00.00.11  00.00.10
    13 17 20 24
05  419900000005 16 00.00.30  00.00.10
```

В данный момент в решении две терминальных задачи. К задаче с шифром
234500000000 подключен терминал с физическим номером 11; за задачей с шифром
419900000005 закреплены терминалы со следующими физическими номерами: 5, 13,
17, 20, 24.

Сообщение на директиву `ВЦП Р` включает в себя сообщение на директиву
`ВЦП П` плюс дополнительная информация о заказанных и использованных
ресурсах задачи:

```
<"ВЦПП"> <ЗАК.ОЗУ>:<ИСП.ОЗУ> <ЗАК.ТРАКТЫ>:<ИСП.ТРАКТЫ>
```

| Поле             | Значение |
|------------------|----------|
| `<ЗАК.ОЗУ>`      | Число листов основной памяти, заказанных в паспорте задачи. |
| `<ИСП.ОЗУ>`      | Число листов основной памяти, используемых задачей в данный момент. |
| `<ЗАК.ТРАКТЫ>`   | Число трактов, заказанных в паспорте задачи. |
| `<ИСП.ТРАКТЫ>`   | Число трактов, используемых задачей в данный момент. |

Пример:

```
583900000000 01 00.00.16  00.04.43  32:23  064:010
620200000000 02 00.00.00  00.05.00  24:03  064:001
```

В паспорте задачи с шифром 583900000000 заказано 32 листа оперативной
памяти и 64 тракта, а используется в данный момент 23 листа ОЗУ и 10
трактов. Для задачи с шифром 620200000000 заказано 24 листа ОЗУ и 64 тракта;
используется 3 листа ОЗУ и 1 тракт.

Директива `ВЦП <N ПР.КАНАЛА>` позволяет получить информацию о ходе решения
задачи по указанному программному каналу.

Если в момент исполнения директивы `ВЦП <N ПРОГР.КАНАЛА>` задача производила
обмен с внешними устройствами, то над строкой "ВЦПП" выдается одно из
следующих сообщений:

* `МГ-<N УСТ-ВА> ЕС / <КОМАНДА ОБМЕНА>` — при обмене с магнитным
  накопителем ЕС-5025;
* `МД-<N УСТ-ВА> <N БОБ>: <N ТЕКУЩ.ЗОНЫ> [ВЫКЛ]` — при обмене с
  накопителем на магнитных дисках.

| Поле                 | Значение |
|----------------------|----------|
| `<N УСТ-ВА>`         | Физический номер устройства, участвующего в обмене. |
| `<N БОБ>`            | Номер ленты или пакета на указанном устройстве. |
| `ВЫКЛ`               | Указание на отключение питания или перевод устройства в автономный режим. |
| `<КОМАНДА ОБМЕНА>`   | `ЗП` / `ЧТ` / `ФАЙЛ.В` / `ФАЙЛ.Н` / `ПЕРЕМ` / `ЗП.МГЗ` |

| Команда    | Значение |
|------------|----------|
| `ЗП`       | Осуществляется прием данных из ЭВМ и передача их в указанный НМЛ. |
| `ЧТ`       | Принимаются данные из НМЛ и передаются в ЭВМ. |
| `ФАЙЛ.В`   | Лента перематывается вперед до первого межзонного промежутка после маркера группы зон. Примечание: группы зон могут разделяться так называемым маркером группы зон. Этот маркер представляет собой однобайтовую зону с одной строкой продольного контроля; маркер группы зон иногда называют маркером ленты. |
| `ПЕРЕМ`    | Выполняется перемотка ленты назад до маркера начала ленты. Примечание: маркер начала ленты служит для предупреждения о приближении края ленты. |
| `ЗП.МГЗ`   | Вырабатывается байт маркера группы зон и строка продольного контроля, которые передаются из ЭВМ в указанный НМЛ для их записи (см. "ФАЙЛ.В"). |

Если задача не участвует в операции обмена с внешней памятью, то сообщение
на данную директиву аналогично сообщению на директиву `ВЦПП`.

Директива `ВЦП` без параметров служит для получения информации о решении
задач по 1–4 программному каналу, т. е. о ходе решения счетных (фоновых)
задач.

Директива `ВЦП` без параметра, заданная через символ "обратная косая черта"
с терминала, занятого задачей, позволяет получить информацию о состоянии
данной диалоговой задачи.

Примечание: если при многократной выдаче сообщения на директиву текущая зона
остается без изменений, то это указывает на выключение накопителя или на
реверс ленты (операция чтения или записи не выполняется, например, из-за
дефектов на носителе или нарушения юстировки магнитной головки).

Латинский вариант: `CPT [<N ПРОГРАММНОГО КАНАЛА>]`.

#### 4.3.2. Директива `КТО`

/О/. Директива `КТО` предназначена для вывода следующей справочной
информации о задачах, находящихся в решении: шифр, фамилия пользователя,
номер стандартного паспорта, ключ (имя) диалоговой задачи.

Сообщение на директиву:

```
[<N ТЕРМ>] <ШИФР> <N ПР.КАНАЛА> <ФИО> [<N СТ.ПАСП>] [<КЛЮЧ>]
```

| Поле              | Значение |
|-------------------|----------|
| `<N ТЕРМ>`        | Физический номер терминала, закрепленного за задачей. |
| `<ШИФР>`          | Шифр пользователя. |
| `<N ПР.КАНАЛА>`   | Номер программного канала, по которому выполняется программа пользователя. |
| `<ФИО>`           | Фамилия, имя и отчество пользователя (если фамилия состоит больше чем из 10 букв, то имя и отчество не указывается). |
| `<N СТ.ПАСП>`     | Номер стандартного паспорта (если задача не использует стандартный паспорт, то выдаются пробелы). |
| `<КЛЮЧ>`          | Ключ (имя) диалоговой задачи. |

Пример:

```
    587100000000 01 ХАПАЕВ       ЗС2
43  190200000000 13 ГОРБАТОВ     З35  ДЖИН
07  419999125790 17 ОС ДИСПАК    ЗСК  УПО
```

Фамилия владельца задачи с шифром 587100000000 — Хапаев; с шифром
190200000000 — Горбатов; задача с шифром 419999125790 относится к классу
задач, запущенных под именем "ОС Диспак" (данное имя определяют первые 4
цифры шифра — 4199). Задача по 1 программному каналу выполняется в пакетном
режиме и имеет стандартный паспорт ЗС2. Задачи по 13 и 17 программному
каналу работают в режиме диалога (взаимодействие пользователя с ЭВМ
осуществляется через терминалы 43, 07). Их заказанные паспорта — З35, ЗСК,
а ключи — ДЖИН и УПО.

#### 4.3.3. Директива `АДР[ЕС] <АДРЕС ЯЧЕЙКИ>`

/ОП/. Директива `АДР` предназначена для выдачи содержимого указанной ячейки
физической памяти.

| Параметр           | Значение |
|--------------------|----------|
| `<АДРЕС ЯЧЕЙКИ>`   | Адрес ячейки, содержимое которой предполагается выдать по директиве. |

Сообщение системы на директиву:

```
<АДРЕС>:<СОДЕРЖИМОЕ ЯЧЕЙКИ>
```

| Поле                      | Значение |
|---------------------------|----------|
| `<АДРЕС>`                 | Адрес ячейки, указанный в директиве (от 0 до 77777). |
| `<СОДЕРЖИМОЕ ЯЧЕЙКИ>`     | Содержимое указанной ячейки. |

Пример:

```
АДР 74412
    77412 : 0000111000000000
```

Содержимое физической ячейки с адресом 77412 равно 000111000000000.

Латинский вариант: `ADR <АДРЕС ЯЧЕЙКИ>`.

#### 4.3.4. Директива `СМЕ[НА]`

/О/. Директива позволяет получить номер смены операторов, обслуживающей
машину, и некоторую другую информацию, характеризующую эффективность
использования ЭВМ.

Сообщение выдается в виде строки и содержит следующую информацию:

```
СМ<N СМЕНЫ>П: <ВРЕМЯ ПРОСТОЯ ЦП> ЭВМ-<N МАШИНЫ> <ДАТА> ВРЕМЯ: <ВРЕМЯ> <ВРЕМЯ ЖИЗНИ ОС>
```

| Поле                   | Значение |
|------------------------|----------|
| `<N СМЕНЫ>`            | Номер смены операторов. |
| `<ВРЕМЯ ПРОСТОЯ ЦП>`   | Время простоя центрального процессора, отсчитываемое от момента вызова системы (ч, мин). |
| `<N МАШИНЫ>`           | Номер ЭВМ в комплексе. |
| `<ДАТА>`               | Дата (число, месяц, год). |
| `<ВРЕМЯ>`              | Астрономическое время исполнения директивы `СМЕ` (ч, мин, сек). |
| `<ВРЕМЯ ЖИЗНИ ОС>`     | Время, отсчитываемое от начала вызова операционной системы (ч, мин). |

Примечание: директива `СМЕ` выполняется автоматически с периодом в 15 минут.

Латинский вариант: `CRP`.

#### 4.3.5. Директива `УСТ [<N КЛАССА>]`

/О/. Директива `УСТ` предназначена для выдачи списка номеров магнитных лент
и дисковых пакетов, которые требуется установить на магнитные накопители
для включения задач в решение.

| Параметр      | Значение |
|---------------|----------|
| `<N КЛАССА>`  | Номер класса, для задач которого исполняется директива `УСТ`. |

Существует возможность получения информации о магнитных носителях отдельно
для каждого класса задач. Для этого в директиве `УСТ` задается номер класса.

Пример:

```
УСТ0
```

Выдать номера всех лент и пакетов, которые требуются для задач 0-ого класса.

Сообщения на директиву:

* `<N КЛАССА>:<ЧИСЛО Г.З-Ч> [<N БОБИН>]` — установить на накопители
  указанные бобины для заданного класса задач;
* `ЗНЕТ` — на буфере ввода нет задач.

| Поле               | Значение |
|--------------------|----------|
| `<N КЛАССА>`       | Номер класса задачи. |
| `<ЧИСЛО Г.З-Ч>`    | Число задач в классе, уже готовых к решению. |
| `<N БОБИН>`        | Номера бобин, которые требуются задаче (знак "+" означает, что бобина установлена). |

Каждая строка сообщения дает информацию о бобинах одной задачи. После
исполнения директивы `УСТ` без параметра выдается информация о 10 задачах,
начиная с задач более приоритетных классов.

Пример:

```
УСТ
 УСТ2:01  +2048   0063
 УСТ2:01  +2048  +2119  0004
```

Для задач 2-ого класса необходимо установить бобины 63 и 4. Бобины 2048,
2119 уже установлены. Одна задача второго класса готова к решению и не
входит в решение из-за отсутствия системных ресурсов.

Если в сообщении на директиву указаны бобины, которые необходимо установить
для задач, то автоматически инициируется выдача свободных накопителей на
терминал оператора.

Латинский вариант: `SET [<N КЛАССА>]`.

#### 4.3.6. Директива `СВМ`

/О/. Директива `СВМ` предназначена для выдачи сообщения, в котором
указываются номера магнитофонов (НМЛ), не закрепленных ни за одной из
решаемых задач и задач, находящихся на буфере ввода.

Сообщение на директиву:

```
СВМ <N ЭВМ> <N УСТ-ВА>
```

| Поле          | Значение |
|---------------|----------|
| `<N ЭВМ>`     | Номер ЭВМ, на которой исполнена директива. |
| `<N УСТ-ВА>`  | Физические номера свободных магнитофонов (от 30 до 67). |

Пример:

```
СВМ
 СВМ 3 62 64
```

После задания директивы (первая строка) выдается сообщение (2-я строка) о
свободных магнитофонах на ЭВМ 3. В данный момент ленты можно установить на
накопители с номерами 62 и 64.

Латинский вариант: `VST`.

#### 4.3.7. Директива `СВД`

/О/. Директива `СВД` предназначена для получения сообщения, в котором
указываются номера накопителей на магнитных дисках (НМД), не закрепленных ни
за одной из решаемых задач.

Сообщение на директиву:

```
СВД <N ЭВМ> <N УСТ-В>
```

| Поле          | Значение |
|---------------|----------|
| `<N ЭВМ>`     | Номер ЭВМ, на которой исполнена директива `СВД`. |
| `<N УСТ-В>`   | Физические номера свободных НМД (от 00 до 77). |

Латинский вариант: `VCD`.

#### 4.3.8. Директива `НОМ[ЕР] [<ШИФР>]` или `[<ЧИСЛО>]`

/ОП/. Директива `НОМ` позволяет выяснить номер задачи на буфере ввода.

| Параметр   | Значение |
|------------|----------|
| `<ШИФР>`   | Первые 4 цифры шифра задачи, для которой нужно определить номер на буфере ввода (для любого большего набора воспринимаются первые 4 цифры). |
| `<ЧИСЛО>`  | Число, которое, будучи умноженным на 10 (восьмер.), даст координату на буфере ввода, начиная с которой выводится информация о первых восьми задачах. |

После ввода задача попадает на буфер, где ей присваивается внутренний
номер — номер задачи на буфере ввода. Используя данный номер в директиве
`СКВ <N ЗАДАЧИ НА БУФЕРЕ ВВОДА>`, можно определить текущее состояние
соответствующей задачи.

Сообщения системы на директиву:

```
<ШИФР> <N З-ЧИ НА БУФ.ВВОДА>
```

| Поле                      | Значение |
|---------------------------|----------|
| `<ШИФР>`                  | Шифр задачи, указанный в директиве. |
| `<N З-ЧИ НА БУФ.ВВОДА>`   | Искомый номер задачи на буфере ввода. |

* `ЗНЕТ` — задача с указанным шифром отсутствует на буфере ввода.

Пример:

```
НОМ 5210
 521000000000 010
 521000000000 015
```

В момент исполнения директивы `НОМ 5210` на буфере ввода находятся две
задачи с указанным шифром. Их номера на буфере ввода соответственно 10, 15.

По директиве `НОМ` без параметров выдается информация о первых восьми
задачах с меньшими номерами, расположенных на буфере ввода.

Латинский вариант: `NUM [<ШИФР>]` или `[<ЧИСЛО>]`.

#### 4.3.9. Директива `СКВ [<N ЗАДАЧИ НА БУФЕРЕ ВВОДА>]`

/ОП/. Директива `СКВ` предназначена для выдачи информации о текущем
состоянии задачи.

Если задача находится на буфере ввода, то возможны сообщения следующего
вида:

```
П<ПОРЯДОК В ОЧЕРЕДИ> <N КЛАССА>  КЛ
  <ПРИЧИНА>
```

| Поле                    | Значение |
|-------------------------|----------|
| `<N КЛАССА>`            | Номер класса, к которому принадлежит задача (от 0 до 8). |
| `<ПОРЯДОК В ОЧЕРЕДИ>`   | Порядок задачи в очереди на выполнение для класса, указанного в данном сообщении. |
| `<ПРИЧИНА>`             | Причина, по которой задача не выбирается в решение. |

`<ПРИЧИНА>` = `НЕ ЗАД.КАН` / `ЗКАН` / `РЕС.<ТИП РЕСУРСОВ>` / `СТОП` /
`НЕТ Б<N БОБИН>` / `ЗАНЯТ Б<N БОБИН>` / `ЗАПР.АРХ`

| Причина                 | Значение |
|-------------------------|----------|
| `ЗКАН`                  | Заняты все программные каналы, выделенные данному классу. |
| `РЕС.<ТИП РЕСУРСОВ>`    | Задача не входит в решение из-за недостатка указанных системных ресурсов. |
| `НЕ ЗАД.КАН`            | Данному классу задач не выделены программные каналы. |
| `НЕТ Б <N БОБИН>`       | Бобины с указанными номерами не установлены на накопителях; требуемые бобины заказаны в паспорте данной задачи. |
| `ЗАНЯТ Б<N БОБИН>`      | Указанные бобины заняты другими задачами. |
| `СТОП`                  | На ЭВМ установлен режим "СТОП". |
| `ЗАПР.АРХ`              | Архивная система запрещает включение задач в решение. |

`<ТИП РЕСУРСОВ>` = `ОЗУ` / `ТРАКТЫ` / `СЕГМ`

| Тип        | Значение |
|------------|----------|
| `ОЗУ`      | В данный момент система не может предоставить задаче затребованных ресурсов оперативной памяти (листов ОЗУ). |
| `ТРАКТЫ`   | В данный момент система не может предоставить задаче затребованных ресурсов по трактам. |
| `СЕГМ`     | В данный момент система не может предоставить задаче затребованных ресурсов по сегментам (по кускам) МД. |

* `ЗНЕТ` — задача с указанным номером отсутствует на буфере ввода.

Если задача находится в решении, то выдается сообщение, аналогичное
сообщению на директиву `ВЦП <N ПРОГР.КАНАЛА>`.

По директиве `СКВ` без параметра выдается информация об общем состоянии
буфера ввода. Сообщение на данную директиву имеет следующий вид:

```
ТЕЛЕ:<КОЛ-ВО З-Ч С "ТЕЛЕ">, СЧЕТ:<КОЛ-ВО СЧЕТНЫХ З-Ч> (<КОЛ-ВО З-Ч СО "ЖДЕМ">)
```

| Поле                         | Значение |
|------------------------------|----------|
| `<КОЛ-ВО З-Ч С "ТЕЛЕ">`      | Количество задач на буфере ввода с разделом "ТЕЛЕ". |
| `<КОЛ-ВО СЧЕТНЫХ З-Ч>`       | Количество счетных (фоновых) задач на буфере ввода. |
| `<КОЛ-ВО З-Ч СО "ЖДЕМ">`     | Количество задач на буфере ввода с разделом "ЖДЕМ". |

Латинский вариант: `WHH [<N З-ЧИ НА БУФЕРЕ ВВОДА>]`.

#### 4.3.10. Директива `РЕЖ[ИМЫ]`

/О/. Директива `РЕЖ` позволяет получить информацию об установленных режимах
на ЭВМ.

Сообщения системы на директиву:

| Сообщение                  | Значение |
|----------------------------|----------|
| `МИН <N КЛАССОВ>`          | По указанным классам установлен режим МИН. |
| `КВАНТ`                    | По всем классам установлен режим квантования процессорного времени. |
| `СТОП <N ТЕРМ> <ВРЕМЯ>`    | На ЭВМ установлен режим "СТОП". |
| `СПЕЦ <N ТЕРМ> <ВРЕМЯ>`    | На ЭВМ установлен режим "СТОП СПЕЦ". |
| `СТК`                      | На ЭВМ установлен режим "СТК". |
| `ДИАЛГ ЗАКР`               | Запрещено включение диалоговых задач в решение. |
| `ОТЛ`                      | На ЭВМ установлен отладочный режим. |

где:

| Поле         | Значение |
|--------------|----------|
| `<ВРЕМЯ>`    | Время с момента исполнения директивы "СТОП" или "СТОП СПЕЦ". |
| `<N ТЕРМ>`   | Номер терминала, с которого исполнена директива "СТОП" или "СТОП СПЕЦ". |

Пример:

```
 МИН 0 1 2 3
 ОТЛ
```

На ЭВМ установлены следующие режимы: 1) "МИН" для 0, 1, 2, 3; 2) отладочный
режим.

Латинский вариант: `MOD`.

#### 4.3.11. Директива `ВЫД[АТЬ] <N ПРОГР.КАНАЛА>`

/О/. Директива `ВЫД` предназначена для вывода на алфавитно-цифровое
печатающее устройство (АЦПУ) информации, накопленной в процессе решения
задачи на буфере вывода.

| Параметр             | Значение |
|----------------------|----------|
| `<N ПРОГР.КАНАЛА>`   | Номер программного канала той задачи, для которой выполняется директива `ВЫД`. |

Иногда при решении многочасовых задач возникает необходимость вывода на
АЦПУ полученной информации, не дожидаясь окончания задачи. Для этой цели в
операционной системе Диспак используется директива `ВЫД <N ПРОГР.КАНАЛА>`.

Сообщение системы на директиву:

* `ЕСТЬ` — подтверждение выполнения директивы.

Латинский вариант: `OUT <N ПРОГРАММНОГО КАНАЛА>`.

#### 4.3.12. Директива `ПАК`

/О/. Директива `ПАК` предназначена для выдачи полной информации о всех
задачах, находящихся на буфере ввода и в решении, и печати таблицы
состояния всех магнитных накопителей, входящих в конфигурацию системы.
Указанная информация выводится на АЦПУ.

Сообщение на директиву:

* `ЕСТЬ` — подтверждение выполнения директивы.

После исполнения директивы `ПАК` по 2-му логическому каналу выводится
сообщение, подтверждающее формирование задачи ПАК.

#### 4.3.13. Директива `НАЙ <N БОБИНЫ>`

/ОП/. Директива `НАЙ <N БОБИНЫ>` используется для определения физических
номеров внешних устройств, на которых установлена запрашиваемая бобина.
Помимо адреса устройств в некоторых случаях выдается дополнительная
информация о запрашиваемой бобине.

| Параметр       | Значение |
|----------------|----------|
| `<N БОБИНЫ>`   | Номер запрашиваемого дискового пакета или ленты. |

Директиву рекомендуется выполнять перед установкой бобины на накопитель, с
тем чтобы предупредить ситуацию присутствия на ЭВМ носителей с одинаковыми
номерами. Директива также информирует оператора о наличии бобины на внешнем
устройстве.

Сообщение системы на директиву:

```
М<ИДЕН-Р УСТ-ВА> <N УСТ-ВА>-<N БОБИНЫ> [<ИДЕН-Р БОБИНЫ>], ...
```

| Поле                 | Значение |
|----------------------|----------|
| `<ИДЕН-Р УСТ-ВА>`    | `Г` — идентификатор накопителя на магнитных лентах; `Д` — идентификатор накопителя на магнитных дисках. |
| `<N УСТ-ВА>`         | Физический номер устройства, на котором установлена запрашиваемая бобина. |
| `<N БОБИНЫ>`         | Номер запрашиваемой бобины. |
| `<ИДЕН-Р БОБИНЫ>`    | `СИС` — признак системной бобины; `АРХ` — признак архивной бобины; `УПР` — признак бобины, принадлежащей упрятанной задаче. |

* `НЕТ` — запрашиваемая бобина не обнаружена.

Пример:

```
НАЙ 2053
  МД 40-2053 СИС, МД 44-2053
```

Первая бобина 2053, установленная на устройстве 40, имеет признак системной
бобины; вторая бобина 2053, установленная на устройстве 44, в данный момент
признака системной бобины не имеет.

Латинский вариант: не используется.

#### 4.3.14. Директива `НОМВ`

Директива `НОМВ` предназначена для просмотра очереди заявок на АЦПУ.

Сообщение на директиву `НОМВ`:

```
[<СОСТОЯНИЕ АЦПУ>]
<ШИФР> <N ЗАЯВКИ> <ОБЩ.ЧИСЛО ЗОН>[/<ОСТ.ЗОН>][А<N АЦПУ>][+], ...
```

где `<СОСТОЯНИЕ АЦПУ>` = `НЕТ А0` / `НЕТ А1` / `СБО А0` / `СБО А1`

| Поле                 | Значение |
|----------------------|----------|
| `НЕТ А<N УСТ-ВА>`    | Указанное АЦПУ отключено от системы с помощью директивы `НЕТ А<N УСТ-ВА>`. |
| `СБО А<N УСТ-ВА>`    | Зафиксирован сбой на указанном АЦПУ. Инициация устройства выполняется по директиве `ПОВ А<N УСТ-ВА>`. |
| `<ШИФР>`             | Шифр задачи (указываются только первые 6 цифр шифра). |
| `<N ЗАЯВКИ>`         | Номер заявки в очереди на буфере вывода (число заявок не может превышать 64). |
| `<ОБЩ.ЧИСЛО ЗОН>`    | Количество зон информации, которое должно быть выведено на АЦПУ. |
| `<ОСТ.ЗОН>`          | Количество зон, которое осталось вывести на АЦПУ. |
| `А<N АЦПУ>[+]`       | Номер АЦПУ, на которое намечается выдача; знак "+" указывает, что на данное АЦПУ уже производится выдача. |

Примечание: приоритет заявок на выдачу соответствует порядку расположения
их в сообщении.

Пример:

```
419918  10  001
101200  20  002
555555  07  010/003  А1+
```

В первом столбце указаны шифры задач, ожидающих выдачу на АЦПУ. Во 2-ом
столбце — номер в очереди на буфере вывода; в третьем — число зон для
выдачи. В 4-ом столбце для тех задач, от имени которых уже происходит
выдача, указывается число оставшихся зон (для задачи с шифром 555555
осталось выдать 3 зоны на АЦПУ номер 1).

<ЛАБ><ЭКСПР><ДЕЖУР><ЛИМИТ><БУМАГА><ЗАХОДЫ>
```

| Поле         | Значение |
|--------------|----------|

| `<ЭКСПР>`    | Количество экспрессного времени. |
| `<ДЕЖУР>`    | Количество дежурного времени. |

#### 4.3.16. Директивы `ДИС`; `ЛЕН`

/ОП/. Директива предназначена для выдачи на терминал информации о магнитных

### 4.4. Директивы управления задачами

#### 4.4.1. Директивы `ПРТ [<КВАНТ>] <N ПРОГР.КАНАЛА>`; `ОСТ <N ПРОГР.КАНАЛА>`

/О/. Директивы позволяют изменить квант и класс задачи, находящейся в
решении.

| Параметр             | Значение |
|----------------------|----------|
| `<КВАНТ>`            | Квант, который присваивается задаче (от 0 до 177). |
| `<N ПРОГР.КАНАЛА>`   | Номер программного канала, для которого меняется квант (от 1 до 17). |

При мультипрограммировании время ЦП распределяется между задачами,
находящимися в решении. Чтобы осуществить такое распределение, время
процессора для каждой задачи разбивается на интервалы. Такой интервал
времени называется квантом.

В зависимости от класса задачи, выбранной в решение, центральному
процессору назначается определенный квант времени. Чем больше квант
времени, тем больше процессорного времени выделяется задаче. Если для
решаемой задачи с помощью директивы устанавливается квант, равный нулю, то
задача останавливается до тех пор, пока не будет задан квант, отличный от
нуля.

С помощью директивы `ПРТ <N ПРОГР.КАНАЛА>` задаче по указанному
программному каналу присваивается значение кванта, равное 100 (класс
остается без изменений).

Директива `ОСТ <N ПРОГР.КАНАЛА>` служит для останова задачи по указанному
программному каналу, т. е. для присвоения задаче кванта, равного нулю.

Сообщения системы на директиву:

* аналогично сообщению на директиву `ВЦП <N ПРОГР.КАНАЛА>`;
* `НЕТ` — сообщение указывает на невыполнение директивы; причина: в момент
  задания директивы задача производила обмен информацией с внешней памятью
  на НМЛ или НМД.

Пример:

```
ПРТ  177  06
  419979000000  06  00.00.15  00.00.15  5  177
```

Задаче по 6-ому программному каналу присвоен квант 177.

Перевод задачи из одного класса в другой осуществляется по директиве с
добавлением двух параметров:

```
ПРТ <КОД> <N КЛАССА> <КВАНТ> <N ПРОГ.КАНАЛА>
```

| Параметр       | Значение |
|----------------|----------|
| `<КОД>`        | Специальный код (код назначается разработчиками ОС и в общем случае равен 51). |
| `<N КЛАССА>`   | Номер класса, в который переводится задача. |

Латинский вариант: `PRT <КВАНТ> <N ПРОГР.КАНАЛА>`.

Примечание: для перевода задачи в режим реального времени (восьмой класс)
при задании директивы код = 53, класс = 7.

#### 4.4.2. Директива `ВКН <N ПРОГР.КАНАЛА>`

/О/. Директива предназначена для принудительного окончания задачи,
находящейся в решении.

| Параметр             | Значение |
|----------------------|----------|
| `<N ПРОГР.КАНАЛА>`   | Номер программного канала той задачи, которую требуется принудительно снять с решения. |

После исполнения директивы происходит завершение задачи и формирование
аварийной распечатки на АЦПУ и терминал оператора.

Директива `ВКН <N ПРОГР.КАНАЛА>` позволяет снять задачу во время
выполнения операции обмена с внешней памятью на НМЛ и НМД.

#### 4.4.3. Директива `ВМГ <N УСТ-ВА>`

/О/. Директива `ВМГ` предназначена для принудительного окончания задачи,
участвующей в обмене с накопителями на магнитных лентах (задача завершается
по номеру устройства НМЛ, в отличие от директивы `ВКН <N ПРОГР.КАНАЛА>`,
где указывается номер программного канала).

| Параметр       | Значение |
|----------------|----------|
| `<N УСТ-ВА>`   | Физический номер устройства НМЛ (от 30 до 67). |

Сообщения на директиву:

* `ЕСТЬ` — подтверждение выполнения директивы;
* `НЕТ` — сообщение указывает на невыполнение директивы. Причина: 1) НМЛ
  находится в автономном режиме; 2) операция обмена с данным НМЛ не
  выполняется.

Директива применяется обычно при невозможности завершения операции обмена
на НМЛ, что, как правило, связано с плохим качеством поверхности магнитной
ленты или с нарушением юстировки магнитной головки устройства.

При завершении задачи по директиве в листинге задачи печатается сообщение:
`ОШИБКА МЛ`.

Пример:

```
ВМГ 60
 ЕСТЬ
```

Принудительно завершена задача, выполнявшая операцию обмена с МГ-60.

Латинский вариант: `DRT <N УСТ-ВА>`.

#### 4.4.4. Директива `ВМД <N УСТ-ВА>`

/О/. Директива `ВМД` предназначена для принудительного окончания задачи,
выполняющей обмен информацией с накопителями на магнитных дисках (НМД).

| Параметр       | Значение |
|----------------|----------|
| `<N УСТ-ВА>`   | Физический номер НМД (от 00 до 77). |

Сообщения на данную директиву аналогичны сообщениям на директиву `ВМГ`.

В листинге задачи, завершенной по директиве `ВМД`, печатается сообщение:
`ОШИБКА МД`.

Латинский вариант: `DDS <N УСТ-ВА>`.

#### 4.4.5. Директива `ВЫБ <N ЗАДАЧИ НА БУФЕРЕ ВВОДА>`

/О/. Директива `ВЫБ` позволяет исключить задачу из входной очереди буфера
ввода.

| Параметр                     | Значение |
|------------------------------|----------|
| `<N З-ЧИ НА БУФЕРЕ ВВОДА>`   | Номер исключаемой задачи на буфере ввода (от 1 до 377). |

После выполнения директивы `ВЫБ` вся информация о задаче аннулируется.

Сообщение на директиву:

```
ВЫБ <ШИФР> <N ТЕРМ>
```

| Поле         | Значение |
|--------------|----------|
| `<ШИФР>`     | Шифр исключаемой задачи. |
| `<N ТЕРМ>`   | Физический номер терминала, с которого была набрана директива. |

Пример:

```
ВЫБ 102
 ВЫБ 310023880000 Т33
```

Задача с номером 102 (шифр задачи 310023880000) исключается из входной
очереди буфера ввода; директива задана с терминала с номером 33.

Латинский вариант: `DEL <N З-ЧИ НА БУФЕРЕ ВВОДА>`.

#### 4.4.6. Директива `ПОР <N З-ЧИ НА БУФЕРЕ ВВОДА> <ПРИОРИТЕТ>`

/О/. Директива `ПОР` позволяет изменить порядок задач во входной очереди на
буфере ввода.

| Параметр                     | Значение |
|------------------------------|----------|
| `<ПРИОРИТЕТ>`                | Число от 1 до 77. |
| `<N З-ЧИ НА БУФЕРЕ ВВОДА>`   | Номер задачи на буфере ввода (от 1 до 177). |

Сообщение на директиву:

* `ЕСТЬ` — подтверждение выполнения директивы;
* `НЕТ` — сообщение указывает на невыполнение директивы. Причина: 1) задача
  с указанным номером отсутствует на буфере ввода; 2) номер задачи на
  буфере ввода больше 177.

Пример:

```
ПОР 15 1
 ЕСТЬ
```

После исполнения директивы задача с номером 15 на буфере ввода получит 1-ый
порядковый номер во входной очереди соответствующего класса.

Латинский вариант: `ORD <N З-ЧИ НА БУФЕРЕ ВВОДА> <ПРИОРИТЕТ>`.

#### 4.4.7. Директива `СПЕ[Ц] <N З-ЧИ НА БУФЕРЕ ВВОДА>`

/О/. Директива `СПЕЦ` обеспечивает пропуск задачи в решение, если на ЭВМ
установлен режим "СТОП-СПЕЦ".

| Параметр                     | Значение |
|------------------------------|----------|
| `<N З-ЧИ НА БУФЕРЕ ВВОДА>`   | Номер той задачи на буфере ввода, которой разрешается войти в решение, если на ЭВМ набран режим "СТОП-СПЕЦ". |

Сообщения на директиву:

* `ЕСТЬ` — подтверждение выполнения директивы;
* `ЗНЕТ` — задача с указанным номером отсутствует на буфере ввода.

При попытке вызова диалоговой задачи в режиме "СТОП-СПЕЦ" на экран
терминала, с которого задана директива, выдается сообщение:

```
СТОП: <N З-ЧИ НА БУФЕРЕ ВВОДА>
```

Номер задачи на буфере ввода, указанный в сообщении, используется в
директиве `СПЕЦ` для включения задачи в решение.

Латинский вариант: не существует.

#### 4.4.8. Директивы `УПР [<N ПРОГР.КАНАЛА>]`; `ВОС <N З-ЧИ НА БУФЕРЕ ВВОДА>`

/О/. Директива `УПР <N ПРОГР.КАНАЛА>` предназначена для упрятывания задач,
находящихся в решении, в область архива; директива
`ВОС <N З-ЧИ НА БУФЕРЕ ВВОДА>` — для восстановления и продолжения решения
задач, ранее упрятанных в архиве.

| Параметр                     | Значение |
|------------------------------|----------|
| `<N ПРОГР.КАНАЛА>`           | Номер программного канала задачи, которую требуется упрятать. |
| `<N З-ЧИ НА БУФЕРЕ ВВОДА>`   | Номер на буфере ввода упрятанной задачи. |

Возможность упрятывания и восстановления в операционной системе Диспак
реализована на основе архивно-файловой системы "АРФА". Число упрятываемых
задач лимитируется количеством зон, отведенных в архиве под данную работу.
В любой момент разрешается упрятывать только одну задачу. По завершению
процесса упрятывания разрешается упрятывание следующей задачи. Не
выполняется упрятывание задач с разделом "ТЕЛЕ", главных и подчиненных
задач.

Сообщение системы на директивы:

| Сообщение                                | Значение |
|------------------------------------------|----------|
| `ЗАКАЗ ПРИНЯТ`                           | Директива принята системой; производится анализ на возможность выполнения дальнейших действий. |
| `ИДЕТ УПР/ВОС`                           | Не закончена обработка ранее принятого заказа на упрятывание или восстановление задачи. |
| `НЕТ УПР/ВОС К<N ПРОГР.КАНАЛА>: <ПРИЧИНА>` | Указывается причина, по которой не выполняется процесс упрятывания. |
| `ДЛЯ УПР/ВОС УСТ.СРОЧНО ТОМ <N ТОМА>`    | Не установлен архивный том, предназначенный для упрятывания или восстановления задачи. Сообщение выдается по 2-ому логическому каналу. |
| `ЕСТЬ`                                   | Директива `ВОС <N З-ЧИ НА БУФЕРЕ ВВОДА>` принята к исполнению. |
| `ЗНЕТ`                                   | По программному каналу, указанному в директиве `УПР`, в данный момент отсутствует задача; по номеру задачи на буфере ввода, указанному в директиве `ВОС`, отсутствует задача или находится не упрятанная задача. |

После завершения процесса упрятывания по 2-ому логическому каналу выдается
сообщение:

```
УЗ(<N З-ЧИ НА БУФЕРЕ ВВОДА>) <ШИФР> L=<ДЛИНА ОБЛАСТИ>
```

Определение номеров на буфере ввода упрятанных задач производится с помощью
директивы `УПР` без параметров.

Сообщение на директиву `УПР` (без параметров):

```
СКВ УПРЗ : <СПИСОК НОМЕРОВ ЗАДАЧ НА БУФЕРЕ ВВОДА>
```

Пример:

```
УПР 15
  ЗАКАЗ ПРИНЯТ
  НЕТ УПР/ВОС К15: ТЕЛЕ ЗАДАЧА
```

В первой строке представлена директива `УПР`, по которой выполняется
упрятывание задачи по 15-ому программному каналу, во второй строке —
сообщение системы о принятии директивы `УПР <N ПРОГР.КАНАЛА>`, в третьей —
сообщение системы о невозможности упрятывания задачи по 15-ому программному
каналу ввиду наличия в ее паспорте раздела "ТЕЛЕ".

Латинский вариант: не используется.

### 4.5. Директивы управления внешними устройствами

#### 4.5.1. Директива `СБВ`

/О/. Директива `СБВ` предназначена для отказа от не полностью введенной
информации на буфер ввода.

Сообщение на директиву `СБВ`:

* `ЕСТЬ` — подтверждение выполнения директивы.

Латинский вариант: `CIN`.

#### 4.5.2. Директивы `ДАЙ <ИДЕНТ.УСТ-ВА>[<N УСТ-ВА>]`; `НЕТ <ИДЕНТ.УСТ-ВА>[<N УСТ-ВА>]`

/О/. Директива `ДАЙ` предназначена для подключения указанного внешнего
устройства к конфигурации системы; директива `НЕТ` — для отключения
указанного устройства от конфигурации системы.

| Параметр                   | Значение |
|----------------------------|----------|
| `<ИДЕНТИФИКАТОР УСТ-ВА>`   | `А` — алфавитно-цифровое печатающее устройство (номер устройства от 0 до 1). |
| `<N УСТ-ВА>`               | Физический номер устройства (указывается для АЦПУ). |

Директивы используются при проведении ремонтных и профилактических работ
соответствующих внешних устройств ввода-вывода.

Сообщение на директивы:

* `ЕСТЬ` — подтверждение выполнения директивы.

Латинский вариант: `ONL <ИДЕНТ.УСТ-ВА><N УСТ-ВА>`;
`NOT <ИДЕНТ.УСТ-ВА>[<N УСТ-ВА>]`.

#### 4.5.3. Директива `ПОВ [<ИДЕНТ.УСТ-ВА>][<N УСТ-ВА>]`

/О/. Директива `ПОВ` предназначена для продолжения операции вывода на
внешние устройства после их сбоя.

| Параметр                   | Значение |
|----------------------------|----------|
| `<ИДЕНТИФИКАТОР УСТ-ВА>`   | `А` — алфавитно-цифровое печатающее устройство (номер устройства от 0 до 1). |
| `<N УСТ-ВА>`               | Физический номер устройства (указывается для АЦПУ). |

После исполнения директивы `ПОВ` для устройств АЦПУ вывод информации
производится с начала той зоны буфера вывода, при выдаче которой
обнаружено, что данное устройство не готово к работе (для АЦПУ сбой
фиксируется по сообщению: `СБОЙ А<N УСТ-ВА>`).

Сообщение системы на директиву:

* `ЕСТЬ` — подтверждение выполнения директивы.

Директива `ПОВ` без параметров инициирует продолжение операции вывода для
всех вышеперечисленных устройств, на которых был зафиксирован сбой.

Латинский вариант: `REP [<ИДЕНТ.УСТ-ВА>][<N УСТ-ВА>]`.

#### 4.5.4. Директива `СБО [<ИДЕНТ.УСТ-ВА>][<N УСТ-ВА>]`

/О/. Директива `СБО` предназначена для перевода выдачи на свободное
(запасное) устройство вывода, а также для селективного сброса ленточного
канала типа ЕС.

| Параметр                   | Значение |
|----------------------------|----------|
| `<ИДЕНТИФИКАТОР УСТ-ВА>`   | `А` — алфавитно-цифровое печатающее устройство (номер устройства от 0 до 1); `К3` — ленточный канал номер 3 типа ЕС. |
| `<N УСТ-ВА>`               | Физический номер устройства (указывается только для АЦПУ). |

Примечание: директива `СБО` без параметров исключает все внешние устройства
вывода из конфигурации системы. Для обратного подключения к системе внешних
устройств вывода необходимо исполнить директиву
`ДАЙ <ИДЕНТ.УСТ-ВА> [<N УСТ-ВА>]`.

Пример: если устройство АЦПУ-1 неисправно, для перевода выдачи на АЦПУ-0
необходимо задать следующую последовательность директив:

```
СБОЙ А1
 ЕСТЬ
ДАЙ А0
 ЕСТЬ
```

Латинский вариант: `EME [<ИДЕНТ.УСТ-ВА>] [<N УСТ-ВА>]`.

#### 4.5.5. Директива `ПРО <ИДЕНТ.УСТ-ВА>[<N УСТ-ВА>]`

/О/. Директива `ПРО` отменяет выдачу на указанном устройстве вывода.

| Параметр                   | Значение |
|----------------------------|----------|
| `<ИДЕНТИФИКАТОР УСТ-ВА>`   | `А` — алфавитно-цифровое печатающее устройство (номер устройства от 0 до 1). |
| `<N УСТ-ВА>`               | Физический номер устройства (указывается только для АЦПУ). |

Перед выполнением директивы `ПРО` для АЦПУ необходимо имитировать сбой
данного устройства, например, кратковременным нажатием клавиши "ПРОГОН" на
его пульте управления.

Сообщение на директиву:

* `ЕСТЬ` — подтверждение выполнения директивы.

После выполнения директивы `ПРО` на АЦПУ выдается стандартная распечатка по
концу задачи.

Латинский вариант: `PAS <ИДЕНТ.УСТ-ВА>[<N УСТ-ВА>]`.

#### 4.5.6. Директива `ПУЛ[В] [<С КАКОГО УСТР>][<НА КАКОЕ УСТР>]`

/О/. Директива `ПУЛ` позволяет перевести сообщения системы на заданный
терминал оператора. Директива `ПУЛВ` переводит выдачи, предназначенные для
АЦПУ одной ЭВМ, на указанное АЦПУ другой ЭВМ, причем номер АЦПУ должен быть
указан на единицу больше.

| Параметр             | Значение |
|----------------------|----------|
| `<С КАКОГО УСТР>`    | Для директивы `ПУЛ` это физический номер терминала, с которого требуется перевести сообщения системы; для директивы `ПУЛВ` это номер очереди на АЦПУ, полученный по директиве `НОМВ`. |
| `<НА КАКОЕ УСТР>`    | Для директивы `ПУЛ` — физический номер терминала, на который требуется перевести сообщения системы; для директивы `ПУЛВ` — номер ЭВМ и номер АЦПУ, куда надо перевести выдачу (номер АЦПУ указывается на единицу больше). |

Сообщение системы на директиву:

* `ЕСТЬ` — подтверждение выполнения директивы;
* `Т>60` — номер терминала больше допустимого (60);
* `Т<N ТЕРМ> ПОЛЬЗОВАТЕЛЬСКИЙ` — сообщение указывает на невозможность
  исполнения директивы `ПУЛ` с терминала пользователя;
* `Т<N ТЕРМ>НЕ ПОДКЛЮЧ.` — указанный терминал не подключен к системе.

Номер терминала оператора, с которого переводится сообщение, можно не
указывать, если директива `ПУЛ` задается с его клавиатуры.

Примеры:

1. ```
   ПУЛ 1 3
    ЕСТЬ
   ```
   Сообщения с терминала 1 переведены на терминал 3.

2. ```
   ПУЛВ 05 2 А1
    ЕСТЬ
   ```
   Выдача с очередью 05 переводится на ЭВМ 2, АЦПУ-0.

Возврат выдачи на терминал (после директивы `ПУЛ`) выполняется с помощью
директивы `НОТ <N ТЕРМ>`.

Примечание: для терминалов, подключенных через аппаратуру сопряжения,
вместо физического номера в директиве `ПУЛ` указывается логический номер.

Латинский вариант: `PUL <С КАКОГО ТЕРМ><НА КАКОЙ ТЕРМ>`.

#### 4.5.7. Директива `НОТ [<N ТЕРМ>]`

/О/. Директива `НОТ` предназначена для возврата на терминал оператора ранее
переведенных с него сообщений системы.

| Параметр     | Значение |
|--------------|----------|
| `<N ТЕРМ>`   | Физический номер терминала. |

Сообщения системы на директиву `НОТ` аналогичны сообщениям на директиву
`ПУЛ`.

Если с терминала оператора выдачи были переведены по директиве `ПУЛ`, то
после исполнения директивы `НОТ` выдачи возвращаются обратно на данное
устройство.

Директива `НОТ` без параметра производит возврат сообщений (если ранее
сообщения были переведены на другой терминал оператора) на тот терминал
оператора, с клавиатуры которого было выполнено ее задание.

Пример:

```
НОТ 15
ЕСТЬ
```

Сообщения возвращены на терминал номер 15.

#### 4.5.8. Директива `НУС <N ТЕРМ> [<ТИП ТЕРМ>]`

/О/. Директива `НУС` предназначена для идентификации типа терминалов.

| Параметр       | Значение |
|----------------|----------|
| `<N ТЕРМ>`     | Логический номер терминала. |
| `<ТИП ТЕРМ>`   | `Э` — тип терминала "Электроника" (ИЭ15-00-013); `D` — тип терминала VDT-52129, VDT-52130; `Р` — тип терминала "РИН". |

Сообщение на директиву `НУС`:

* `ЕСТЬ` — подтверждение выполнения директивы.

Латинский вариант: `NSN <N ТЕРМ>[<ТИП ТЕРМ>]`.

### 4.6. Сервисные директивы

#### 4.6.1. Директива `ЕСМ <N ЛЕНТЫ> <N УСТ-ВА>`

/О/. Директива `ЕСМ` предназначена для присваивания номера магнитной ленте.
Лента установлена на НМЛ ЕС-5025.

| Параметр       | Значение |
|----------------|----------|
| `<N ЛЕНТЫ>`    | Номер, который присваивается ленте, установленной на НМЛ ЕС-5025. |
| `<N УСТ-ВА>`   | Номер устройства ЕС-5025. |

Сообщение системы на директиву:

* `МГ <N УСТ-ВА> - <N ЛЕНТЫ> ЕС` — для контроля задания параметров
  директивы `ЕСМ`.

Пример:

```
ЕСМ 1064 41
 МГ 41-1064 ЕС
```

Ленте, установленной на НМЛ ЕС-5025 с номером 41, присвоен номер 1064.

#### 4.6.2. Директива `ПОД <N ПРОГРАММНОГО КАНАЛА>`

/ОП/. Директива `ПОД` позволяет подключиться к терминальной задаче,
решающейся по указанному программному каналу, если задача позволяет
подобное подключение. Однотерминальная задача допускает подобное
подключение, если она имела терминал и впоследствии отказалась от него;
многотерминальная задача допускает подключение, если хотя бы некоторое
время работала с двумя терминалами. При подключении по директиве `ПОД`
задаче дается событие о возникновении у нее терминала.

При невозможности подключения ответ на директиву: `НЕТ`; при успешном
подключении ответом является сообщение подключенной задачи.

## 5. Сообщения оператору

Сообщения на терминал упорядочены по следующему алфавиту:

    А Б В Г Д Е Ж З И К Л М Н О П Р С Т У Э Ю Я D F G I J L N Q R S U V Y Z - цифра

и пронумерованы; сообщения выделяются подчеркиванием.

Использование квадратных скобок `[]` в сообщении указывает на то, что данная
часть сообщения в некоторых случаях может отсутствовать; в угловые скобки
`<>` заключается конкретное числовое значение, например, номер устройства,
номер бобины, значение счетчика и т. д.

Буква "О" в косых скобках означает выдачу сообщения на терминал в режиме
оператора, буква "П" — в режиме пользователя.

Предположим, что после исполнения директивы "СКВ" на терминал вывелось
сообщение "ЗАНЯТ 0056". На букву "З" находим сообщение номер 16:

> **5.16. `ЗАНЯТ <N БОБ>`**
>
> — бобина занята обменом
>
> /ОП/. Описание сообщения.

Описание сообщения составлено таким образом, чтобы можно было понять
причину, по которой сообщение было инициировано, и предпринять необходимые
действия.

### 5.1. АВВД НПК НСТ НС СИМ ШИФР

```
АВВД НПК НСТ НС СИМ ШИФР <ШИФР>
<АВВД><НПК><НСТ><НС><СИМ> <ПРИЧИНА ОШИБКИ>
```

/О/. Заголовок диагностического сообщения системной программы ввода об
ошибках.

Заголовок сообщения состоит из разделов, представляющих собой названия
координат ошибки ввода:

| Поле     | Значение |
|----------|----------|
| `<АВВД>` | Адрес ячейки, в которую введено слово, содержащее ошибку. |
| `<НПК>`  | Номер условной перфокарты, на которой обнаружена ошибка. Условная перфокарта — 120 (восьм.) подряд идущих символов на буфере ввода. |
| `<НСТ>`  | Номер строки условной перфокарты, содержащей неверный символ (1–12). Строка условной перфокарты — группа из 10 подряд идущих символов. |
| `<НС>`   | Номер символа в строке (1–10). |
| `<СИМ>`  | Код ошибочного символа. |

### 5.2. Б... МГ... ВРЕМЯ

```
Б<N БОБ><ПРИЧИНА СООБЩЕНИЯ>
МГ<N УСТ-ВА>[/<ДОП.ИНФ>] ВРЕМЯ:<ВРЕМЯ>
```

/О/. Сообщение системы, связанное с аварийной ситуацией при работе с НМЛ
(магнитофонами).

| Поле        | Значение |
|-------------|----------|
| `<N БОБ>`   | Номер бобины (магнитной ленты). |
| `<N УСТ>`   | Номер накопителя на магнитной ленте. |
| `<ДОП.ИНФ>` | Дополнительная информация, характеризующая ошибку. |
| `<ВРЕМЯ>`   | Астрономическое время выдачи сообщения (ч, м). |

`<ДОП.ИНФ>` = `Б<N БОБИНЫ>` / `ОШ.ЗП`

* `Б<N БОБИНЫ>` — номер бобины.
* `ОШ.ЗП` — ошибка записи.

`<ПРИЧИНА СООБЩЕНИЯ>` = `ОШ.ЦКС` / `ОШ.ЧЕК` / `Ч.БАЙТ`

**`ОШ.ЦКС`** — ошибка строки циклического контроля.

Ошибка, обнаруженная в результате несовпадения строки ЦКС записи и ЦКС
чтения при работе в режиме "ЕС".

При записи информации на магнитофоне типа ЕС-5025 в конце зоны данных
записывается строка циклического контроля, которая формируется устройством
управления по специальному алгоритму во время записи информации. В процессе
считывания зоны вновь вычисляется строка ЦКС и сравнивается с ЦКС,
записанной на ленте. При несовпадении значений строк циклического контроля
выдается описываемое сообщение с указанием данной причины.

**`ОШ.ЧЕК`** — ошибка продольного чека.

Во время работы с лентой в режиме "ЕС" была выявлена ошибка в результате
контроля строк продольного чека. Продольный контроль по каждой дорожке
состоит в том, что в конце каждой зоны записывается строка контроля (ПКС) с
такими значениями разрядов рядов, которые вместе с общим числом единичных
битов соответствующей дорожки давали бы четное число. При считывании
информации с ленты проверяется выполнение этого условия. В случае его
невыполнения выдается описываемое сообщение с указанием данной причины.

Пример:

```
Б104 ОШ.ЧЕК МГ 31  ВРЕМЯ 16.49
```

В 16 часов 49 минут зафиксирована ошибка продольного чека на магнитофоне
ЕС-5025 с номером 31; на данном НМЛ установлена бобина с номером 104.

**`Ч.БАЙТ`** — четность байта.

Ошибка, обнаруженная в результате контроля байта на нечетность.

Поперечный контроль байта заключается в записи на девятой паритетной
дорожке контрольного бита, имеющего такое значение, при котором число
единиц в байте вместе с контрольным разрядом нечетное. Если во время чтения
схема контроля обнаруживает, что в каком-то байте вместе с контрольным
разрядом содержится четное число единиц, то в сообщении указывается данная
причина.

Пример:

```
Б202 Ч.БАЙТ МГ 30  ВРЕМЯ 17.37
```

В 17 часов 37 минут зафиксирована ошибка четности байта на магнитофоне
ЕС-5025, работающем с бобиной 202.

### 5.3. БУФ ВВД ЗАПОЛНЕН

```
БУФ ВВД ЗАПОЛНЕН
```

— буфер ввода заполнен

/О/. Сообщение системы, указывающее на невозможность дальнейшего ввода
информации в системный буфер ввода.

Причиной, вызывающей данное сообщение, является переполнение каталога ввода
или переполнение зон буфера ввода, отведенных под массивы задач.

Примечание: каталог ввода рассчитан на 254 задачи.

**Действия оператора:** на некоторое время прекратить ввод информации с
устройства чтения.

### 5.4. ВКЛМГ

```
ВКЛМГ <N ЛЕНТЫ> - <N УСТРОЙСТВА>
```

— включить НМЛ

/О/. Сообщение системы в случае отключения магнитофона, закрепленного за
задачей.

| Поле             | Значение |
|------------------|----------|
| `<N ЛЕНТЫ>`      | Номер ленты, установленной на магнитофоне. |
| `<N УСТРОЙСТВА>` | Номер отключенного магнитофона. |

В одну из функций операционной системы входит отслеживание текущих
состояний накопителей на магнитных лентах (магнитофонов), закрепленных за
задачами. Для этого через каждые 6 секунд ОС проверяет наличие сигнала
готовности соответствующих НМЛ. Если НМЛ не готов к работе, то на терминал
оператора выдается данное сообщение.

Пример:

```
ВКЛМГ 0897 - 34
```

Необходимо включить магнитофон 34; на данном магнитофоне должна быть
установлена лента с номером 897.

**Действия оператора:** при наличии на данном магнитофоне ленты, указанной в
сообщении, включить НМЛ.

### 5.5. ВКЛМД

```
ВКЛМД <N ПАКЕТА> - <N УСТРОЙСТВА>
```

— включить НМД

/О/. Сообщение системы в случае отключения дискового устройства,
закрепленного за выполняемой задачей.

| Поле             | Значение |
|------------------|----------|
| `<N ПАКЕТА>`     | Номер пакета, установленного на НМД. |
| `<N УСТРОЙСТВА>` | Номер отключенного НМД. |

В одну из функций операционной системы входит отслеживание текущих
состояний накопителей на магнитных дисках, закрепленных за задачами. Для
этого через каждые 6 секунд ОС проверяет наличие сигнала готовности
соответствующих НМД. При отсутствии данного сигнала на терминал оператора
выдается описываемое сообщение.

**Действия оператора:** при наличии на накопителе указанного пакета включить
НМД.

### 5.6. ВЫБ

```
ВЫБ <ШИФР> Т<N ТЕРМ>
```

/О/. Сообщение системы о выполнении директивы "ВЫБ <N з-чи на буфере
ввода>" или специального экстракода.

| Поле       | Значение |
|------------|----------|
| `<ШИФР>`   | Шифр задачи, исключенной с буфера ввода. |
| `<N ТЕРМ>` | Физический номер терминала, с которого задана директива "ВЫБ". |

После выполнения директивы "ВЫБ" вся информация о задаче с указанным
номером на буфере ввода аннулируется, и на терминал оператора выдается
сообщение, подтверждающее данное действие.

Примечание: если директива "ВЫБ" задана с помощью экстракода, то в
описываемом сообщении номер терминала равен 0.

Пример:

```
ВЫБ 14
  ВЫБ 419976000000 Т10
```

После исполнения директивы "ВЫБ" (верхняя строка) задача с номером 14 (шифр
задачи 419976000000) исключается из входной очереди буфера ввода и из всех
списков и каталогов операционной системы; директива была задана с терминала
N15.

### 5.7. ВЫКЛ.КОНТ-Р

```
ВЫКЛ.КОНТ-Р <N НМЛ>
```

— выключен контроллер НМЛ

/О/. Сообщение системы, уведомляющее оператора о выключении контроллера
указанного накопителя на магнитных лентах.

| Поле      | Значение |
|-----------|----------|
| `<N НМЛ>` | Номер накопителя на магнитных лентах. |

При выключенном контроллере данное сообщение выдается периодически через 6
секунд. Номер контроллера можно определить с помощью директивы "ОПР МГ <N
МГ>".

**Действия оператора:** если контроллер не удается перевести во включенное
состояние, то оператор должен исключить с помощью директивы "ИСК" все НМЛ,
подключенные к неисправному контроллеру. По возможности следует переставить
магнитные ленты с накопителей, исключенных из конфигурации системы. О
неисправности сообщить техническому персоналу.

### 5.8. ДАТА

```
ДАТА:<ЧИСЛО> <МЕСЯЦ> <ГОД> [ВРЕМЯ: <ВРЕМЯ>]
```

/ОП/. Сообщение системы на директивы "ДАТ <число> <месяц>", "ДАТ",
"ВРЕ <время>" и "ВРЕ".

| Поле      | Значение |
|-----------|----------|
| `<ЧИСЛО>` | Текущее число месяца (от 1 до 31). |
| `<МЕСЯЦ>` | Текущий месяц (от 1 до 12). |
| `<ГОД>`   | Значение года. |
| `<ВРЕМЯ>` | Время суток; выдается в виде ЧЧ.ММ.СС, где ЧЧ — часы, ММ — минуты, СС — секунды. |

Дата (время), указанная в сообщении, может интерпретироваться двояко в
зависимости от того, по какой директиве она выведена. Если данное сообщение
получено по директиве "ДАТ <число><месяц><год>" ("ВРЕ <время>"), то дата
(время) представляет собой астрономическую дату (время суток), которую
оператор указывает системе после вызова ОС или с целью выполнения коррекции
(когда это требуется) даты (времени), хранящейся в системе. В случае
директивы "ДАТ" ("ВРЕ") полученная дата (время) поступила из системы с тем,
чтобы оператор проконтролировал ее значение на совпадение с действительной
датой (с действительным временем суток).

В данном сообщении время выводится только на директиву "ВРЕ [<время>]".

Пример:

```
ДАТА:08.02.84
```

После запроса даты по директиве "ДАТ" вывелась дата, хранящаяся в системе.
Дата соответствует 8 февраля 1984 года.

### 5.9. ДИАЛОГ ЗАК

```
ДИАЛОГ ЗАК
```

— диалог закрыт

/ОП/. Сообщение системы о запрете вызова диалоговых задач.

Запрещается работа в диалоговом режиме. Если затем с клавиатуры терминала
набрать директиву вызова диалоговой задачи, то в ответ будет выдано данное
сообщение.

**Действия пользователя:** в случае данного сообщения следует на некоторое
время отложить действия, связанные с вызовом диалоговой задачи.

### 5.10. ДЛЯ УПР/ВОС УСТ.СРОЧНО ТОМ

```
ДЛЯ УПР/ВОС УСТ.СРОЧНО ТОМ <N ТОМА>
```

/О/. Сообщение системы, уведомляющее оператора о невозможности выполнения
процесса упрятывания/восстановления из-за отсутствия указанной архивной
бобины (тома) на внешних устройствах памяти.

| Поле       | Значение |
|------------|----------|
| `<N ТОМА>` | Номер архивного пакета или ленты. |

Пример:

```
ДЛЯ УПР/ВОС УСТ.СРОЧНО ТОМ 2125
```

Для упрятывания или восстановления задачи необходимо установить бобину с
номером 2125.

**Действия оператора:** установить на накопитель указанную бобину.

### 5.11. ЕСТЬ

```
ЕСТЬ
```

/ОП/. Сообщение системы, подтверждающее факт начала исполнения директивы
оператора.

Данное сообщение выдается, например, при исполнении директив "ПРТ", "ВКН",
"СТОП" и т. д. В момент выдачи сообщения заданная директива начинает

### 5.12. ЖДИ.

```
ЖДИ.
```

/ОП/. Сообщение системы о запрете дальнейшего подключения терминалов к
диалоговой задаче.

Любая многотерминальная задача одновременно может работать с ограниченным
числом терминалов. При попытке вызова диалоговой задачи, уже обслуживающей
максимально допустимое число терминалов, абоненту, пославшему запрос на
установку связи, выдается данное сообщение.

**Действия пользователя:** периодически возобновлять попытку вызова
соответствующей диалоговой задачи.

### 5.13. ЖДУ

```
ЖДУ <КОД>
```

/ОП/. Сообщение системы об исполнении директивы "СКВ" (N23).

`<КОД>` = `<ШИФР>` / `999999999999` / `000<ЧИСЛО><МЕСЯЦ><ВРЕМЯ>`

| Поле | Значение |
|------|----------|
| `<ШИФР>` | Шифр задачи, по окончании которой в решение выбирается задача с номером, указанным в директиве "СКВ" (СКВ <N задачи на буфере ввода>). |
| `999999999999` | Признак диалоговой задачи, ожидающей вызова по директиве: ШИФР <шифр>. |
| `000<ЧИСЛО><МЕСЯЦ><ВРЕМЯ>` | Указывается период времени, с наступлением которого задача автоматически выбирается в решение. Желаемая дата, месяц и время включения в решение указываются пользователем в разделе "ЖДУ" паспорта задачи. |

Задача с заданным номером на буфере ввода ожидает одно из следующих
событий:

- окончания задачи с указанным шифром;
- задания директивы вызова с терминала;
- наступления заданного периода времени.

Пользователь может влиять на последовательность включения задач в решение
путем использования раздела паспорта "ЖДЕМ". В информации к этому разделу
указывается шифр задачи, окончание которой является необходимым условием
начала решения данной задачи. Задача с разделом "ЖДЕМ" не выбирается в
рабочую смесь системы до тех пор, пока не будет закончена обработка
ожидаемой задачи или выполнен экстракод.

Пример:

```
СКВ 31
    ЖДУ  303800000000
```

В верхней строке содержится директива "СКВ", а в нижней — сообщение системы
на данную директиву, которое следует трактовать следующим образом: после
окончания задачи с шифром 303800000000 в решение будет выбрана задача с
номером 31, находящаяся на буфере ввода машины.

Появление сообщения "ЖДУ 999999999999" означает, что диалоговая задача с
номером, указанным в директиве "СКВ", ожидает своего вызова по директиве
"ШИФР <шифр>".

Пример:

```

```

Предположим, на буфере ввода сформировался файл диалоговой задачи
пользователя с шифром 359777000000. После исполнения директивы "СКВ" для
данной задачи на терминал поступило сообщение "ЖДУ 999999999999".

Вызов диалоговой задачи с последующей загрузкой ее в основную память
выполняется при наборе на клавиатуре терминала следующей директивы: ШИФР
359777000000. Появление символа "-", означающего приглашение, соответствует
началу установки диалогового режима с данной задачей.

Сообщение "ЖДУ 000<число><месяц><время>" означает, что после наступления
указанного периода времени задача должна войти в решение.

Пример:

```
ЖДУ 000031120
```

Задача пользователя не будет выбираться в решение программой-планировщиком
до 20 часов 03.11 сего года.

**Действие пользователя:** если после исполнения директивы "СКВ" было выдано
сообщение "ЖДУ 999999999999", то путем ввода директивы "ШИФР <шифр>"
осуществляется вызов данной диалоговой задачи.

### 5.21. КЗ... КОНЕЦ ЗАДАЧИ

```
КЗ(<N З-ЧИ НА БУФ. ВВОДА>)<ШИФР><ВРЕМЯ>
/<ИСПОЛЬЗОВАННОЕ ВРЕМЯ> М=<М> КОНЕЦ ЗАДАЧИ
```

/О/. Сообщение системы, уведомляющее оператора о нормальном завершении
задачи.

| Поле | Значение |
|------|----------|
| `<N З-ЧИ НА БУФ.ВВОДА>` | Номер задачи на буфере ввода (идентифицирует задачи с одинаковым шифром). |
| `<ШИФР>` | Шифр завершенной задачи. |
| `<ВРЕМЯ>` | Астрономическое время окончания задачи (ч. мин.). |
| `<ИСПОЛЬЗОВАННОЕ ВРЕМЯ>` | Процессорное время, фактически затрачиваемое на решение данной задачи (ч. мин). |
| `<М>` | Коэффициент мультипрограммности; М = (Т1 − Т2) : Т3, где Т1 — коммерческое время; Т2 — коммерческое время неудавшихся обменов; Т3 — время жизни операционной системы. |

При нормальном завершении задачи, оканчивающейся экстракодом Э62 или Э74
(экстракод "конец задачи"), формируется требуемая статистическая
информация и выводится на АЦПУ. Затем разделы каталога и соответствующие
разделы ОС, занятые под данную задачу, очищаются, а освободившиеся при этом
ресурсы возвращаются в распоряжение ОС. Если окончание задачи произошло в
результате ошибки, то выдается сообщение:

```
ОЗ(<N З-ЧИ НА БУФЕРЕ ВВОДА>) <ШИФР> <ВРЕМЯ>/<ИСПОЛЬЗОВАННОЕ ВРЕМЯ> М=<М> <ПРИЧИНА>
```

Пример:

```
КЗ(057) 033311000078 15.45/00.01 М=098 КОНЕЦ ЗАДАЧИ
```

В 15 часов 49 минут завершена задача с шифром 033311000078; на буфере
ввода эта задача имела номер 57; процессорное время, затрачиваемое на
решение задачи, равно 1 минуте; коэффициент мультипрограммности равен 098.

| `<N ПРОГР.КАНАЛА>` | Номер программного канала, по которому производится упрятывание задачи. |
| `<ПРИЧИНА>` | `ГЛАВН.ЗАДАЧА` / `ДИСПАК ПРОТИВ` / `НЕТ АРХИВА` / `ПОДЧ.ЗАДАЧА` / `ТЕЛЕ ЗАДАЧА` |

После принятия системой заказа на упрятывание или восстановление
производится анализ возможности инициирования. Если система обнаруживает
невыполнение определенных условий, то текущий заказ на
упрятывание/восстановление аннулируется, и на терминал оператора выдается
данное сообщение с указанием одной из следующих причин:

| Причина | Значение |
|---------|----------|
| `ГЛАВН.ЗАДАЧА`  | В ОС Диспак запрещено упрятывание главных задач. |
| `ДИСПАК ПРОТИВ` | Указание на то, что в течение 2 минут после постановки заказа на упрятывание по какой-то непонятной причине не удалось инициировать процесс упрятывания для желаемой задачи. |
| `НЕТ АРХИВА`    | Архивно-файловая система не находится в решении. Проверка наличия архива в решении производится по директиве "ВЦП 20". |
| `ПОДЧ.ЗАДАЧА`   | В ОС Диспак запрещено упрятывание подчиненных задач. |
| `ТЕЛЕ ЗАДАЧА`   | В ОС Диспак запрещено упрятывание задач с разделом "ТЕЛЕ" (диалоговых задач). |

**Действия оператора:** при указании в сообщении причины "НЕТ АРХИВА"
рекомендуется выполнить следующие действия:

1. По директиве "РЕЖ" проверить наличие запрета на выбор архива в решение.
   В ответ на сообщение "НЕТ АРХ." следует выполнить директиву "ДАЙ АРХ".
2. Набрать директиву "ВРЕ". Директива "ВРЕ" вызывает активизацию архива,
   т. е. формирование задачи архива и выбор его в решение.

### 5.39. ОЗ... ОШИБКА ЗАДАЧИ

```

```

/О/. Сообщение системы об аварийном завершении программы пользователя

| Поле | Значение |
|------|----------|
| `<N З-ЧИ НА БУФ.ВВОДА>` | Номер задачи на буфере ввода (идентифицирует задачи с одинаковым шифром). |
| `<ШИФР>` | Шифр завершенной задачи. |
| `<ВРЕМЯ>` | Астрономическое время снятия задачи с решения (ч. мин.). |
| `<ИСПОЛЬЗОВАННОЕ ВРЕМЯ>` | Процессорное время, затраченное на решение данной задачи (ч. мин). |
| `<М>` | Коэффициент мультипрограммности; М = (Т1 − Т2) : Т3, где Т1 — коммерческое время; Т2 — коммерческое время неудавшихся обменов; Т3 — время жизни операционной системы. |
| `<ПРИЧИНА ОШИБКИ>` | Причина, по которой задача была снята с решения (подробно см. "Руководство пользователю"). |

Причина, обуславливающая данное сообщение, также указывается в листинге
задачи. Вся информация, находящаяся в распоряжении ОС и связанная с данной

Пример:

```

```

В 16 часов 11 минут вследствие обнаружения контроля команды в программе
пользователя было прекращено решение задачи с шифром 033395000000 (номер
задачи на буфере ввода равен 13); процессорное время, использованное на
решение задачи, — 10 минут; коэффициент мультипрограммности — 091.

### 5.42. П... КЛ

```
П<ПОРЯДОК В ОЧЕРЕДИ> <N КЛАССА>  КЛ
<ПРИЧИНА>
```

/ОП/. Сообщение системы об исполнении директивы "СКВ".

| Поле | Значение |
|------|----------|
| `<N КЛАССА>` | Номер класса, к которому принадлежит задача (от 0 до 8). |
| `<ПОРЯДОК В ОЧЕРЕДИ>` | Порядок задачи в очереди для класса, указанного в данном сообщении. |
| `<ПРИЧИНА>` | Причина, по которой задача не выбирается в решение. |

`<ПРИЧИНА>` = `НЕ ЗАД.КАН` / `ЗКАН` / `РЕС.<ТИП РЕСУРСОВ>` / `СТОП` /
`ЗАПР.АРХ` / `ЗУПР`

**`ЗАПР.АРХ`** — архивная система запрещает включение задач в решение.

**`ЗКАН`** — заняты все программные каналы, выделенные данному классу.

Операционная система Диспак использует режим мультипрограммирования, что
позволяет одновременно выполнять до 47 программ. Каждой задаче, выбранной в
решение, внутри операционной системы присваивается номер, однозначно
идентифицирующий задачу в рабочей смеси и называемый программным каналом.
За каждым классом обрабатываемых задач можно закрепить определенные
программные каналы. При возникновении такой ситуации, когда все
программные каналы определенного класса заняты и по директиве "СКВ"
запрашивается местонахождение задачи, относящейся к этому классу, выдается
данное сообщение с указанием причины "ЗКАН". После освобождения
программного канала, обслуживающего данный класс задач, не выбранная ранее
планировщиком задача в порядке установленной очереди поступает в свободный
канал.

Пример:

```
СКВ 23
  П003 6 КЛ
  ЗКАН
```

Задача с номером 23 на буфере ввода и номером 3 внутри класса не
выбирается в решение из-за занятости программных каналов, обслуживающих
данный класс задач; по очереди задача 3-я в 6-м классе.

**`РЕС.<ТИП РЕСУРСОВ>`** — задача не входит в решение из-за недостатка
указанных системных ресурсов.

`<ТИП РЕСУРСОВ>` = `ОЗУ` / `ТРАКТЫ` / `СЕГМ`

| Тип | Значение |
|-----|----------|
| `ОЗУ`    | В данный момент система не может предоставить задаче затребованных ресурсов оперативной памяти (листов ОЗУ). |
| `ТРАКТЫ` | В данный момент система не может предоставить задаче затребованных ресурсов по трактам. |
| `СЕГМ`   | В данный момент система не может предоставить задаче затребованных ресурсов по сегментам (по кускам) МД. |

Перед выбором задачи в рабочую смесь программа-планировщик проверяет,
достаточно ли оставшихся в распоряжении ОС ресурсов для выделения данной
задаче. К ресурсам, подлежащим распределению, относятся листы основной
памяти и зоны МД. Если потребность задачи в каком-либо из перечисленных
ресурсов удовлетворена быть не может, то включение задачи в решение
откладывается до освобождения недостающего ресурса. При наборе директивы
"СКВ" с номером данной задачи на терминал абонента поступает сообщение,
указывающее в качестве причины задержки "РЕС.<тип ресурса>" тип
отсутствующего ресурса.

### 5.43. ПР. МД. - устройство

```
ПР. МД. - <N УСТРОЙСТВА>
```

— проверить НМД

/О/. Сообщение о том, что пакет магнитных дисков, установленный на данном
НМД, операционной системой не опознан (номер пакета не занесен в
соответствующую таблицу ОС).

| Поле             | Значение |
|------------------|----------|
| `<N УСТРОЙСТВА>` | Номер НМД, содержащего неопознанный пакет дисков. |

Одной из функций операционной системы является отслеживание состояния
устройств внешней памяти. С этой целью через каждые 6 секунд ОС опрашивает
готовность дисковых устройств. Если на какой-либо НМД устанавливается
пакет дисков, то в момент опроса определяется его номер и заносится в
соответствующий раздел таблицы занятости накопителей на магнитных дисках.
Если во время опроса НМД номер пакета определен быть не может, то выдается
данное сообщение. Невозможность опознания пакета указывает на
неисправность НМД.

**Действия оператора:** при неоднократной выдаче данного сообщения
переставить пакет дисков на другое устройство.

### 5.44. ПР. МД. пакет - устройство

```
ПР. МД. <N ПАКЕТА> - <N УСТРОЙСТВА>

— проверить на НМД N пакета

/О/. Сообщение системы о неправомерной замене пакета дисков на указанном

| Поле             | Значение |
|------------------|----------|
| `<N ПАКЕТА>`     | Номер пакета, который должен быть установлен на данном НМД. |
| `<N УСТРОЙСТВА>` | Номер накопителя на магнитных дисках. |

Если до окончания задачи на НМД, участвующем в обмене, будет произведена

обслуживающих машину, и некоторой другой информации, характеризующей
эффективность использования ЭВМ.

Раздел сообщения "время простоя ЦП" соответствует времени простоя
центрального обрабатывающего устройства. Центральный процессор является
наиболее дорогостоящим устройством вычислительного комплекса, и поэтому с
экономической точки зрения следует стремиться к повышению эффективности
использования процессорного времени (машинного времени) или, иначе говоря,
к снижению времени простоя ЦП.

Для обеспечения наиболее полной загруженности центрального процессора и
всего комплекса в целом операторам следует своевременно осуществлять ввод
информации, подлежащей обработке.

Раздел сообщения "время жизни ОС" содержит время безотказной работы
вычислительной системы, что характеризует надежность ее аппаратных и
программных средств.

Пример:

```
СМЕ
 СМ3П:05.30. ЭВМ-4 28.02.84  ВРЕМЯ:12.05.32  098.19
```

28 февраля 1984 года в 12 часов 05 минут 32 секунды была исполнена
директива "СМЕ". В сообщении указывается также, что работает третья смена
операторов; потери процессора номер четыре составляют 5 часов 30 минут, а
время безотказной работы вычислительной системы равно 98 часам 19 минутам.

### 5.50. СРОЧ.ВКЛ

```
СРОЧ.ВКЛ<N УСТРОЙСТВА>
```

— срочно включить НМД

/О/. Сообщение системы о необходимости включения указанного НМД.

При работе НМД во время обслуживания заказа может возникнуть ситуация,
когда пропадает сигнал готовности устройства. В этом случае на терминал
выдается данное сообщение.

Примечание: следует иметь в виду, что одной из причин отсутствия сигнала
является отключение устройства.

**Действия оператора:** произвести включение устройства в комплексный
режим.

### 5.51. СТОП

```
СТОП
```

/ОП/. Сообщение системы на попытку установки связи с диалоговой задачей
(путем задания для нее директивы вызова) или на исполнение директивы
"СТОП".

После исполнения директивы "СТОП" программа-планировщик задачи в решение
больше не включает.

Обычно директива используется перед обнулением системы или когда надо
обеспечить монопольную обработку задач, находящихся в рабочей смеси

### 5.52. ТЕЛЕ... СЧЕТ

```
ТЕЛЕ:<КОЛИЧЕСТВО ЗАДАЧ С "ТЕЛЕ">,
СЧЕТ:<КОЛИЧЕСТВО СЧЕТНЫХ ЗАДАЧ>
(<КОЛИЧЕСТВО ЗАДАЧ С "ЖДЕМ">).
```

/О/. Сообщение системы об исполнении директивы "СКВ".

Данное сообщение информирует оператора о содержимом буфера ввода.

| Поле | Значение |
|------|----------|
| `<КОЛИЧЕСТВО СЧЕТНЫХ ЗАДАЧ>` | Количество счетных задач на буфере ввода. |
| `<КОЛИЧЕСТВО ЗАДАЧ С "ТЕЛЕ">` | Количество задач с разделом "ТЕЛЕ", находящихся на буфере ввода. |
| `<КОЛИЧЕСТВО ЗАДАЧ С "ЖДЕМ">` | Количество задач с разделом "ЖДЕМ" на буфере ввода. |

Раздел "ТЕЛЕ" паспорта является признаком диалоговой задачи.

Задачи без раздела "ТЕЛЕ" и без раздела "ЖДЕМ" относятся к счетным задачам.

Пользователь может влиять на последовательность включения задач в решение
путем использования раздела "ЖДЕМ" паспорта задачи. В информации к этому
разделу указывается шифр задачи, окончание которой является необходимым
условием начала решения данной задачи. Задача с разделом "ЖДЕМ" не
выбирается в рабочую смесь системы до тех пор, пока не будет закончена
обработка ожидаемой задачи или выполнен специальный экстракод.

Пример:

```
СКВ
  ТЕЛЕ :015, СЧЕТ :050(015)
```

В верхней строке содержится директива "СКВ", а в нижней — сообщение
системы на данную директиву, которое следует трактовать следующим образом:
в данный момент на буфере ввода находится 15 задач с разделом "ТЕЛЕ", 50
счетных задач и 15 задач с разделом "ЖДЕМ".

### 5.53. УЗ... УПРЯТАНА ЗАДАЧА

/О/. Сообщение системы, уведомляющее оператора о завершении процесса

Дальнейшая активизация решения упрятанной задачи производится с помощью

### 5.54. УСТ

```
УСТ<N КЛАССА>:<ЧИСЛО ГОТОВЫХ З-Ч>[<N БОБИН>]
```

— установить указанные носители

/О/. Сообщение системы на директиву "УСТ".

| Поле | Значение |
|------|----------|
| `<N КЛАССА>` | Номер класса задачи. Для задачи данного класса необходимо установить ленту или пакет. |
| `<ЧИСЛО ГОТОВЫХ З-Ч>` | Число задач в классе, уже готовых к решению. |
| `<N БОБИН>` | Номера бобин, которые требуются задаче (знак "+" означает, что бобина установлена). |

В данном сообщении указываются номера магнитных лент и пакетов, которые
должны быть установлены на накопителе для того, чтобы задачи, находящиеся

Последовательность распечатки носителей в сообщении соответствует
приоритету задач на буфере ввода.

Пример:

```

```

Для включения в решение задачи 2-го класса необходимо установить магнитную
ленту с номером 163; для задачи 1 класса требуется лента — 124; магнитные
пакеты 2048 и 2019 уже установлены на дисковых устройствах. Одна задача
2-го класса и 10 задач 1-го класса готовы к решению (для данных задач
установлены все заказанные носители).

### 5.55. Ф... ОКОНЧЕН ПРОЦЕСС ФОРМИРОВАНИЯ ЗАДАЧИ

— окончен процесс формирования задачи

|------|----------|

| `<ШИФР>` | Шифр сформированной задачи. |

Формирование новой задачи начинается с обращения к экстракоду Э50 "7701".

/О/. Сообщение системы об аварийном завершении программы пользователя

| Поле | Значение |

снята с решения; время, затраченное ЦП на решение задачи, составляет 30
минут; в момент аварийного завершения задачи коэффициент
мультипрограммности был равен 080.

предварительно проконсультировавшись с пользователем и получив его
согласие, ввести задачу повторно.

Примечание: указание "НЕ ВВОДИТЬ!" означает автоматическое повторение
решения задачи, предписанное разделом "ПОВТОР" ее паспорта.

| `<N ГОЛОВКИ>` | Номер магнитной головки. |

`ДРУГОЙ ПАКЕТ` / `ДРУГАЯ ЗАПИСЬ` / `КАНАЛ НЕ КОНЧИЛ` / `КОМ.ОТВЕРГНУТА` /
`ТРЕБ.ВМЕШАТ-ВО` / `ОШИБКА ШИН-К` / `СБОЙ ОБОРУДОВАН.` / `СБОЙ ДАННЫХ` /
`ПОСТОЯННАЯ ОШИБ.` / `ЗАПИСЬ НЕ НАЙДЕН` / `ЗАПРЕТ ЗАПИСИ` /
`ОПЕРАЦИЯ НЕЗАВЕР`

| Причина | Значение |
|---------|----------|
| `ВУ НЕ НАЙДЕНО` | Диск с N не найден. |
| `УВУ ЗАНЯТО` | Занято УВУ. |
| `ОШЧА` | Из ВУ поступил байт с ошибкой по четности. |
| `ОШЧМ` | Ошибка четности числа ОП в 67–65 и 64–33 рр. |
| `ОШЧС` | Ошибка четности числа ОП в 70–68 и 64–33 рр. |
| `ОШАС` | Ошибка четности 23–11 рр. адреса, выданного каналом в ОП. |
| `ОШАМ` | Ошибка четности в 10–1 рр. адреса, выданного каналом в ОП. |
| `ОШ.ВЫБОР.КСК` | После выполненного обмена 8-й разряд ССК ≠ 0. |
| `ВУДЛК` | Операция ввода-вывода завершилась по инициативе канала ввиду исчерпания байтов, заданных в КСК. |
| `ВУКОРК` | Операция ввода-вывода завершилась по инициативе канала, т. к. количество байтов не было исчерпано. |
| `БЛКК` | Ошибочное выполнение команды ввода-вывода. |
| `NВУ НЕ СОВПАЛИ` | N ВУ в КСК и ССК. |
| `NВУ НЕ СОВП.` | См. "NВУ НЕ СОВПАЛИ". |
| `НАЧАЛЬН.БС'0` | Начальный байт состояния ВУ ≠ 0. |
| `ПЕРЕХ.В КАН` | Ошибка при выполнении команды перехода в канале. |
| `ВУ НЕ КОНЧИЛО` | ВУ не закончило обмена. |
| `НЕ СОВПАД. КЛЮЧ` | Несовпадение контрольных сумм, полученных после обмена с ВУ, с контрольными суммами в служебных словах зоны МД. |
| `ДРУГОЙ ПАКЕТ` | Несовпадение N пакета с N пакета в служебных словах. |
| `ДРУГАЯ ЗАПИСЬ` | Несовпадение N записи с N записи в служебных словах. |
| `КАНАЛ НЕ КОНЧИЛ` | Обмен с каналом не закончен. |
| `КОМ.ОТВЕРГНУТА` | Команда отвергнута. |

`ОПЕРАЦИЯ НЕЗАВЕР.` — см. [6].

### 5.62. адрес:содержимое

```
<АДРЕС>:<СОДЕРЖИМОЕ ЯЧЕЙКИ>
```

/О/. Сообщение системы об исполнении директивы "АДР" (АДР <адрес ячейки>).

| Поле | Значение |
|------|----------|
| `<АДРЕС>` | Адрес, заданный в директиве: АДР <адрес ячейки>. |
| `<СОДЕРЖИМОЕ ЯЧЕЙКИ>` | Содержимое ячейки по указанному адресу. |

По адресу, указанному в директиве АДР <адрес ячейки>, выдается содержимое
соответствующей ячейки физической памяти.

Примечание: директива "АДР" позволяет выдавать состояние заданных ячеек
резидентной части операционной системы.

Пример:

```
АДР 77412
     77002402000000000
```

В верхней строке задана директива "АДР", а в нижней — сообщение на данную
директиву: содержимое ячейки с адресом 77412 равно 002402000000000.

### 5.63. ... КВ НА АЦПУ

```
<ШИФР> КВ НА АЦПУ<N УСТРОЙСТВА>
```

— конец выдачи на АЦПУ

/О/. Сообщение системы о завершении работы, связанной с печатью на АЦПУ
листинга, инициируемой соответствующей задачей.

| Поле | Значение |
|------|----------|
| `<N УСТРОЙСТВА>` | Номер устройства АЦПУ (N0 или N1). |
| `<ШИФР>` | Шифр задачи. |

Пример:

```
319979000000 КВ НА АЦПУ 01
```

Закончилась печать листинга задачи с шифром 319979000000 на
алфавитно-цифровом печатающем устройстве 1.

## Перечень терминов

- **Авост** — прекращение выполнения программы в результате аварийной
  ситуации.
- **Зона** — участок внешнего носителя, содержащий 1024 информационных слова
  и 8 служебных слов.
- **Том** — физическая единица внешней памяти.
- **Тракт** — буфер оперативной памяти емкостью 1024 слова, выделяемый задаче
  на момент ее решения.
