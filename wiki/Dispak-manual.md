## 1. Общие сведения об ОС

### 1.1. Назначение ОС

Описываемая программа представляет собой операционную систему (ОС) для
вычислительного комплекса "Эльбрус 1-КБ".

Наименование программы — "Диспак".

ОС Диспак обеспечивает:

- решение системных задач и задач пользователей в мультипрограммном режиме;
- решение задач в режимах пакетной, дистанционно-пакетной обработки,
  диалоговом режиме и режиме реального времени;
- работу вычислительного комплекса как в режиме короткого адреса (режим 1),
  так и в режиме длинного адреса (режим 3);
- оператора ЭВМ широким набором средств и возможностей для простой и
  оперативной работы за терминалом;
- эффективную защиту самой ОС и информации пользователей от
  несанкционированного доступа;
- высокую надежность работы вычислительной системы в целом и отдельных ее
  компонентов, а также простоту эксплуатации;
- пользователя средствами отладки программ и некоторым набором средств
  управления решением задачи;
- оперативную выдачу сообщений об отказах аппаратуры;
- возможность использования ряда компиляторов, разработанных независимо от
  операционной системы;
- регистрацию, обработку и выдачу статистической информации о работе
  пользователей и аппаратуры;
- сохранение преемственности к программному хозяйству, накопленному на ЭВМ
  БЭСМ-6 и МВК "Эльбрус-1" комплектации 2 за время ее эксплуатации;
- достаточно простое включение в состав ОС новых возможностей и замену
  отдельных ее компонентов более совершенными, то есть возможность развития.

Программы операционной системы написаны на макрокоде "Бемш" и ассемблере
ВК "Эльбрус 1-КБ".

### 1.2. Программное обеспечение, необходимое для работы ОС

Для функционирования ОС Диспак необходимо, чтобы в состав вычислительной
системы был включен комплекс пультового программного обеспечения
("ППО. Руководство оператора" ИЫ.00112-01 34 01), в состав которого должны
входить сервисные программы для постановки и вызова ОС.

## 2. Функциональное назначение ОС

ОС Диспак является операционной системой общего назначения и может быть
использована для решения широкого круга народнохозяйственных, научных,
экономических и специальных задач, требующих большого объема вычислений.

ОС Диспак также обеспечивает работу процессора ВК "Эльбрус 1-КБ" в рамках
систем коллективного пользования с применением пакетного режима и режима
разделения времени.

Имеется широкий набор входных языков, поддерживаемых компиляторами,
работающими под управлением ОС, в том числе Фортран-Дубна, Фортран-ГДР,
Forex (близкий к Фортрану-77), БЭСМ-Алгол, Алгол-ГДР, Паскаль, Рефал,
автокоды Бемш, Madlen, ИТМ, ассемблер ВК "Эльбрус 1-КБ".

Операционная система Диспак поддерживает на ВК "Эльбрус 1-КБ" работу
однотерминальных и многотерминальных диалоговых систем, работающих на ЭВМ
типа БЭСМ-6 и учитывающих специфику аппаратуры вычислительного комплекса.

Для обмена информацией с ЭВМ БЭСМ-6 и МВК "Эльбрус 1-К2" используются
магнитные ленты типа ЕС, работающие в режиме ЕС.

## 3. Описание логической структуры ОС

### 3.1. Структурные единицы ОС

Операционная система Диспак представляет собой совокупность большого числа
служебных программ, связанных между собой в единый иерархический комплекс.
По функциональным и организационным принципам в структуре этого комплекса
можно выделить четыре основные части:

- супервизор;
- управляющую программу;
- монитор;
- блок обработки экстракодов.

Каждая из этих частей в свою очередь есть совокупность согласованных между
собой служебных программ. Часть служебных программ размещается постоянно в
оперативной памяти, образуя резидент ОС, остальные хранятся во внешней
памяти и в области ОП, имитирующей внешнюю память (программный магнитный
барабан, системный магнитный диск). Эти служебные программы называются
нерезидентами ОС и вызываются в оперативную память по мере надобности. В
резидентную часть ОС входят также некоторые информационные и буферные поля.

#### 3.1.1. Супервизор

1. Обслуживает систему аппаратных прерываний ЭВМ. При обслуживании
   какого-либо прерывания допускается возникновение другого прерывания более
   высокого приоритета;
2. обслуживает систему фиктивных прерываний, то есть прерываний,
   возбуждаемых служебными программами ОС и используемых для
   распараллеливания работы ОС;
3. обслуживает каналы связи с внешними устройствами. Супервизор при вводе
   данных приводит их к стандартному внутренним кодам, а при выводе — от
   стандартного кода к коду, соответствующему реальному каналу вывода;
4. реагирует на некоторые директивы оператора;
5. реакцию на аварийное состояние системы.

Обмен с внешними устройствами и постановка заказов осуществляется через
единый блок, который собирает заказы от исполнительных блоков — драйверов.
Система обмена с внешними устройствами обеспечивает:

- контролируемый обмен с внешними устройствами;
- автоматическое слежение за постановкой и отключением сменных носителей;
- повторение обмена в случае сбоя.

#### 3.1.2. Управляющая программа

Управляющая программа выполняет следующие функции:

1. Принимает и организует выполнение директив оператора;
2. активизирует работу исполнительных блоков ОС по заказу или по таймеру;
3. осуществляет распределение процессора между процессами в соответствии с
   их приоритетами;
4. управляет распределением ресурсов между процессами;
5. осуществляет меры по сбору информации об использовании ресурсов ОС и
   надежности функционирования отдельных устройств ЭВМ.

#### 3.1.3. Монитор

Монитор выполняет следующие функции:

1. Осуществляет прием задач пользователя и организует очередь для их
   активизации;
2. информирует оператора о действиях, которые он должен произвести для
   активизации той или иной задачи пользователя;
3. осуществляет оперативное распределение ресурсов ОС между
   активизированными задачами пользователя в процессе их выполнения;
4. активизирует служебные программы для выполнения заданий, содержащихся в
   директивах задач пользователя;
5. осуществляет предварительную буферизацию данных для последующего вывода
   на реальные устройства;
6. организует совмещенное выполнение активизированных служебных программ и
   задач пользователя;
7. осуществляет вывод задач пользователя из ОС с выдачей накопленных
   результатов по стандартным каналам ОС;
8. управляет очередностью выполнения заказов, поступающих из различных
   частей ОС и из задач пользователя, на обмен с внешней памятью или по
   каналам ввода-вывода;
9. ведет учет расходования ресурсов при выполнении каждой активизированной
   задачи пользователя и передает накопленную информацию об этом блоку сбора
   статистической информации после вывода задач пользователя из ВС.

#### 3.1.4. Блок обработки экстракодов

Блок обработки экстракодов интерпретирует макрокоманды, встречающиеся при
выполнении программ в режиме пользователя и в ОС. Наличие экстракодов
обеспечивает расширение системы команд, что создает экономию математической
памяти, несколько ускоряет вычисления за счет более быстрого вычисления
стандартных функций и дает гибкий интерфейс для обращения к ОС. Сама
операционная система широко использует возможности экстракодов для связи
отдельных процессов между собой.

Блок обработки экстракодов выполняет следующие функции:

1. Дешифрацию экстракодов;
2. активизацию необходимых исполнителей;
3. активизацию процесса, выдавшего экстракод, после его исполнения;
4. устанавливает соответствие между абстрактным каналом ввода-вывода,
   указанным в экстракоде задачи пользователя, и соответствующей частью
   буфера ввода-вывода;
5. устанавливает соответствие между абстрактным и реальным каналами
   ввода-вывода.

### 3.3. Используемые методы

#### 3.3.1. Метод страничной организации памяти

Операционная система ориентируется на аппаратно поддерживаемую страничную
организацию памяти. При работе в первом режиме (режим короткого адреса)
длина страницы составляет 1К слов (К=1024). Обмены с внешней памятью в этом
режиме разрешены квантами, равными странице, а с магнитными лентами в режиме
ЕС и с логическими магнитными барабанами также четвертью страницы. При работе
в третьем режиме (режим длинного адреса) длина страницы составляет 32К слов.

#### 3.3.2. Метод модульности ОС

Операционная система Диспак представляет собой набор модулей программ,
которые могут быть написаны и протранслированы независимо друг от друга.
Полученные после трансляции объектные модули объединяет и превращает в
готовые программы компоновщик. Программы для первого и третьего режимов
транслируются и компонуются независимо друг от друга.

### 3.4. Составные части операционной системы

В состав операционной системы должны входить следующие основные части:

- генератор ОС;
- система управления прохождением задач через вычислительную систему
  (планировщик задач);
- система управления вводом/выводом (планировщик работ);
- система управления процессами;
- система управления данными;
- диалоговый отладчик;
- блоки обработки экстракодов, обеспечивающие связь операционной системы с
  системами программирования как в режиме совместимости, так и в режиме
  длинного адреса.

В нижеследующих разделах описаны указанные основные части ОС.

### 3.5. Связь с другими программами

Связь операционной системы с задачами пользователя осуществляется с помощью
экстракодов и трансляторов с различных языков программирования. Трансляторы
в свою очередь связаны с операционной системой посредством экстракодов.
Описание экстракодов приведено в документе "ОС Диспак. Руководство
программиста" ИЫ.00110-01 33 01.

В настоящее время операционной системой Диспак работают системы
программирования и трансляторы:

- мониторная система "Дубна";
- Монитор-80;
- система БЭСМ-Алгол;
- транслятор с макрокода "Бемш";
- транслятор с автокода ИТМ;
- система программирования с ассемблером ВК "Эльбрус 1-КБ".

## 4. Генератор ОС

Генератор операционной системы включает в себя модули ГЕНС, ГЕНС1, ГЕНС2,
ЗВОНОК. Модуль ЗВОНОК работает в третьем режиме, модули ГЕНС, ГЕНС1, ГЕНС2 —
в первом режиме. Генератор системы выполняет следующие основные функции:

1. Чтение параметров генерации с зоны системного МД;
2. выбор заданного набора параметров генерации;
3. перепись готовых программ ОС на свои рабочие места;
4. роспись каталогов ОС, если это было задано на логическом тумблерном
   регистре;
5. определение установленных томов МД и МЛ, занесение информации о них в
   системные таблицы;
6. формирование шкал для работы с терминалами;
7. аварийное завершение задач;
8. выбор даты из зоны статистики;
9. выдача сообщений на терминал об установленных МД, МЛ, текущей дате,
   ресурсах ОС, аварийных задачах;
10. переход на ждущий тест в блок выбора задач.

К моменту начала работы генератора на логическом тумблерном регистре
(слово 1) уже должна быть задана необходимая информация:

- в 1—3 разрядах — номер ЭВМ; если эти разряды равны нулю, номер ЭВМ
  принимается равным единице;
- в 25—28 разрядах — номер варианта параметров генерации; если в этом поле
  нули, принимается первый вариант;
- в 48 разряде — необходимость росписи каталогов.

Номера разрядов приведены в представлении БЭСМ-6.

Варианты параметров генерации размещены в 750 зоне системного МД. Они
представляют собой наборы констант по 40(8) слов, содержащие информацию о
номере ЭВМ, номерах МД загрузки, ввода и вывода, последних цифрах года,
владельце ЭВМ, подключении бюджетной и архивной систем, подключенных
терминалах и выделении среди них операторских, и другие сведения.

При вызове ОС номер требуемого набора задается на логическом тумблерном
регистре (25—28 разряды); если эти разряды равны нулю, выбирается набор
номер 1 для заданного номера ЭВМ. Если не находится варианта с требуемым
номером для указанной ЭВМ, программа выходит на фатальный (непроталкиваемый)
стоп с адресной частью "11111".

Найденный набор параметров генерации переписывается в поле "ПАРОС",
расположенное в адресах памяти 71740—71777(8), для дальнейшей работы с ним.

Нумерация наборов раздельная для каждой ЭВМ. Таких наборов констант можно
иметь до 15 для всех ЭВМ.

Наборы констант готовятся заранее с помощью директивы "ГЕНС" сервисной
программы "СЕРП". Работа с этой директивой и описание параметров генерации
приведено в документе "ОС Диспак. Руководство системного программиста"
ИЫ.00110-01 32 01.

## 5. Планировщик задач

К планировщику задач относятся модули НПЛАН, НПЛАН2, БОП, БОП1, БОП2, ПРИК,
ПРИК1—ПРИК10.

Основные функции планировщика работ:

1. Чтение каталогов ввода;
2. выбор задачи в решение:
   - обработка паспорта;
   - проверка режимов работы ОС (СТОП, СПЕЦ, ОТЛ, БЮДЖЕТ);
   - проверка наличия требуемых томов;
   - проверка наличия ресурсов;
   - проверка наличия каналов;
   - включение задачи в решение;
3. обработка конца задачи;
4. обработка директив оператора.

### 5.1. Классы задач

В ОС Диспак все пользовательские задачи, поступающие для решения на
вычислительном комплексе, попадают сначала на буфер ввода, образуя входную
очередь задач. Для того, чтобы включить задачу в решение из входной очереди,
ей нужно выделить программный канал и необходимые ресурсы, указанные в
паспорте задачи. В ОС Диспак имеется 96 программных каналов, среди которых
может быть до 48 пользовательских задач и 48 служебных задач.

К числу задач, которые нельзя выбрать в решение из входной очереди даже при
наличии ресурсов, относятся:

- терминальные задачи, то есть задачи с разделом "ТЕЛЕ" в паспорте;
- задачи, в паспорте которых есть раздел "ЖДЕМ" (ждем шифра или ждем
  времени);
- задачи, в паспорте которых есть раздел "МАШ", указывающий, на какой из ЭВМ
  многомашинного комплекса они могут быть включены в решение;
- задачи, выбор которых в решение по какой-либо причине запрещен бюджетной
  системой.

Все пользовательские задачи, поступающие во входную очередь, делятся на
9 классов. Стандартное распределение задач на классы в системе:

- 0 класс — задачи с временем решения более 10 мин 40 сек;
- 1 класс — задачи с временем решения от 5 мин 20 сек до 10 мин 40 сек;
- 2 класс — задачи с временем решения от 2 мин 40 сек до 5 мин 20 сек;
- 3 класс — задачи с временем решения от 2 мин 40 сек до 2 мин 40 сек;
- 4 класс — задачи с временем решения менее 1 мин 20 сек;
- 5 класс — терминальные задачи;
- 6 и 7 классы — задачи из приоритетного каталога;
- 8 класс — задачи реального времени.

Каждый раз, когда появляется возможность включения задачи в решение,
просматриваются задачи сначала одного класса, затем все задачи другого класса
и так далее, пока не будут просмотрены задачи всех классов. Порядок просмотра
может быть изменен директивой "ПЛАН" сервисной программы "СЕРП".

### 5.2. Объединенный буфер ввода-вывода в ОС

**5.2.1.** При использовании ОС Диспак в различных конфигурациях
вычислительных систем и на разнообразных классах задач стояла проблема
объема буфера ввода и буфера вывода, так как часто возникала ситуация, когда
не было места на буфере ввода, в то время, как на буфере вывода было
свободное пространство. Поэтому появилась необходимость объединить буфера
ввода и вывода в единый пул. Такое распределение сглаживает недостатки в
распределении дискового пространства между буферами ввода и вывода. Введение
в ОС объединенного буфера позволило сократить время ответа системным задачам
из-за уменьшения перемещений головок МД при подводах.

При разработке программного обеспечения были учтены недостатки малой емкости
буфера. Общая емкость буфера увеличена до 2000(8) зон.

Общее количество задач пользователя в системе не должно превышать 255
(256-ю задачу система не примет). Информация о задачах заносится в каталоги
ввода-вывода, расположенные в 545—547 зонах системного МД.

**5.2.2.** В 545 зоне находится каталог шифров и зон ввода. Ниже приведена
его структура.

0 слово — пустое.

В словах 1—177(8) — первый каталог. В нем находятся в двоично-десятичном
виде шифры введенных задач. Номер слова соответствует номеру очереди (СКВ N).
Из первого каталога задачи непосредственно выбираются в решение.

200 слово — пустое.

В словах 201—377(8) шифры задач, окончания которых ждут задачи первого
каталога (раздел паспорта "ЖДЕМ") соответственно словам первого каталога.
Когда задача, которую ждут, закончилась, в словах 201—377 обнуляется
соответствующая строка. Задачи с разделом паспорта "ТЕЛЕ" в слове для шифра
ожидаемой задачи имеют код "999999999999". Задачи с разделами паспорта
"ТЕЛЕ" и "ЖДЕМ" могут попасть только в первый каталог.

В словах 400—577(8) расположен второй каталог. Структура его аналогична
первому каталогу. При освобождении места в первом каталоге задачи из второго
каталога переходят в первый.

В словах 700—777(8) размещен каталог приоритетных шифров, на один шифр
отводится два слова. Информация в него заносится директивой "ПРИО" сервисной
программы "СЕРП".

Начиная с 1000(8) слова размещается информация о занятых зонах буфера
ввода-вывода. В каждом слове этого пространства используются старшие
32 разряда. Старший разряд соответствует нулевой зоне буфера ввода-вывода.
Единица в соответствующем разряде означает, что зона занята.

**5.2.3.** В 546—547 зонах системного МД находится большой каталог ввода.
В него записываются паспортные данные задачи. Для каждой задачи отводится
8 слов, в 10—17(8) словах 546-ой зоны информация о первой в очереди задаче
(СКВ 1), в 20—27(8) словах — о второй в очереди задаче (СКВ 2) и т. д.
В 547 зоне аналогичная информация о задачах второго каталога.

## 6. Планирующая система ввода-вывода

Планирующая система ввода-вывода включает в себя модули В1К, В3В4, В6В7,
РОБОТ, ПЕЧАТЬ, МОТСВС, НЕРОТ, РЕЗОТ, ТЕРСВС.

**6.1.** Модули В1К, В3В4, В6В7 обслуживают ввод задач в операционную
систему, а модули РОБОТ, ПЕЧАТЬ осуществляют вывод информации на реальные
устройства. Задачи вводятся с помощью экстракода формирования из диалоговых
систем. С точки зрения программ ввода задача представляет собой набор
массивов. Паспорт задачи является нулевым массивом.

Программы ввода выполняют следующие функции:

1. Заполнение каталогов шифров и зон ввода;
2. заполнение большого каталога ввода;
3. разбиение задач на классы и присвоение приоритетов;
4. разбор разделов паспорта, проверка допустимого и заданного числа листов,
   трактов;
5. анализ признаков ввода "А0"—"А5";
6. работа с каталогами бюджетной системы;
7. подсчет и выдача ошибок ввода.

Описание признаков ввода и разделов паспорта приведено в документе
"ОС Диспак. Руководство программиста" ИЫ.00110-01 33 01.

**6.2.** Модули РЕЗОТ, НЕРОТ, ТЕРСВС, МОТСВС обслуживают терминалы. Для
работы с терминалами ОС использует режим непосредственного доступа. В этом
режиме контролируется каждый символ, передаваемый с терминала. Наиболее
употребительным режимом работы терминала является в этом случае режим работы
на линию. В этом режиме каждый набираемый символ передается в ЭВМ (память
дисплея доступна для записи в нее символов, поступающих в ЭВМ) и затем по
второму каналу — в терминал, т. е. устанавливается двусторонняя связь
терминала и ОС. В этом случае любая ошибка аппаратуры или пользователя
влечет выдачу соответствующего сообщения: ошибки в работе линии или ошибки в
задании операции для системы обслуживания терминалов.

Обмен информацией с терминалами имеет ряд особенностей, которые вызваны
техническими характеристиками оборудования и присутствием человека со своими
особенностями поведения. Это предъявляет определенные требования к
организации программ, особенно многотерминальных, т. е. обслуживающих
несколько устройств.

При работе с терминалами пользователь должен указывать номера устройств, под
которыми они фигурируют внутри ОС. Поэтому, прежде, чем начать работу с
терминалом, необходимо определить закрепленный за ним номер и в дальнейшем
всегда указывать его при работе. Для этого имеется экстракод определения
номеров терминалов, подключенных к задаче.

Все экстракоды, выполняющие функции, связанные с обращением к терминалу,
указывают на информационное слово обмена. В этом слове указывается
расположение информации обмена в ОП, номер терминала и код режима обмена.
Раздельное выполнение приема и передачи позволяет создать следующие режимы:
прием, выдача, прием с разрывом дуплекса и прием с приглашением. Режимы
приема и выдачи не требуют пояснений.

Прием с разрывом дуплекса имеет смысл для терминалов, в которых символ не
поступает на экран, если нет сигнала с ЭВМ. Его удобно использовать для
подтверждения различных ключей, паролей.

В режиме приема с приглашением вначале производится выдача текста —
приглашения, затем терминал переводится в режим приема, причем вводимый
текст записывается на место приглашения, заменяя его. Реализация экстракодов
обмена выполнена так, что обмен производится последовательно, причем ОС
берет на себя функции по автоматической синхронизации обменов и обращений
через аппарат событий. Только после опроса готовности терминалов и получения
определенного кода ответа можно продолжать работу с устройством. В остальных
случаях задача снимается из-за некорректности обращения к терминалу. Задача,
обслуживающая терминалы, может отказаться от дальнейшей работы с каким-либо
из них, если он не занят обменом.

Задачи, работающие с терминалами, должны иметь в паспорте раздел "ТЕЛЕ". Они
называются терминальными. Выбор их в решение производится только после
набора пользователем соответствующей директивы, содержащей шифр или ключ
задачи, причем терминал, на котором набиралась директива, закрепляется за
данной задачей. Если включение задачи в данный момент невозможно, например,
для нее не установлена лента, то терминал может быть использован для вызова
другой задачи. Первая задача выбирается в решение после выполнения всех
условий, необходимых для ее решения, и освобождения терминала. Она может быть
вызвана с другого терминала. Действующее правило закрепляет за задачей тот
терминал, на котором последний раз набирался ее шифр или ключ. Задачи,
работающие с несколькими терминалами, могут быть вызваны по ключу для каждого
нового терминала.

Сформулированные принципы работы с терминалами позволяют организовывать
различные системы, работающие с терминалами и предоставляющие пользователям
различные услуги. Среди таких систем "УПО", и многие другие. Все эти
терминальные системы имеют свои архивы, в которых хранится информация
пользователей, и все они имеют свои правила работы с файлами, но, в силу
общих задач, имеют и много общего. Каждый пользователь в них поочередно
набирает ключ диалоговой системы, код, шифр и ключ файла и получает доступ
к своей программе. Такие правила входа созданы для защиты массивов от
несанкционированного доступа.

Получив доступ к своей программе, пользователь может вносить в нее изменения,
дополнять ее и пускать в решение. По результатам работы программы, которые
можно видеть в той же самой системе, можно сразу же внести исправления и
ввести программу вновь в работу. Для этого терминальные системы позволяют
просматривать полученные данные, оттранслированную программу и производить
отладочные работы. Все это позволяет резко ускорить работу по отладке
программ.

## 7. Система управления процессами

Управление процессами осуществляют модули ПРОЦЕС, КАНАЛ.

### 7.1. Принципы управления процессами и ресурсами

К программам реакции на внешние и внутренние прерывания по экстракодам
непосредственно примыкают системные исполнители. Однако прежде, чем
переходить к описанию принципов работы системных исполнителей, введем
понятие интерфейса обмена информацией с блоками ОС.

Первый уровень интерфейса существует для обмена информацией между ОС и
оператором вычислительной системы, т. е. внешний интерфейс. Он включает в
себя директивы оператора, паспортные данные задачи пользователя и ответные
сообщения ОС. Весь обмен происходит, в силу присутствия человека, через
внешние устройства.

Второй уровень интерфейса предназначен для обмена информацией между блоками
ОС. Он включает большой набор экстракодов и системных команд, указывающих на
действия, необходимые для продолжения вычислений. Конкретный тип
взаимодействия определяется взаимоотношением задач пользователя и системных
процессов, а непосредственная передача информации между различными
структурными единицами осуществляется через системные таблицы и шкалы,
которые отражают состояние всех процессов и ресурсов системы. Исходное
значение этих таблиц и шкал устанавливается в момент генерации, т. е. запуска
ОС.

Если первый уровень — язык общения с человеком — направлен в основном на
улучшение условий работы оператора и пользователя, то второй — направлен на
ускорение прохождения задач и повышение производительности вычислительной
установки.

Если первый уровень интерфейса понять нетрудно, то методы использования
системных таблиц и шкал требуют дополнительных пояснений. Сделаем это на
конкретном примере блока "ТБУФ", входящего в ядро ОС.

При помощи процедуры "ТБУФ" выполняется запрос и возврат полей оперативной
памяти, которые берутся во временное пользование процессами ОС. Используя
различные значения параметров вызова процедуры, можно инициировать следующие
действия:

- запрос абзаца для размещения нерезидента из специально выделенной в данной
  конфигурации вычислительной системы области памяти;
- запрос листа оперативной памяти в нулевом сегменте;
- загрузка листового нерезидентного исполнителя с предварительным выделением
  листа для его размещения;
- возврат ранее запрошенного поля в набор свободных.

Сама процедура "ТБУФ" выделяет для использования только свободные абзацы
оперативной памяти. Если запрошен целый лист, а свободных листов в нулевом
сегменте нет, то производится обращение к исполнителю "КАЧКА", который
осуществляет откачку (перемещение) содержимого какого-нибудь занятого листа
на внешнюю память, а затем и само выделение освободившегося ресурса
заказчику. При этом процесс, выдавший запрос, на время работы процесса
"КАЧКА" переводится в состояние "блокирован".

Если нет в наличии свободного абзаца, то выполнение соответствующего запроса
откладывается до тех пор, пока какой-либо абзац не будет возвращен в набор
свободных, а процесс, выдавший запрос, на это время переводится в состояние
"блокирован".

Обращение к процедуре производится прямой передачей управления с помощью
команды 31(ПВ). Параметры вызова при этом находятся на сумматоре АУ.
Рассмотрим подробнее работу процедуры "ТБУФ" при различных значениях
параметров:

1. Признаком запроса листа является нулевой код во всех разрядах сумматора.
   В этом случае "ТБУФ" заносит в шкалу заказов для исполнителя "КАЧКА"
   единицу в разряд, соответствующий номеру канала процесса-заказчика. Если
   "КАЧКА" не была в работе, т. е. в шкале заказов для исполнителя "КАЧКА"
   не было единиц, то она приводится в готовность: в 38-й (соответствующий
   номеру счетного канала "КАЧКИ") разряд шкалы готовности заносится единица.
   Процесс-заказчик переводится в состояние "блокирован". Работа процесса
   будет продолжаться после окончания работы блока "КАЧКА", т. е. передачи
   заказчику листа;

2. если на сумматоре код "1" в 1-ом разряде при нуле во всех остальных, то
   это запрос на абзац из памяти для секторных нерезидентов. Свободная память
   для секторных нерезидентов отмечена в шкале "ШКСВМ", начальное значение
   которой задается при вызове ОС. Шкала "ШКСВМ" имеет следующую структуру.
   Свободные абзацы отмечаются в шкале единицами. Листы под абзацы для
   секторных нерезидентов отводятся в нулевом сегменте и задаются при
   генерации конфигурации вычислительной системы. Закончившие свою работу
   секторные нерезиденты не удаляются из занимаемых ими абзацев памяти,
   поскольку это позволяет ускорить повторную активизацию исполнителя. Все
   нерезиденты, окончившие свою работу, но не удаленные из памяти, обозначены
   единицами в шкале "ШКНП". Занятая этими нерезидентами память может быть
   освобождена, если есть запрос на абзац, а свободных абзацев нет, т. е.
   ШКСВМ=0. В таком случае процессу-заказчику выделяется абзац, занятый одним
   из ранее отработавших нерезидентов, перечисленных в "ШКНП". Для определения
   адреса абзаца, хранящего отработавший нерезидент, имеется массив ссылок,
   выборка из которого происходит по номеру нерезидента.

   Память, на которой находится свободный нерезидент из шкалы "ШКНП",
   отсутствует в шкале "ШКСВМ".

   Процедура "ТБУФ", найдя свободный разряд в одной из шкал, гасит единицу в
   соответствующей шкале; если свободный абзац найден, то "ТБУФ" возвращает
   управление обратившемуся процессу, адрес выделенного абзаца заносится на
   сумматор АУ, абзац исключается из набора свободных.

   Если свободный абзац не найден, процесс-заказчик переводится в состояние
   "блокирован";

3. при вызове листового нерезидента или подкачке специального листа параметры
   обращения к "ТБУФ" следующие: номер листа, номер задачи. Номер листа
   определяется по номеру вызываемого нерезидента. Номер листа и номер
   нерезидента — это координаты для поиска листа в ОЗУ или буферной памяти,
   если лист откачан. В случае необходимости вызова листа в ОЗУ формируется
   заказ блоку "КАЧКА" для переписи из буферной памяти в ОЗУ требуемого листа;

4. если при входе в "ТБУФ" разряды сумматора с 13-го по 48-й не равны "0" и в
   19-м разряде есть единица, то это означает возврат листа в набор свободных,
   причем номер листа задается в разрядах с 13-го по 17-й. Этот случай
   включает возврат листа в общий ресурс с сохранением и без сохранения
   информации;

5. возврат системе абзацев оперативной памяти.

На примере процедуры "ТБУФ" можно видеть следующее:

- системные команды представляют собой команды передачи управления с
  определенным значением кода на сумматоре числа;
- каждый системный исполнитель может обратиться к другой исполнительной
  программе за дополнительными действиями, что требует многократной
  вкладываемости исполнительных программ;
- обращение из одного исполнительного блока в другой производится в
  зависимости от наличия того или иного нерезидента в оперативной памяти.

Каждый процесс в ходе работы ОС может находиться в одном из следующих
состояний:

- **текущий процесс**, в данный момент занимающий процессор. В каждый момент
  времени процессор занимается только одним процессом. Для того, чтобы
  процесс стал текущим, необходимо загрузить все управляющие регистры
  процессора соответствующей информацией данного процесса. Решение о том,
  какой процесс в данный момент станет текущим, принимает специальный
  планировщик выбора процессов. Процессы, работающие в системных каналах,
  обслуживаются в первую очередь с учетом их взаимного приоритета;
- **блокирован** — развитие процесса приостановлено по какой-либо причине.
  В ОС Диспак процесс будет прерван, если его нет в шкале готовности или он
  закрыт хотя бы одной из масок шкалы готовности. Процесс переводится в
  состояние "блокирован" другим процессом или сам переводит себя в это
  состояние. Прерванный процесс может стать готовым к выполнению, если он
  присутствует в шкале готовности и открыт во всех ее масках;
- **готов к выполнению** — процесс образован, имеет дескриптор, занесен в
  шкалу готовности и открыт во всех ее масках. Готовый к выполнению процесс
  может в следующий момент времени перейти в состояние "текущий" или
  "блокирован".

### 7.2. Процессы, события и их синхронизация

Последовательный процесс есть работа, выполняемая последовательно процессором
над программой с ее данными. Логически всякий процесс должен иметь свой
собственный процессор и программу, а кроме того два или более процесса могут
разделять одну и ту же программу и процессор. Назовем последний вид процесса
асинхронным последовательным процессом.

Развитие всякого процесса может быть описано в виде множества векторов
состояния процесса E1, ..., EN, ..., где всякий элемент множества EK
определяет координатное положение процесса и значение всех данных,
используемых процессом. Таким образом вектор состояния процесса EK является
полным описателем для процессора.

В конкретный момент времени процесс может находиться в одном из двух
состояний: продолжающийся и блокированный. Процесс П будет находиться в
состоянии блокировки до того момента, пока не будет получен сигнал, сообщение
или ресурс от другого процесса. Процесс П называется продолжающимся, если он
выполняется процессором или мог бы им выполняться при условии доступности
процессора данному процессу.

Всякая мультипрограммная ОС может быть описана в терминах асинхронных
последовательных процессов, которые действуют независимо друг от друга,
вступают в связь друг с другом путем пересылки обусловленных сообщений и
иерархически разделяют общие ресурсы вычислительной системы. Разделение ОС на
процессы становится возможным лишь при наличии аппаратной поддержки со
стороны вычислительной системы, на которой функционирует ОС. Концепция
процесса позволяет эффективно организовывать, выделять и определять базовые
задачи ОС, упрощает их организацию и изучение динамики.

Аппарат процессов перенесен с уровня ОС на уровень задачи пользователя
программным путем и является виртуальным процессом более высокого уровня, чем
аппарат процессов собственно ОС. Перевод процесса пользователя из состояния
блокировки в состояние продолжения или готовности к продолжению
осуществляется с помощью логического примитива типа "флаг", называемого
"событием". В распоряжение пользователя выделяются средства, позволяющие
определить подмножество событий, интересующих пользователя, а также место,
доступное процессу пользователя, куда ОС передаст информацию о наступивших
событиях. Физически эти операции осуществляются путем задания места в
программе пользователя, куда ОС передаст управление при появлении событий,
заданных пользователем.

Синхронизация процессов в задаче пользователя осуществляется на базе
семафорных примитивов, разрешающих или запрещающих наступление событий в
задаче пользователя. Накопление различных событий для задачи пользователя
производится аддитивно и, таким образом, потерь различных событий в системе
не происходит. Допускается возможность многократной вложенности событий,
т. е. наступление события P(N+1) возможно при продолжающемся процессе
обработки события P(N). В данном случае восстановление процесса уровня N
произойдет по окончании процесса уровня N+1.

### 7.3. Аппарат главной и подчиненной задач

Полномочия процесса в системе есть множество действий, которые данный процесс
может производить как над собой, так и над другими объектами в системе.
Поставим в соответствие всякому процессу множество возможных полномочий
процесса в системе и определим подчиненный процесс как процесс, множество
полномочий которого — Xi — является подмножеством множества полномочий
некоторого другого процесса — Xj:

```
Xj ⊃ Xi
```

Аппарат главной и подчиненной задачи является дальнейшим развитием концепции
дерева процессов и позволяет переносить аппарат событий с уровня единичного
примитива процесса на уровень множеств процессов с наложением ограничения о
существовании единственного главного процесса в каждый момент времени для
всякого подчиненного процесса. Из определения следует, что множество
полномочий Xj характеризует главную задачу (процесс), а Xi — подчиненную
задачу.

Главная задача имеет возможность управлять своей подчиненной задачей во
всякий момент времени, когда подчиненная задача передала полномочия
иерархического подчинения главной задаче. Одновременно подчиненная задача
может являться главной задачей по отношению к своим подчиненным задачам.
Подчиненная задача имеет полномочия на отказ от подчинения и на перевыбор
своей главной задачи в процессе своего решения. При окончании главной задачи
все ее подчиненные задачи также завершаются.

По характеру взаимодействия между собой задачи, решающиеся под управлением
ОС, могут быть разделены на три класса:

- подчиненные задачи;
- независимые задачи, имеющие подчиненные задачи;
- независимые задачи, не имеющие подчиненных задач.

### 7.4. Системные примитивы аппарата главной и подчиненной задач

Множество полномочий главной задачи включает в себя операции:

- остановить подчиненную задачу;
- пустить подчиненную задачу;
- окончить подчиненную задачу;
- передать ресурсы подчиненной задаче;
- отобрать ресурсы у подчиненной задачи;
- сменить подчинение задачи.

Подчиненная задача объявляет свою главную задачу с помощью примитива
объявления главной задачи. После исполнения данного примитива задача
переходит в класс подчиненных задач при условии нахождения в решении задачи,
объявляемой главной.

Отключение подчиненной задачи от главной производится при обращении к
соответствующему примитиву и задача переходит в класс независимых задач.

Подчиненная задача имеет возможность передать контроль над своим дальнейшим
решением главной задаче обращением к примитиву разрешения продолжения
решения. Результатом выполнения этого примитива является перевод подчиненной
задачи в режим ожидания до момента получения соответствующего разрешения от
главной задачи.

#### 7.4.1. Примитивы главной задачи

**7.4.1.1.** Обращение к примитиву остановки подчиненной задачи вызывает
перевод указанной подчиненной задачи в режим ожидания и дальнейшее ее решение
становится возможным лишь по указанию от главной задачи.

**7.4.1.2.** Обращение к примитиву пуска подчиненной задачи вызывает снятие
режима ожидания в подчиненной задаче и продолжение ее решения.

**7.4.1.3.** Примитив окончания подчиненной задачи вызывает безусловное
окончание подчиненной задачи и выход ее из решения.

**7.4.1.4.** В качестве ресурсов, предназначенных для обмена между главной и
подчиненной задачей, рассматриваются ресурсы оперативной памяти, внешние
запоминающие устройства, терминальные устройства, содержимое оперативной
памяти и индексных регистров главной и подчиненной задач. Все примитивы,
обеспечивающие обмен ресурсами, являются доступными лишь главной задаче.

**7.4.1.5.** Главная задача имеет возможность опросить наличие своих
подчиненных задач, а также подчиненных задач, находящихся в режиме ожидания.

**7.4.2.** Все описанные выше примитивы аппарата главной и подчиненной задач
реализованы на базе экстракодов ОС.

### 7.5. Системные примитивы аппарата событий

**7.5.1.** Необходимым условием работы с аппаратом событий ОС является
указание места, в доступной задаче области оперативной памяти, куда ОС будет
передано управление при возникновении интересующих пользователя событий. Для
этой цели используется примитив задания адреса процесса "дешифратор".

**7.5.2.** Выбор интересующего пользователя подмножества множества событий

Результатом использования данного примитива является выделения требуемого
подмножества событий.

**7.5.3.** Выдача наступивших к данному моменту событий происходит при
обращении к примитиву выдачи шкалы наступивших событий — заданного ранее,
интересующего пользователя подмножества множества событий.

**7.5.4.** Перевод задачи пользователя в режим ожидания событий происходит при

**7.5.5.** Всякое событие может быть объявлено или сброшено при обращении к
примитиву дополнения текущей шкалы событий даже при условии отсутствия
данного события в выбранном подмножестве множества событий.

**7.5.6.** При окончании работы по процессу возврат в прерванное место задачи

### 7.6. События в задаче пользователя и их обработка

Всякое событие, передаваемое ОС задаче пользователя, должно быть определено в
маске шкалы событий этой задачи. Значение события определяется позиционно.

**7.6.1.** Событие "будильник" — 1-й разряд в маске шкалы событий. Данное
событие определяет временное прерывание задачи пользователя и является
необходимым для работы с аппаратом событий и процессов. Длительность
интервала срабатывания будильника устанавливается пользователем и может
составлять от 0.08 с до 2 мин 43 с.

**7.6.2.** Событие "конец ввода с терминала" — 3-й разряд в маске шкалы
событий. Данным событием ОС оповещает задачу пользователя о том, что
сообщение, переданное с терминала в задачу, размещено в буфере терминала,
определенном пользователем.

**7.6.3.** Событие "конец вывода на терминал" — 4-й разряд в маске шкалы
событий. Данным событием ОС сообщает задаче пользователя, что один из
работающих с ней терминалов окончил вывод и освободился.

**7.6.4.** Событие "получено сообщение от другой задачи" — 5-й разряд маски
шкалы событий. Данное событие возникает в задаче пользователя при
использовании аппарата обмена сообщениями типа "память — память". Событие
определяет момент получения сообщения буфером приема порта данной задачи.

**7.6.5.** Событие "окончание обмена с МЛ, МД" — 6-й разряд в маске шкалы
событий. Данным событием ОС оповещает задачу о реальном окончании обмена с
внешним запоминающим устройством.

**7.6.6.** Событие "связь с оператором" — 8-й разряд в маске шкалы событий.
Данное событие оповещает задачу пользователя о выполнении операции
принудительного окончания ее директивой оператора.

**7.6.7.** Событие "событие в подчиненной задаче" — 9-й разряд в маске шкалы
событий. Данным событием ОС оповещает задачу, являющуюся главной, что в одной
из ее подчиненных задач произошло событие, заданное в маске шкалы событий,
установленной главной задачей для своей подчиненной задачи.

**7.6.8.** Событие "образование подчиненной задачи" — 11-й разряд в маске
шкалы событий. Данным событием ОС оповещает задачу пользователя о появлении у
нее подчиненной задачи.

**7.6.9.** Событие "доверение ресурса" — 12-й разряд в маске шкалы событий.
Данным событием ОС оповещает задачу о передаче или отнятии у нее ресурса:
листов оперативной памяти, внешних запоминающих устройств, терминалов.

**7.6.10.** "Программное событие" — 14—16-й разряды маски шкалы событий.
Данные события не инициируются ОС, а момент их наступления определяется самим
пользователем. Данные события используются при работе программных комплексов
для синхронизации различных частей комплекса или для синхронизации выполнения
различных частей одной задачи.

**7.6.11.** Событие "аварийная ситуация в задаче" — 17-й разряд маски шкалы
событий. Данным событием ОС сообщает задаче пользователя об аварии в задаче.
При работе по этому событию ОС не берет на себя функции обработки аварии в
задаче пользователя, а передает эти функции самой задаче.

**7.6.12.** Событие "обращение в закрытый лист" — 18-й разряд в маске шкалы
событий. Данным событием ОС оповещает задачу пользователя об обращении в
лист, занятый обменом или переведенный ОС на внешние запоминающие устройства.

**7.6.13.** Событие "перехват экстракода" — 19-й разряд в маске шкалы событий.
Данным событием ОС сообщает о передаче задаче пользователя функции выполнения
экстракода, который задача пользователя будет интерпретировать иначе, чем ОС.

**7.6.14.** Событие "готов к приему сообщения" — 20-й разряд в маске шкалы
событий. Данное событие оповещает задачи, работающие под управлением ОС, о
готовности некоторой задачи к приему сообщения.

**7.6.15.** Обработка полученного события осуществляется прерыванием
последовательного выполнения команд в задаче пользователя и передачей
управления по адресу дешифратора событий. Для получения события необходимо
выполнение следующих условий:

- в задаче пользователя разрешен переход на асинхронные процессы;
- задан адрес дешифратора событий;
- в маске шкалы событий есть разряд, соответствующий требуемому событию, и
  определено событие "будильник".

В том случае, если хотя бы одно из вышеуказанных условий не выполнено, признак
события для задачи устанавливается, но решение задачи пользователя не
прерывается. Как только все три условия в задаче пользователя будут выполнены,
то ОС известит пользователя о наступившем событии.

По наступлению разрешенного события, при прерывании естественного выполнения
задачи пользователя, ОС проделывает работу по формированию вектора состояния
прерванного процесса в поле упрятывания, занимающем слова с адресами
Д-1, ... Д-11, где Д — адрес начала программы дешифратора, заданный
пользователем ранее. Содержимое поля упрятывания:

- **Д-1**: специальная информация о состоянии процесса;
- **Д-2**: содержимое 15(8) индекс-регистра задачи пользователя на момент
  прерывания (1—15 рр.);
- **Д-3**: содержимое 16(8) индекс-регистра задачи пользователя на момент
  прерывания (1—15 рр.);
- **Д-4**: содержимое 17(8) индекс-регистра задачи пользователя на момент
  прерывания (1—15 рр.);
- **Д-5**: содержимое специального индекс-регистра ИС0 на момент прерывания;
- **Д-6**: специальная информация о состоянии процесса;
- **Д-7**: адрес возврата из последнего выполненного экстракода на момент
  прерывания;
- **Д-8**: содержимое специального индекс-регистра ИС7 на момент прерывания;
- **Д-9**: содержимое регистра младших разрядов на момент прерывания;
- **Д-10**: содержимое регистра режима работы арифметического устройства
  (42—48 рр.); при наступлении события "обращение в закрытый лист" в 1—5 рр.
  заносится номер листа в задаче пользователя, при обращении к которому
  возникло событие; в 6-й разряд заносится 1, если данный лист участвует в
  обмене, и 0 — если данный лист был перенесен ОС в виртуальную память на
  внешних запоминающих устройствах; при наступлении события "перехват
  экстракода" в 1—6 рр. заносится идентификатор перехваченного экстракода,
  который может быть определен из выражения

  ```
  КОП - 40(8),
  ```

  где КОП — код операции перехваченного экстракода;
- **Д-11**: содержимое сумматора задачи на момент прерывания.

После образования поля упрятывания ОС устанавливает запрет перехода на
асинхронные процессы в задаче пользователя при появлении событий, засылает в
16(8) индекс-регистр задачи адрес начала программы дешифратора асинхронных
процессов (Д), записывает на сумматор задачи маску шкалы событий (48—25 рр.),
шкалу наступивших к данному моменту событий (1—24 рр.), гасит все возникшие к
данному моменту события, включая и те, которые не были заданы в маске шкалы
событий, и передает управление в задачу пользователя на начало программы
дешифратора асинхронных процессов.

После окончания работы по асинхронному процессу, по желанию пользователя, ОС
производит восстановление прерванного процесса по его состоянию на момент
прерывания из поля упрятывания задачи. Возможность изменения адреса
восстановления прерванного процесса допускается лишь с занесением нулевого
кода в слово по адресу Д-6.

При совместном использовании аппарата событий и аппарата главной и
подчиненной задач возможны два варианта работы:

- события обрабатываются лишь главной задачей;
- события обрабатываются как главной, так и подчиненной задачей.

В первом случае работа главной задачи по событию ничем не отличается от случая
работы независимой задачи с учетом наличия события типа "образовалась
подчиненная задача" и "событие в подчиненной задаче". Главная задача имеет
возможность установить маску шкалы событий для подчиненной задачи и
обрабатывать события, возникающие в подчиненной задаче, от своего имени.

Во втором случае обозначим маску шкалы событий, установленную главной задачей
для своей подчиненной, — МГ, а маску шкалы событий собственно подчиненной
задачи — МП. В случае, когда пересечение множеств МГ и МП пусто, каждая из
задач будет обрабатывать появившееся событие раздельно. В том случае, когда
пересечение множеств МГ и МП не пусто, то при работе по событию,
принадлежащему пересечению множеств МГ и МП, первой о происшедшем событии
будет оповещена главная задача, а по окончанию работы главной задачи по
данному событию будет инициирована обработка этого события в подчиненной
задаче.

### 7.7. Аппарат перехвата экстракодов

Аппарат перехвата экстракодов позволяет пользователю обеспечить трассировку
своей программы и интерпретацию некоторых экстракодов. Перехват экстракодов
возможен как с помощью аппарата событий, так и без его использования.

#### 7.7.1. Перехват экстракодов без использования аппарата событий

Без использования аппарата событий ОС позволяет перехватывать:

- экстракод обмена с внешними запоминающими устройствами (э70);
- экстракод печати на АЦПУ (э64);
- экстракод работы с терминалами (э71);
- экстракод конца задачи (э74).

Работа по перехвату экстракодов представляется пользователем для ОС в виде
шкалы перехватываемых экстракодов. При выполнении перехвата ОС выполняет
следующие действия:

- экстракод перехватывается до его исполнения ОС;
- формирует информационное поле перехвата экстракода, состоящее из трех слов;
- запрещает дальнейший перехват этого экстракода;
- передает управление в точку начала программы дешифратора перехвата (П),
  указанную пользователем ранее;
- засылает в 16(8) индекс-регистр исполнительный адрес перехваченного
  экстракода.

Информационное поле перехвата экстракода формируется относительно адреса
начала программы дешифрации перехваченных экстракодов и содержит следующую
информацию:

- **П-1**: содержимое сумматора на момент перехвата экстракода;
- **П-2**: содержимое специального индекс-регистра 32(8) — адрес выполнения
  перехватываемого экстракода;
- **П-3**: исполнительный адрес экстракода (1—15 рр.), идентификацию
  перехваченного экстракода в виде единицы шкалы (16—26 рр.).

Для дальнейшего перехвата экстракода необходимо вновь внести …
*(В оригинале фраза обрывается.)*

#### 7.7.2. Перехват экстракодов с использованием аппарата событий

При использовании аппарата событий множество экстракодов, которые позволяет
перехватывать ОС, значительно расширяется. При работе с аппаратом событий
разрешается перехват:

- экстракода чтения строки с буфера ввода;
- экстракода вывода на АЦПУ (э64);
- экстракода обмена с МЛ и МД (э70);
- экстракода работы с терминалами (э71);
- экстракода конца задачи (э74);
- экстракодов э52 и э53;
- экстракода обмена с буферной памятью (э70);
- экстракодов э63, э66, э62, э51, э72, э73, э54, э55, э56, э57, э67, э61.

Для выполнения перехвата указанных экстракодов необходимо выполнить следующие
подготовительные операции:

- установить адрес дешифратора асинхронных процессов;
- задать в маске шкалы событий по крайней мере 1 и 19 разряды;
- разрешить переход на асинхронные процессы;
- задать маску шкалы перехватываемых экстракодов.

Маска шкалы перехватываемых экстракодов задается позиционно, значение позиции
в маске следующее:

- 1 р. — перехват экстракодов э60, э50, э51, э54—э57;
- 2 р. — перехват экстракода э64;
- 3 р. — перехват экстракода обмена с МЛ и МД;
- 4 р. — перехват экстракодов э71, э72, э73;
- 5 р. — перехват экстракода э74;
- 6 р. — перехват экстракодов э52 и э53;
- 7 р. — перехват экстракода обмена с буферной памятью ОЗУ;
- 8 р. — перехват экстракодов э63, э66, э62, э61, э67.

При работе по событию "перехват экстракода" ОС заносит в 1—6 рр. слова с
адресом Д-10 идентификатор перехваченного экстракода, определяемый из
выражения

```
КОП - 40(8),
```

где КОП — код операции перехваченного экстракода.

### 7.8. Передача сообщений между задачами

Существование программных комплексов, т. е. задач, выполняющих совместное
решение общей проблемы, приводит к необходимости обмена информацией между
задачами комплекса. Обмен большими порциями информации можно осуществлять с
помощью внешних запоминающих устройств, синхронизировав работу всех частей
программного комплекса по выполнению операций чтения и записи на общем поле
памяти. Такой способ обмена информацией оказывается медленным и неэффективным
в случае обмена малыми объемами информации. Для поддержки общения задач в
процессе решения программного комплекса в ОС вводится аппарат обмена
сообщениями между задачами, находящимися в решении. Передача сообщения
представляет собой обмен типа "память — память" и позволяет переписывать
информацию из некоторого участка оперативной памяти (буфера выдачи — БВ) одной
задачи в некоторый участок оперативной памяти (буфер приема — БП) другой
задачи.

Всякая задача может иметь до 255 БП и столько же БВ, которые располагаются в
ее оперативной памяти. Для точного определения координат отправления и приема
сообщения применяется понятие порта — совокупность одного БП и одного БВ.
Всякий порт характеризуется своим номером и группой признаков, описывающих
текущее состояние данного порта. Все данные о порте представляют собой строку
в специальной матрице, называющейся таблицей портов (ТП).

Данными, описывающими текущее состояние порта, являются:

- признак существования данного порта у задачи;
- признак открытия или закрытия данного порта на прием или выдачу сообщения;
- ссылочные указатели на соответствующий БП и БВ;
- максимальные размеры сообщений, принимаемых в БП и выдаваемых из БВ.

ТП располагается в оперативной памяти пользователя, а ее адрес сообщается ОС.
Данная таблица является полной характеристикой задачи пользователя с точки
зрения аппарата передачи сообщений.

Для передачи информации пользователь должен указать ОС номер порта, из
которого задача будет отправлять сообщение. Далее ОС обратится к
соответствующему БВ указанного порта. Информация об адресате сообщения
является заголовком передаваемого сообщения. Адрес получателя состоит из
номера программного канала, по которому решается задача пользователя, которой
направляется сообщение, номер порта получения сообщения в этой задаче и
признак необходимости оповещения адресата о поступлении к нему сообщения через
средства аппарата событий. Кроме того должна быть указана длина передаваемого
сообщения.

Строго задаваемый адрес получателя сообщения позволяет точно направить
информацию указанному адресату. Аппарат работы с БП более гибок и позволяет
обеспечить эффективную работу "почтового ящика" при возможности поступления
сообщения от различных задач программного комплекса.

Обозначим номер программного канала отправителя — НК, а номер порта
отправителя — НП. Рассмотрим различные комбинации значений величин НК и НП:

- если НК≠0 и НП≠0, то в данный БП может быть принято сообщение лишь от
  задачи, решающейся по программному каналу с номером НК, отправленное из ее
  порта с номером НП;
- если НК≠0, а НП=0, то в этот БП может быть принято всякое сообщение,
  отправленное задачей, решающейся по программному каналу с номером НК;
- если НК=0, а НП≠0, то в данный БП может поступить сообщение от любой
  решающейся в данный момент задачи, но только из определенного у нее порта с
  номером НП;
- если НК=0 и НП=0, то данный БП считается открытым для приема всех сообщений
  из всех портов решающихся в настоящее время задач.

ТП может состоять из нескольких частей, связанных между собой ссылками. ОС
сообщается адрес начала таблицы портов (АТП). Каждая часть ТП может содержать
информацию не более чем о 32 портах данной задачи. Первые три слова части ТП
описывают состояние порта, а именно: существование данного порта, описанного
данной частью таблицы, и состояние его БП и БВ для принятия и передачи
сообщения соответственно. Начиная с 4-го слова располагается информация о всех
портах задачи из расчета 2 слова на один порт. В этих словах содержится
информация об адресах БП и БВ данного порта, максимальная длина сообщения для
БП и БВ данного порта, а также информация о задачах, передача сообщений от
которых в БП данного порта закончилась неудачно.

Если задача использует менее 255 портов, то ТП может состоять менее чем из
8 частей и последняя часть может быть неполной. Передача сообщений внутри
одной задачи запрещается ОС. Кроме того запрещается указывать ссылку на К+1
часть ТП в К-1 части: все части ТП должны быть связаны непосредственно.

Для обеспечения возможности передачи сообщений между задачами в ОС включены
следующие примитивы:

- "установи адрес ТП";
- "управление состоянием порта";
- "передай сообщение".

Аппарат передачи сообщений поддерживается аппаратом событий с помощью
примитивов "пришло сообщение" и "готов к приему сообщений".

## 8. Система управления данными

Под системой управления данными понимается система общения с физическими
магнитными носителями напрямую, а также общение с областями архивной системы.
Напрямую с магнитными носителями общаются модули ВЗУ, ОБМЕН, ЭКС, ОС4; к
модулям архивной системы относятся АРХИН, ТРАХ, ГИДРА, КОМАР, РЕЗАРХ, АРФА,
РА, ОБРАЗ, НЕРЕЗА. Архивные модули и модуль ВЗУ работают в первом режиме,
модули ЭКС, ОБМЕН и ОС4 — в третьем режиме.

### 8.1. Архивная система ОС Диспак

Архивная система ОС предназначена для обеспечения пользователя средствами
работы с массивами информации, хранящимися на внешних носителях. Архивная
система позволяет:

- организовать централизованное хранение данных;
- обеспечить эффективное динамическое распределение памяти на внешних
  носителях;
- предоставить пользователю средства доступа к данным, позволяющие обращаться
  к ним на уровне символических имен;
- обеспечить пользователя средствами защиты информации от
  несанкционированного доступа;
- обеспечить сохранность данных.

Архив располагается на томах — дисковых пакетах. Вся совокупность томов,
находящихся под управлением архивной системы, образует архивное пространство.
На некоторых томах кроме областей располагается и служебная информация —
каталоги архива.

Для пользователя архивное пространство представляется в виде совокупности
областей, где область — именованная единица внешней памяти. Область занимает
целое число зон на архивном томе и идентифицируется своим именем и шифром
хозяина данной области. Имя области — это последовательность простых имен,
разделенных точками. Простое имя содержит не более девяти символов, а имя
содержит не более семи простых имен. Шифр хозяина — это первые шесть цифр
шифра пользователя в операционной системе, причем любая цифра может быть
заменена точкой, обозначающей произвольную цифру.

Все тома, образующие архивное пространство, разделяются на две категории:
первичные и вторичные носители. Область доступна пользователю только тогда,
когда она находится на первичном носителе. На вторичные носители
"выталкиваются" (переносятся) области, к которым не было обращений в течение
длительного времени. Выталкивание производится лишь тогда, когда необходимо
освободить место для какой-либо "вталкиваемой" области. Пользователь, в рамках
выделенного ему бюджета, может запросить дублирование областей. В этом случае
на одном из вторичных носителей будет заведена периодически обновляемая копия
области.

Для каждой области в архивной системе определены следующие атрибуты:

- шифр пользователя, создавшего область;
- дата создания области;
- число обращений к области;
- дата последнего обращения к области;
- дата, время последней записи в область;
- шифр пользователя, выполнившего последнюю запись в область;
- длина области;
- тип области. Тип определяет носитель, на котором будет расположена область;
- пароли на чтение и на запись;
- список шифров пользователей, имеющих право работать с областью.

Для распределения архивного пространства между пользователями в составе архива
функционирует бюджетная система. Бюджеты в архиве представляют собой дерево с
произвольным количеством уровней. "Корнем" дерева бюджетов является фиктивный
бюджет шифра "......", располагающего неограниченным количеством ресурсов всех
типов. Администратор этого бюджета является администратором всего архива.
Только ему разрешено изменять режим работы архива, включать в состав архива
новые тома и выполнять ряд других административных функций.

Средства защиты областей от несанкционированного доступа включают:

- защиту архивных томов от прямого обращения к ним экстракодом обмена;
- защиту областей по списку допущенных лиц;
- защиту областей по паролю.

### 8.2. Работа с областями

Заказ областей в паспорте задачи осуществляется аналогично заказу лент и
дисков. В том случае, когда в паспорте задачи заказана несуществующая область,
задача выбрасывается с буфера ввода с соответствующей диагностикой. После
того, как архив просмотрел задачу, она попадает в общую очередь задач,
ожидающих включения в решение, и выбирается в решение по общим правилам. В
процессе обработки задачи архивом определяется правомочность доступа к
области. Если пользователь не имеет права работать с областью, то задача
выбрасывается с буфера ввода. В процессе решения пользователь может обращаться
к области, используя все экстракоды, у которых параметрами являются
виртуальные номера и регистрационные номера томов.

Инструкции по работе с архивной системой приведены в документах "ОС Диспак.
Руководство системного программиста" ИЫ.00110-01 32 01 и "ОС Диспак.
Руководство программиста" ИЫ.00110-01 33 01.

## 9. Отладка программ в ОС Диспак

### 9.1. Общее описание

Для Э1-КБ надъязыковым средством отладки является символьный диалоговый
отладчик (СДО). Отладчик реализован в рамках операционной системы Диспак и в
качестве системы программирования ориентируется на мониторную систему Дубна.
Символьный диалоговый отладчик представляет из себя, с точки зрения
операционной системы, отдельную задачу. СДО может одновременно обслуживать до
11 пользователей. В настоящее время символьная отладка реализована для
Fortran-Дубна, Fortran-ГДР, Алгол-ГДР, Forex и автокода Madlen.

Язык СДО учитывает следующие требования:

- обеспечить возможность ведения гибкой и эффективной отладки программ в
  терминах исходного языка программирования;
- обеспечить информационную полноту языка;
- предусмотреть возможность простого и удобного расширения языка СДО для
  реализации отладки в терминах динамических языков программирования;
- обеспечить простоту и удобство использования языка отладки.

Среди требований к реализации СДО следует выделить:

- реализацию СДО на уровне задачи пользователя с точки зрения ОС Диспак,
  сведение взаимодействия с ОС к уровню экстракодов;
- одновременное обслуживание одной копией СДО всех ведущих отладку
  пользователей;
- сведение взаимодействия с МС Дубна к взаимодействию с таблицей
  распределения памяти и модулями загрузки из временной библиотеки;
- выделение всех связей системы программирования в отдельный стыковочный
  модуль СДО с дополнительным контролем аварийных ситуаций;
- возможность символьной отладки без повторной трансляции программ;
- работу непосредственно с рабочей программой без ее модификации;
- использование аппаратных возможностей Э1-КБ для реализации контрольных
  точек;
- полный отказ от использования для нужд отладки оперативной памяти
  отлаживаемой задачи;
- полный синтаксический и семантический контроль диалога с пользователем с
  выдачей подробной диагностики.

Процесс отладки задачи во времени выглядит как смена периодов активности
пользователя и задачи.

В период своей активности пользователь с помощью команд СДО может:

1. Установить режим отладки;
2. установить или погасить точки прерывания (так называемые контрольные точки)
   в отлаживаемых программах;
3. исследовать и изменить данные;
4. возобновить выполнение задачи с указанного или прерванного места;
5. получить дополнительную информацию об отлаживаемых программах;
6. выполнить нестандартные действия.

Период активности пользователя продолжается до тех пор, пока пользователь не
возобновит выполнения задачи с указанного или прерванного места. При переходе
в активное состояние задача начнет решаться и остановится только по
контрольной точке или ошибке счета. Пользователь может сам остановить задачу,
набрав на клавиатуре терминала команду СТОП. Когда задача остановится, то на
терминал будет выдано сообщение с указанием места и причины останова, после
чего снова наступает период активности пользователя.

Независимо от периода отладки пользователь может запрашивать информацию как об
отлаживаемой задаче, так и о всех решаемых на машине задачах.

### 9.2. Вызов отладчика

#### 9.2.1. Отладочный режим трансляции

Пакет задачи пользователя может включать как неотлаженные, так и отлаженные
программы. Программы, предназначенные для отладки, должны транслироваться в
режиме отладки. Этот режим устанавливается управляющей картой

```
*DEBUG
```

и отменяется управляющей картой

```
*NO DEBUG
```

Программы, оттранслированные в отладочном режиме, могут быть записаны в личную
библиотеку и, следовательно, использованы повторно.

Отладочный режим трансляции не меняет загрузку программ в оперативную память и
не влияет на их работу.

#### 9.2.2. Паспорт отлаживаемой задачи

Для ведения отладки с терминала в паспорте задачи должен быть заказан раздел
"ТЕЛЕ‾".

#### 9.2.3. Запуск задачи через отладчик

Для запуска задачи через отладчик необходимо набрать на терминале ключ

```
СЛУГА
```

после ответа

```
СЛУГА ОТ <дата версии>
```

набрать

```
ШИФР <шифр задачи>
```

и ждать ответа

```
ЕСТЬ
```

Для прохождения задачи через этапы трансляции и загрузки необходимо выполнить
следующие стандартные действия:

- установить символьный режим отладки (т. к. в начале работы с СДО установлен
  адресный режим);
- выполнить команду ЖДУ с именем головной программы;
- пустить задачу.

После этого пользователь либо получает сообщение об ошибках трансляции или
загрузки, либо, если трансляция и загрузка прошли успешно, задача будет
остановлена в начале головной программы, на терминал будет выдано
соответствующее сообщение, и пользователь может приступить к отладке своих
программ.

## 10. Экстракоды

Связь операционной системы с программами пользователя осуществляется с помощью
макрокоманд, именуемых экстракодами. В настоящее время существуют экстракоды
для первого и для третьего режимов. К наиболее распространенным относятся
экстракоды вычисления стандартных функций. Ниже приведены принципы построения
этих экстракодов для третьего режима.

### 10.1. Вычисление SQRT(X)

Если X=0, то SQRT(X)=0. Для вычисления значения функции SQRT(X) при X>0
воспользуемся представлением числа X в виде

```
X = F*B**E, где 1/B <= F < 1        (1)
```

Так как Эльбрус-Б — машина с двоичным представлением чисел, B=2. Тогда

```
SQRT(X) = SQRT(F)*2**(E/2),             если E — четное
SQRT(X) = SQRT(F)/SQRT(2)*2**((E+1)/2), если E — нечетное
```

Вычисление SQRT(X) включает 3 этапа:

- приведение аргумента X к виду (1);
- вычисление SQRT(F);
- восстановление SQRT(X).

Для вычисления SQRT(X) применяется итерационный процесс Герона:

```
Y(I) = ((Y(I-1) + F/Y(I-1)))/2, I = 1,2,....J,
```

в котором за начальное приближение принято

```
Y0 = 0.41731 + 0.59016*F
```

Каждая последующая итерация удваивает количество верных знаков в SQRT. Для
получения 15 верных знаков достаточно 3 итераций.

### 10.2. Вычисление LN(X), LG(X)

Пусть X = F*2**M, 0.5 <= F < 1. Определим G и N так, что F = G*2**(-N),
1/SQRT(2) <= G < SQRT(2). Тогда

```
LN(X) = (K*M - N)*LN2
LG(X) = LG(E)*LN(X) = LN(X)/LN(10)
```

Вычисление логарифма включает 3 этапа:

- сведение данного аргумента к соответствующему аргументу в малом интервале
  изменения [1/SQRT(X), SQRT(X));
- вычисление логарифма для этого аргумента;
- восстановление значения искомого логарифма по компонентам.

Пусть S = (G-1)/(G+1). Тогда LN(G) = LN((1+S)/(1-S)). Он вычисляется с
использованием минимаксной аппроксимации.

```
LN(G) = 2*S + S*SUM(1,..) A(J)*S**(2*J), G>0
```

(SUM(1,..) обозначает сумму по J от 1 до бесконечности.)

Используется рациональная аппроксимация R(Z**2). В зависимости от величины F
определяется Z.

```
если F > SQRT(0.5):  Z1 = (F-0.5)-0.5, Z2 = F*0.5+0.5
если F <= SQRT(0.5): Z1 = F-0.5,       Z2 = Z1*0.5+0.5
```

Далее вычисляется Z. Z = Z1/Z2. W = Z**2. И

```
R(Z**2) = W*A(W)/B(W),
```

где A(W) и B(W) — полиномы с коэффициентами LN0, LN1, LN2 и LG0, LG1, LG2.

```
LN0 = -0.641249434237455E+2
LN1 =  0.163839435630215E+2
LN2 = -0.789561128875912E+0
LG0 = -0.769499321084948E+3
LG1 =  0.312032220919209E+3
LG2 = -0.356679777390346E+2
```

Определение RR(Z) производится по формуле RR(Z) = Z+*R(Z**2).

Пусть XN = FLOAT(N), тогда

```
RES = (XN*C2 + RR(Z)) + XN*C1, где
C1 =  0.693359375
C2 = -0.2121944400546E-5
```

LN(X) = RES. Если требуется вычислить LG(X), умножаем RES на
LG(E) = 0.434294481903251.

Функции LN и LG определены при X>0. Поэтому в программе производится выделение
X<=0 как недопустимых значений аргумента.

### 10.3. Вычисление EXP(X)

Пусть X = N*LN(C)+G, |G| <= LN(2)/2. Тогда E**X = E**G*C**N.

Вычисление экспоненты включает 3 этапа:

- сведение данного аргумента к аргументу в малом интервале изменения
  [-LN(2)/2, LN(2)/2];
- вычисление экспоненты от этого аргумента;
- восстановление экспоненты по компонентам.

Точность определения функции существенно зависит от точности G. Пусть
Y = EXP(G). Тогда DY/Y = DG, таким образом относительная ошибка в EXP(G)
приблизительно равна ошибке G. Единственный путь получить малую абсолютную
ошибку в G — использование повышенной точности. Представление

```
G = [(X1 - XN*C1) + X2] - XN*C2, где
X1 = FLOAT(X), X2 = X-X1, XN = FLOAT([X/LN(2)])
C1 = 0.693359375, C2 = -2.1219444005469E-4
```

позволяет вести вычисления с повышенной точностью (используется РМР).
Рациональная функция R(G) аппроксимирует EXP(G)/2. Пусть Z = G**2.

```
G*P(Z) = ((EX2*Z + EX1)*Z + EX0)*G,
Q(Z)   = (EXP2*Z + EXP1)*Z + EXP0

EX2  = 0.16520330026827E-4
EX1  = 0.69436000151179E-2
EX0  = 0.24999999999999999
EXP2 = 0.49586288490544E-3
EXP1 = 0.55553866696900E-1
EXP0 = 0.5E+0
```

Тогда

```
R(G) = 0.5 + G*P(Z)/[Q(Z) - G*P(Z)]
X = RES = R(G)*2**N
```

Если XMIN — минимальное положительное число, представимое в машине, а XMAX —
максимальное, тогда EXP(X) может быть вычислена в пределах LN(XMIN), LN(XMAX).

### 10.4. Вычисление SIN(X), COS(X)

Пусть |X| = N*ПИ+F, где |F| <= ПИ/2. Тогда

```
SIN(X) = SIGN(X)*SIN(F)*(-1)**N и
COS(X) = SIN(X + ПИ/2)
```

Вычисление SIN и COS включает 3 этапа:

- приведение аргумента X к аргументу F в малом интервале изменения
  [-ПИ/2, ПИ/2];
- вычисление SIN(F);
- вычисление SIN(X) по полученным компонентам.

Точность вычисления SIN(X), COS(X) существенно зависит от точности нахождения
F. Для повышения точности вычислений используется представление

```
F = (X - XN*C1) - XN*C2, где
C1 = 3.1416015625, C2 = -8.90891020676E-6, XN = FLOAT[Y/ПИ]
```

Пусть G = F*F. Далее вычисляется R(G) = G*P(G), где P(G) — многочлен с
коэффициентами

```
SIN8 =  0.2720479095788E-14
SIN7 = -0.764291780689E-12
SIN6 =  0.16058936490371E-9
SIN5 = -0.2505210679827E-7
SIN4 =  0.27557319210152E-5
SIN3 = -0.1984126984120E-3
SIN2 =  0.83333333333331E-2
SIN1 = -0.1666666666666666
```

Тогда RES = SGN*F + F*R(G), где SGN=1, если требуется вычислить COS(X) или
X>=0 при нахождении SIN(X). SGN=-1 в противном случае.

В программе осуществляется проверка Y < YMAX, где Y = |X| для SIN(X) и
Y = |X| + ПИ/2 для COS(X). YMAX выбирается следующим образом:

- (XN-C1) и (XN-0.5)*C1 должны быть точно представимы в машине для Y < YMAX;
- ошибка округления в последней цифре величины Y не должна приводить к ошибке
  в SIN(Y), намного большей по величине, чем 2**(T/2) (T — количество разрядов
  в изображении мантиссы числа; в нашем случае T=52) для Y < YMAX;
- N = INTRND(Y/ПИ) должно быть представимо как целое в машине.

Этим условиям отвечает YMAX = ПИ*2**26.

Для малых по абсолютной величине значений F, таких что |F| < EPS
(EPS = 2**(-26)), SIN(F) = F.

### 10.5. Вычисление TG(X), CTG(X)

Пусть X = N*ПИ/2, где |F| <= ПИ/4, тогда

```
TG(X)  = TG(F),    если N — четное,
TG(X)  = -1/TG(F), если N — нечетное,
CTG(X) = 1/TG(X)
```

Вычисление TG(X) таким образом сводится к 3 этапам:

- приведение данного аргумента X к соответствующему аргументу в интервале
  изменения [-ПИ/4, ПИ/4];
- вычисление TG(F);
- вычисление TG(X).

Функции TG(X) и CTG(X) очень чувствительны к малым изменениям аргумента во
всей области определения. Если Y = TG(X), тогда DY/Y = 2*X*COSEC(2*X)*DX/X. И
относительная ошибка в вычислении TG(X) приблизительно равна относительной
ошибке аргумента, определяемой M(X) = 2*X*COSEC(2*X). Так как M(X) велико для
X, близких к N*ПИ/2, TG(X) чувствителен к малым изменениям аргумента, близким
к 0 и к особенностям. Соответственно и CTG(X), только M(X) меняет знак.

Аргумент F вычисляется по формуле:

```
F = (X - XN*C1) - XN*C2, где
C1 = 1.57080078125, C2 = -4.45445510338076E-6
```

XN = FLOAT(N), где N = INTRND[X*2/ПИ]. При этом учитывается участие РМР в
арифметических действиях.

Пусть G = F**2. Далее вычисляются многочлены F(G) и P(G) с коэффициентами:

```
TAN1 = -0.12828347040957E+0
TAN2 =  0.28059182411699E-2
TAN3 = -0.74836349666612E-5
CTA1 = -0.46161680374290E+0
CTA2 =  0.23344852822068E-1
CTA3 = -0.20844804422038E-3
```

Если обозначить XNUM = F*P(G) и XDEN = (G), то результат вычисляется по
формулам RES = ±XNUM/XDEN или RES = ±XDEN/XNUM в зависимости от того,
определяется TG(X) или CTG(X), и четности N.

### Условные обозначения

X = FLOAT(N) обозначает перевод числа из целого представления N в
представление X с плавающей запятой.

N = INTRND(X) обозначает выделение целой части числа X.

## 12. Вызов и загрузка операционной системы

**12.1.** Первоначальная поставка ОС Диспак осуществляется на транспортной
магнитной ленте. Объем готовых программ ОС на транспортной МЛ — 500 зон.
Перепись ОС с МЛ на системный магнитный диск и последующий вызов операционной
системы (загрузка ОС) состоит из трех этапов:

1. Перепись готовых программ ОС с транспортной магнитной ленты в оперативную
   память;
2. перепись готовых программ ОС из оперативной памяти на системный магнитный
   диск;
3. вызов ОС с системного магнитного диска.

Первый этап выполняется программой "МЛОПОС", находящейся на транспортной
магнитной ленте и вызываемой по пультовой программе. Второй и третий этапы
выполняются сервисной программой пультового программного обеспечения.

После постановки операционной системы на вычислительном комплексе для
ежедневного вызова ОС достаточно выполнять только третий этап. Действия по
постановке и вызову ОС приведены в документе "ОС Диспак. Руководство
системного программиста" ИЫ.00110-01 32 01.

**12.2.** После вызова ОС резидентные модули располагаются в операционной
памяти в первых 32К слов (К=1024 слова). Нерезидентные модули размещены в
зонах системного МД 2053, а также в области памяти, начиная с адреса
10600000 (восьм.). Так как на вычислительном комплексе нет физических
магнитных барабанов, то барабанная память (МБ10—МБ27) также имитируется в
оперативной памяти (адреса 4000000—5777777 восьм.). Продолжение барабанной
памяти на магнитном диске, задаваемое в параметрах генерации как "НРДИС", и
сегменты рабочих лент (раздел "МДРЗО" в параметрах генерации), располагаются на
магнитных дисках по указанию параметров генерации.

## 13. Входные данные

Входными данными для операционной системы Диспак является пакет задачи
пользователя. Задача пользователя формируется с терминала при помощи одной из
диалоговых систем.

### 13.1. Структура пакета задачи пользователя

Пакет задачи пользователя должен состоять из паспорта задачи, тела программы и
стандартного окончания.

#### 13.1.1. Паспорт задачи

Паспорт состоит из отдельных разделов. Начальным является раздел "ШИФР".
Порядок следования остальных разделов безразличен. Заканчивается паспорт
символом "Е" с надчеркиванием или без него.

Каждый раздел содержит название (начиная с крайней левой позиции) и некоторую
информацию, которая задается через один или несколько пробелов после названия
раздела. Заканчивается раздел символом ‾ (надчеркивание).

Описание разделов паспорта приведено в документе "ОС Диспак. Руководство
программиста" ИЫ.00110-01 33 01.

#### 13.1.2. Стандартные паспорта

Для обращения к частоиспользуемым трансляторам, а также к диалоговым системам
введены стандартные паспорта, позволяющие не повторять в каждой программе
набор постоянных разделов паспорта. Набор стандартных паспортов определяется
системными программистами каждого ВЦ. Как правило используются следующие
стандартные паспорта:

- С1 — паспорт транслятора с макрокода "Бемш";
- С2 — паспорт мониторной системы "Дубна";
- С3 — паспорт системы "Алгол-БЭСМ";
- СХ — паспорт Монитора-80 (МС "Дубна" версия М-80);
- 88 — паспорт транслятора с автокода ИТМ;
- ЭБ — паспорт для обращения к ассемблеру ВК "Эльбрус 1-КБ";
- АР — паспорт архивной системы

и другие.

Заказ стандартного паспорта производится из задачи математика следующим
образом: в разделе паспорта задачи "ШИФР" после цифр шифра пишется три символа
"ЗХХ", где ХХ — обозначение стандартного паспорта.

```
Пример:      ШИФР 123401 ЗСХ‾
```

Такая запись означает заказ стандартного паспорта "СХ" (т. е. Монитора-80)
задачей с шифром 123401.

Заведение стандартных паспортов, просмотр их содержимого осуществляется с
помощью диалоговой программы "СЕРП" (см. "ОС Диспак. Руководство системного
программиста" ИЫ.00110-01 32 01). Для диалоговых систем стандартный паспорт
ставится в соответствие ключу вызова диалоговой системы. Набор ключей и
соответствующих им стандартных паспортов можно просмотреть также с помощью
программы "СЕРП".

В машинных программах стандартных паспортов могут использоваться следующие
указывающие символы:

- В — признак вводного слова;
- К — признак командного слова;
- С — признак логической константы;
- Б — признак буквенной константы;
- Ч — признак числа;
- И — признак исправления;
- А0—А5 — признаки типа вводной информации;
- \_◇ — признак конца текстовой или автокод-информации;
- Е — признак конца программы.

### 13.2. Комплектование программ

Комплект программ должен составляться по следующему правилу:

```
Паспорт задачи
Конец паспорта ( символ 'Е' )
Массив первый
Конец массива ( символ 'Е' )
Массив второй
Конец массива ( символ 'Е' )
..............
Конец комплекта ( ЕКОНЕЦ )
```

В комплекте обязательно должны быть паспорт задачи и первый массив. Массив
начинается вводным словом и заканчивается символом 'Е'.

## 14. Выходные данные

- сообщения, печатаемые на АЦПУ.
